วิธีใช้หน้านี้

เจ้าของงานกำหนด 6 ต.ค. 2569: ศึกษาหลักการก่อน เทียบกับคอมโพเนนต์ แล้วค่อยออกแบบ
  1. หาหัวข้อที่ตรงกับสิ่งที่กำลังออกแบบจากสารบัญด้านล่าง
  2. อ่านตารางตัดสินใจและหลักการ ทุกข้อมีลิงก์ไปแหล่งอ้างอิง
  3. ดูตารางเทียบคอมโพเนนต์ ว่าคลาสกลางรองรับหลักการนั้นแล้วหรือยัง
  4. ถ้าสถานะเป็น ขาด หรือ รอเคาะ ให้หยุดถามเจ้าของงานก่อน ไม่สร้างคอมโพเนนต์ขึ้นเอง
ป้ายสถานะ: มีแล้ว คลาสกลางรองรับแล้ว มีบางส่วน รองรับไม่ครบ ขาด ยังไม่มีในคลาสกลาง ขัดกัน เอกสารหรือหน้าจอขัดกันเอง รอเคาะ ต้องให้เจ้าของงานตัดสิน ข้อสรุปของผู้ทำ ไม่ได้มาจากแหล่งอ้างอิง
warning
เลขเกณฑ์ในหน้านี้เป็นข้อเสนอ ยังไม่ใช่กฎ จนกว่าเจ้าของงานจะเคาะ · รายการงานค้างทั้งหมดอยู่ใน plan.md หัวข้อ “แนวทาง UX: หลักการ × คอมโพเนนต์”

dropdown search ต้องมีข้อมูลแบบไหน

ข้อ 1–7 มาจากแหล่งอ้างอิงและแอปจริง · ข้อ 8 เป็นข้อสรุปของผู้ทำ
  1. ค่าอ้างอิงคงที่ (id หรือรหัส) แยกจากป้ายที่แสดง
  2. ป้ายหลักบรรทัดเดียว เป็นคำที่ผู้ใช้เรียกและพิมพ์หา USWDS Combo box · Atlassian Select
  3. บรรทัดรองเมื่อป้ายหลักซ้ำกันได้ ไม่เกิน 2 บรรทัด PatternFly Select — แอปจริงใช้ dept_short คู่ dept_full · ในข้อมูลของเรามี กฟส.เฉลิมพระเกียรติ 3 แห่ง ต้องมีจังหวัดกำกับ
  4. ค้นได้มากกว่าหนึ่งฟิลด์ Ant Design Select — แอปจริงค้น full_name · dept_sap · dept_sap_short
  5. ขนาดชุดข้อมูลกำหนดวิธีค้น: โหลดมาทั้งชุดได้ ให้กรองฝั่งหน้าจอตั้งแต่ตัวอักษรแรก · ใหญ่กว่านั้นค้นที่ API ขั้นต่ำ 3 ตัวอักษร หน่วง 500 ms (ค่าจริงใน customSelectOnSearch.tsx)
  6. ก่อนพิมพ์แสดงรายการตั้งต้นได้ (แอปจริงใช้ 12 แถว) · รายการสูงสุด 256px ประมาณ 6 แถว ตรงกับ Carbon Dropdown ที่ให้เริ่มเลื่อนที่แถวที่ 6
  7. มีสถานะครบ: กำลังโหลด · ไม่พบข้อมูล · ปุ่มล้างค่า · ปิดใช้พร้อมเหตุผล PatternFly Select
  8. จับคำแบบ “มีคำนี้อยู่” ไม่ใช่ “ขึ้นต้นด้วย” เพราะชื่อสังกัดขึ้นต้นซ้ำกัน ข้อสรุปของผู้ทำ
