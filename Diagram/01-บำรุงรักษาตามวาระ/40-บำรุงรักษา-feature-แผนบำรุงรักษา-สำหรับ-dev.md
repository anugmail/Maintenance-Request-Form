## 0. กติกาของเอกสารนี้

### 0.1 ชั้นของงาน

- **Feature** ก้อนงานที่ทีม dev รับไปทำ ประกอบด้วยหลายหน้า
- **Journey** งานหนึ่งเรื่องที่ผู้ใช้ตั้งใจทำ ครอบหน้าที่เกี่ยวข้องและทางเปลี่ยนหน้า
- **หน้า** หน้าจอที่ dev ต้องสร้าง
- **case** หน้าตาแบบหนึ่งของหน้านั้น

### 0.2 ไม่สร้างหน้าซ้ำ

1. **Toast สร้างเป็นชิ้นเดียว ไม่สร้างทั้งหน้าซ้ำ** ทุก toast เป็น component Notification ของไลบรารีชิ้นเดียว มีป้ายบอกว่า **แสดงบนหน้าไหน เมื่อไหร่** ตัวอย่าง: toast "ส่งแผนบำรุงรักษาเพื่ออนุมัติสำเร็จ" แสดงบนหน้ารายการแผน เมื่อบันทึกและส่งอนุมัติสำเร็จ ไม่ต้องสร้างหน้ารายการแผนที่มี toast ขึ้นมาอีกจอ ตำแหน่งบนจอจริงคือมุมขวาบนเสมอ
2. **case ที่หน้าตาเหมือนกันสร้างครั้งเดียว** journey อื่นที่ใช้ case นั้นอ้างรหัสจอเดิม ไม่สร้างใหม่
3. **case ที่หน้าเปลี่ยนจริง ยังสร้างเต็มหน้า** เช่น จัดยานพาหนะลงไตรมาสแล้ว ตัวเลขบนแท็บและป้ายในตารางเปลี่ยน ต้องมีจอของสภาพนั้น แต่ toast ที่ขึ้นพร้อมกันแยกเป็นชิ้น

### 0.3 ชื่อ case มาตรฐาน

| case | ความหมาย |
|---|---|
| Default | เปิดหน้าครั้งแรก ยังไม่มีข้อมูล หรือยังไม่กรอก |
| Filled | มีข้อมูล หรือกรอกครบแล้ว |
| Interaction | ระหว่างใช้งาน เช่น เปิดรายการเลือก แผงตัวกรอง popup เมนู |
| Empty result | ค้นหาหรือกรองแล้วไม่พบ |
| Disabled | ปุ่มกดไม่ได้เพราะเงื่อนไขยังไม่ครบ |
| Error Validation Field | ช่องที่ต้องกรอกยังว่าง แสดง error ตอนออกจากช่อง |
| Confirm | หน้าต่างยืนยันก่อนทำต่อ |
| Role · Status | หน้าตาต่างกันตามบทบาทผู้ใช้ หรือสถานะของแผน |
| Toast | ชิ้นแยก ตามข้อ 0.2 |

## 2. Journey

### 4.3 ปลั๊กอินที่สร้างตามหัวข้อนี้

ปลั๊กอิน `figma-export/maintainance-feature-plugin/` ใช้ฟังก์ชันวาดจอเดิมของ `maintainance-plugin/screens.js` ทุกจอ ต่างแค่การจัดวาง · ช่องกรอก Text input / Text area เปิด Show Placeholder ทุกช่อง (ยังไม่กรอก = placeholder สีจาง · กรอกแล้ว = Filled) และสร้างบน Page "แผนบำรุงรักษา" (ชื่อ Page = ชื่อ Feature · ถ้า Page ชื่อนี้มีของอื่นอยู่ ปลั๊กอินใช้ "<ชื่อ> (พระผู้สร้าง)" แทน ไม่วางปน)

**หลาย Feature (17 พ.ย. 2569):** ปลั๊กอินตัวเดียวมีทุก Feature ของบำรุงรักษา ติ๊กได้หลาย Feature และเลือก journey ราย Feature (ลูกศร ›) · Page ใน Figma แยกต่อ Feature ชื่อ Page = ชื่อ Feature (ผู้ใช้สั่ง 17 พ.ย. 2569 · Page เก่า "Maintainance Feature" / "MF …" ไม่ถูกแตะ ลบเองได้) · Feature ไหนพังกลางทาง ปลั๊กอินไปต่อ Feature ถัดไปแล้วสรุปท้าย log

แก้รายการ case หรือลำดับหน้าที่ `features/<id>.js` (journeys · happy · toasts) ให้ตรงหัวข้อ 2 และ 3 ของเอกสาร Feature นั้น ตัวเทสเทียบรหัสจอกับหัวข้อ 3 ให้ · ส่วนจัดวางกลางอยู่ที่ `feature.js`

**จำนวนเฟรมที่ได้** (เลือกทุก journey อุปกรณ์ทั้งคู่ ตามผลเทส) 340 เฟรม = ต่ออุปกรณ์ 170 เฟรม: Happy flow 34 ขั้น · ทุกเคส 135 จอ · toast 1 เฟรม (T1 · toast ชิ้นอื่นซ้อนอยู่ในจอผลลัพธ์แล้ว)

**ส่งไปบอร์ด FigJam** (ผู้ใช้สั่ง 17 พ.ย. 2569 · ให้ทำใน Figma ให้นิ่งก่อนแล้วค่อยส่ง) ปลั๊กอินตัวเดียวใช้ได้ทั้งไฟล์ Figma และไฟล์ FigJam · ภาพผ่าน `serve.js` ในเครื่อง · **ปุ่ม "ส่งทุก Feature ไป FigJam"** ส่งทุก Feature ที่สร้างจอแล้วในรอบเดียว ฝั่ง FigJam ติ๊กหัวกลุ่ม = ทั้ง Feature แล้วกดวางครั้งเดียว

2. ในไฟล์ Figma เปิดพระผู้สร้าง แท็บ "ส่งไป FigJam" → วางลิงก์บอร์ด FigJam กด "เพิ่ม" (ครั้งแรกครั้งเดียว ปลั๊กอินจำไว้ เก็บได้หลายบอร์ด เลือกจากรายการ) → กด "ส่ง Feature ที่เลือก" (ใช้ตัวเลือกอุปกรณ์และ journey ที่ติ๊ก) หรือ "ส่งทุก Feature ไป FigJam" ภาพชุดล่าสุดของ Feature นี้ไปที่ `out/figjam/flow-maintainance-feature/` และสเปก 9 ไฟล์ `out/board-maintainance-feature-{happy,1..8}.json`
3. กด "เปิดบอร์ดปลายทาง" → ในบอร์ดนั้นรันปลั๊กอินตัวเดิม (หน้าต่างเปลี่ยนเป็นโหมด FigJam เอง) → ติ๊กชุดที่จะวาง กด "วางลงบอร์ดนี้"

   - ปลั๊กอินเขียนลงไฟล์อื่นไม่ได้ (ข้อจำกัดของ Figma) จึงต้องเปิดบอร์ดแล้วกดวางเอง 1 ครั้ง

## 5. ยังไม่มีจอ (ส่งให้เจ้าของงานตัดสิน)

1. รายการแผน: ค้นหาหรือกรองแล้วไม่พบแผน
2. รายละเอียดแผน: สถานะดำเนินการ และปิดงานแล้ว
3. จัดการอะไหล่ของยานพาหนะ: Error Validation Field ของช่องน้ำมันและ popup อะไหล่เพิ่มเติม
4. แผนรออนุมัติ: ยังไม่มีแผนรออนุมัติ
5. toast ลบไม่สำเร็จ · toast อนุมัติหรือส่งกลับไม่สำเร็จ

**เคาะแล้วแต่ชุดจอของเจ้าของงานยังไม่มี** (ห้ามออกแบบเอง รอจอจากเจ้าของงาน)

- ฟอร์มแก้ไขแผนที่ดำเนินการแล้ว แก้ได้เฉพาะไตรมาสที่ยังไม่เสร็จ (คำตอบข้อ 8 ของไฟล์ 34-บำรุงรักษา-คำถามจากการตรวจต้นแบบ · R113)
- มือถือ แท็บไตรมาส ไอคอนย้ายและเอาออกในการ์ด (คำตอบข้อ 2 · รอไลบรารี)
