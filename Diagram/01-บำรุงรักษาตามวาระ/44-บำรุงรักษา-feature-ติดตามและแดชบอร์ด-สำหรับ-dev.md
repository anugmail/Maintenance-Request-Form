# Feature ติดตามและแดชบอร์ด: journey หน้า และ case สำหรับทีม dev

> ร่าง 17 พ.ย. 2569 ตามรูปแบบเดียวกับ Feature แผนบำรุงรักษา (ไฟล์ 40)
> ลอกเนื้อหาจากงานเดิม (userflow ไฟล์ 14 Scenario 4 และ 24 · จอใน `figma-export/maintainance-plugin/screens.js` บล็อก C และ W) มาจัดใหม่ ไฟล์เดิมไม่ได้แก้
> ปรับ 18 พ.ย. 2569 ตามงานล่าสุดของเจ้าของงาน (origin/main 13 พ.ย. 2569): แดชบอร์ดแบบ VMS+ หน่วยงานเห็นเฉพาะของตัวเอง กบค. เห็นทุกหน่วยงาน (R106) · รายละเอียดยานพาหนะแบบ Vehicle info มีแท็บประวัติ และการ์ดเครื่องมือกลของ กบค. (R90 R107)

## 0. กติกาของเอกสารนี้

### 0.1 ชั้นของงาน

- **Feature** ก้อนงานที่ทีม dev รับไปทำ ประกอบด้วยหลายหน้า
- **Journey** งานหนึ่งเรื่องที่ผู้ใช้ตั้งใจทำ ครอบหน้าที่เกี่ยวข้องและทางเปลี่ยนหน้า
- **หน้า** หน้าจอที่ dev ต้องสร้าง
- **case** หน้าตาแบบหนึ่งของหน้านั้น

### 0.2 ไม่สร้างหน้าซ้ำ

1. **Toast สร้างเป็นชิ้นเดียว ไม่สร้างทั้งหน้าซ้ำ** ทุก toast เป็น component Notification ของไลบรารีชิ้นเดียว มีป้ายบอกว่า **แสดงบนหน้าไหน เมื่อไหร่** ตัวอย่าง: toast "ส่งออกไฟล์สำเร็จ" แสดงบนหน้าอะไหล่ของแผนที่อนุมัติแล้ว เมื่อกดส่งออกใน popup แล้วสร้างไฟล์สำเร็จ ไม่ต้องสร้างหน้าแดชบอร์ดที่มี toast ขึ้นมาอีกจอ ตำแหน่งบนจอจริงคือมุมขวาบนเสมอ
2. **case ที่หน้าตาเหมือนกันสร้างครั้งเดียว** journey อื่นที่ใช้ case นั้นอ้างรหัสจอเดิม ไม่สร้างใหม่
3. **case ที่หน้าเปลี่ยนจริง ยังสร้างเต็มหน้า** เช่น กรองแล้ว ชิปตัวกรองขึ้นเหนือตารางและแถวในตารางเปลี่ยน ต้องมีจอของสภาพนั้น แต่ toast ที่ขึ้นพร้อมกันแยกเป็นชิ้น

### 0.3 ชื่อ case มาตรฐาน

| case | ความหมาย |
|---|---|
| Default | เปิดหน้าครั้งแรก ยังไม่มีข้อมูล หรือยังไม่กรอก |
| Filled | มีข้อมูล หรือกรอกครบแล้ว |
| Interaction | ระหว่างใช้งาน เช่น เปิดรายการเลือก แผงตัวกรอง popup เมนู |
| Empty result | ค้นหาหรือกรองแล้วไม่พบ |
| Disabled | ปุ่มกดไม่ได้เพราะเงื่อนไขยังไม่ครบ |
| Error Validation Field | ช่องที่ต้องกรอกยังว่าง แสดง error ตอนออกจากช่อง |
| Confirm | หน้าต่างยืนยันก่อนทำต่อ |
| Role · Status | หน้าตาต่างกันตามบทบาทผู้ใช้ หรือสถานะของข้อมูล |
| Toast | ชิ้นแยก ตามข้อ 0.2 |

### 0.4 รหัสจอ

ในเอกสารนี้ใช้รหัสจอเดิมของ `screens.js` (C.1 W.7 …) เพื่อเทียบกับชุดเดิมได้ · บล็อก C = Scenario 4 · บล็อก W = Scenario 24 · ใน Figma แต่ละจอมีรหัสตามชั้นเพิ่ม (journey.หน้า.case เช่น 1.1.2) และวงเล็บรหัสจอเดิมท้ายป้าย

หน้าตาของแต่ละชั้นเหมือนไฟล์ 40 หัวข้อ 4.2: Title และหัวส่วนเป็น component Header แบบ Type=Header · แถบ journey หน้า case เป็น Header แบบ Type=Subheader สถานะ Default / Sub Flow / Sub Flow 2 · ป้ายข้างแถวเป็น component Device Type (Type = Header / Desktop / Mobile)

- เนื้อหาแต่ละแถวตรงหัวข้อ 2 (J1–J4) · toast อยู่ในหน้าที่มันแสดง · จอไฟล์ PDF และ Excel เป็นหน้าตาไฟล์ที่ส่งออก ไม่มีแถบเมนู สร้างแบบ desktop ทั้งสองแถว
- สร้างบน Page "ติดตามและแดชบอร์ด" กดแต่ละครั้งวางชุดใหม่ต่อใต้ของเดิม ไม่ลบไม่ย้ายของเดิม

### 4.3 ปลั๊กอินที่สร้างตามหัวข้อนี้


แก้รายการ case หรือลำดับหน้าที่ `features/track.js` (ค่าคงที่ TRACK) ให้ตรงหัวข้อ 2 และ 3 ของไฟล์นี้ ตัวเทสเทียบรหัสจอกับหัวข้อ 3 ให้ · ส่งไปบอร์ด FigJam ใช้ขั้นตอนเดียวกับไฟล์ 40 หัวข้อ 4.3 (ภาพไปที่ `out/figjam/flow-maintainance-feature-track/` สเปก `out/board-maintainance-feature-track-{happy,1..4}.json`)

### 4.4 Happy flow

| Journey | ขั้น |
|---|---|
| 1 ดูอะไหล่และความคืบหน้าของแผนที่อนุมัติแล้ว | แท็บรวมตามรายการ (C.1) → กดตัวกรอง เลือกแผน (C.3) → กรองแล้ว (C.4) → แท็บแยกรายคัน (C.6) → แท็บความคืบหน้าของแผน (C.7) |
| 2 ส่งออกรายงานอะไหล่ | กรองแล้ว กดส่งออก (C.4) → popup เลือกรูปแบบไฟล์ (C.8) → ส่งออกสำเร็จ (C.9) |
| 3 ติดตามการบำรุงรักษารายคันและกำหนดครั้งถัดไป | ยานพาหนะทุกคัน (W.1) → กดตัวกรอง (W.4) → กรองใกล้ครบกำหนด (W.5) → กดเลขทะเบียน แท็บข้อมูลยานพาหนะ (W.6) → แท็บตารางบำรุงรักษา กำหนดครั้งถัดไป (W.7) |
| 4 จัดการเครื่องมือกล (กบค.) | การ์ดเครื่องมือกล (W.19) → popup แก้ไขเครื่องมือกล (W.25) → บันทึกเครื่องมือกลสำเร็จ (W.27) |

ขั้นส่งออกสำเร็จคือหน้าอะไหล่ของแผนที่อนุมัติแล้วที่กรองแล้ว มี toast อยู่ในจอเลย ให้เห็นผลในภาพเดียว ส่วนชุดทุกเคสยังใช้ toast แยกชิ้นตามหัวข้อ 0.2 · happy flow จบที่ส่งออกสำเร็จ ไม่ใส่จอไฟล์ PDF เพราะขนาดหน้ากระดาษ A4 ได้รับยกเว้นขนาดจอเฉพาะเฟรมที่ชื่อขึ้นต้น "ไฟล์ PDF" ตามกติกา R32 (ชุดทุกเคสตั้งป้าย case เป็น "ไฟล์ PDF · Filled …" และ "ไฟล์ Excel · Filled …")

## 5. ยังไม่มีจอ (ส่งให้เจ้าของงานตัดสิน)

1. toast ส่งออกไม่สำเร็จ
2. ไฟล์ Excel ชีตความคืบหน้าของแผน (popup บอกว่า Excel 1 แท็บ 1 ชีต แต่มีจอแค่ 2 ชีต)
3. ไฟล์ PDF ของแท็บแยกรายคัน และแท็บความคืบหน้าของแผน
4. หน้าอะไหล่ของแผนที่อนุมัติแล้ว: ค้นหาหรือกรองในแท็บแยกรายคันและแท็บความคืบหน้า (ตอนนี้มีจอค้นหาของแท็บรวมตามรายการเท่านั้น)
5. รายละเอียดยานพาหนะ: ยานพาหนะที่ยังไม่มีประวัติการบำรุงรักษา
6. ข้อมูลยานพาหนะ แท็บการบำรุงรักษา: มุมหน่วยงาน เห็นเฉพาะยานพาหนะที่อยู่ในแผนของหน่วยงาน (เจ้าของงานเคาะแล้ว คำตอบข้อ 25 ของไฟล์ 34-บำรุงรักษา-คำถามจากการตรวจต้นแบบ ชุดจอของเจ้าของงานยังไม่มี)

เรื่องที่เคยอยู่หัวข้อ 6 และเจ้าของงานตอบแล้ว: หน่วยงานผู้สร้างแผนเห็นแดชบอร์ดเฉพาะของหน่วยงานตัวเอง กบค. เห็นทุกหน่วยงานแบบดูอย่างเดียว (R106 · component-rules ข้อ 5.44)
