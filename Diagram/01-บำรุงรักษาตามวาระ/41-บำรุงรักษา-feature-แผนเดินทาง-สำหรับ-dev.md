# Feature แผนเดินทาง: journey หน้า และ case สำหรับทีม dev

> ร่าง 17 พ.ย. 2569 รูปแบบเดียวกับ [40-บำรุงรักษา-feature-แผนบำรุงรักษา-สำหรับ-dev.md](40-บำรุงรักษา-feature-แผนบำรุงรักษา-สำหรับ-dev.md)
> ลอกเนื้อหาจากงานเดิม (userflow ไฟล์ 14 scenario 6 7 8 9 25 · AC ไฟล์ 28 และ 31 · จอใน `figma-export/maintainance-plugin/screens.js`) มาจัดใหม่ ไฟล์เดิมไม่ได้แก้
> Feature นี้ต่อจาก Feature แผนบำรุงรักษา เริ่มเมื่อแผนได้รับอนุมัติแล้ว
> ปรับ 18 พ.ย. 2569 ตามงานล่าสุดของเจ้าของงาน (origin/main 13 พ.ย. 2569): แท็บรายการแผนเดินทางรออนุมัติ (F.9 F.10) · popup เพิ่มยานพาหนะเข้าไตรมาสได้ทุกคันที่ยังไม่อยู่ในแผน (E.19 E.26) · นำยานพาหนะที่บำรุงรักษาไม่ได้กลับมาบำรุงรักษาในไตรมาสเดิม (X.11 X.12) · ผู้ดูแลยานพาหนะแทนผู้ดูแลยานพาหนะ

## 0. กติกาของเอกสารนี้

### 0.1 ชั้นของงาน

- **Feature** ก้อนงานที่ทีม dev รับไปทำ ประกอบด้วยหลายหน้า
- **Journey** งานหนึ่งเรื่องที่ผู้ใช้ตั้งใจทำ ครอบหน้าที่เกี่ยวข้องและทางเปลี่ยนหน้า
- **หน้า** หน้าจอที่ dev ต้องสร้าง
- **case** หน้าตาแบบหนึ่งของหน้านั้น

### 0.2 ไม่สร้างหน้าซ้ำ

1. **Toast สร้างเป็นชิ้นเดียว ไม่สร้างทั้งหน้าซ้ำ** ทุก toast เป็น component Notification ของไลบรารีชิ้นเดียว มีป้ายบอกว่า **แสดงบนหน้าไหน เมื่อไหร่** ตัวอย่าง: toast "ส่งแผนเดินทางให้ผู้อนุมัติใหม่แล้ว" แสดงบนหน้าไตรมาส เมื่อส่งอนุมัติใหม่สำเร็จ ไม่ต้องสร้างหน้าไตรมาสที่มี toast ขึ้นมาอีกจอ ตำแหน่งบนจอจริงคือมุมขวาบนเสมอ
2. **case ที่หน้าตาเหมือนกันสร้างครั้งเดียว** journey อื่นที่ใช้ case นั้นอ้างรหัสจอเดิม ไม่สร้างใหม่
3. **case ที่หน้าเปลี่ยนจริง ยังสร้างเต็มหน้า** เช่น สร้างแผนเดินทางแล้ว ตารางแผนเดินทางและชื่อแผนเดินทางในตารางยานพาหนะเปลี่ยน ต้องมีจอของสภาพนั้น แต่ toast ที่ขึ้นพร้อมกันแยกเป็นชิ้น

### 0.3 ชื่อ case มาตรฐาน

| case | ความหมาย |
|---|---|
| Default | เปิดหน้าครั้งแรก ยังไม่มีข้อมูล หรือยังไม่กรอก |
| Filled | มีข้อมูล หรือกรอกครบแล้ว |
| Interaction | ระหว่างใช้งาน เช่น เปิดรายการเลือก ปฏิทิน popup เมนู แผงแจ้งเตือน |
| Empty result | ค้นหาหรือกรองแล้วไม่พบ |
| Disabled | ปุ่มหรือเมนูกดไม่ได้เพราะเงื่อนไขยังไม่ครบ |
| Error Validation Field | ช่องที่ต้องกรอกยังว่าง แสดง error ตอนออกจากช่อง |
| Confirm | หน้าต่างยืนยันก่อนทำต่อ |
| Role · Status | หน้าตาต่างกันตามบทบาทผู้ใช้ หรือสถานะของแผนเดินทาง |
| Toast | ชิ้นแยก ตามข้อ 0.2 |

### 0.4 รหัสจอ

รหัสในวงเล็บ เช่น (E.13) คือชื่อเฟรมในหน้า Maintainance ของ Figma ชุดเดิม ใช้เปิดดูภาพได้ ทุกรหัสมีทั้ง Desktop และ Mobile · บล็อก E = S6 · F = S7 · G = S8 · H = S9 · X = S25 · รายละเอียดระดับฟิลด์อยู่ใน AC ไฟล์ 28 (AC-S6) และ 31 (AC ระดับหน้า S6)

## 2. Journey

แต่ละ journey มี 3 ส่วน: ทางเดิน (action แล้วไปหน้าไหน) · case ของแต่ละหน้าตามลำดับที่เดิน · toast ของ journey

**หน้ารายการแผน** (1 จอ)
- Interaction เมนู … ของแผนที่อนุมัติแล้ว มีดูรายละเอียด (E.1)

**หน้ารายละเอียดแผน** (1 จอ)
- Status อนุมัติแล้ว ปุ่มไปหน้าไตรมาส 1 ที่หัวข้อยานพาหนะในแผน (E.2)

**หน้าไตรมาส** (3 จอ)
- Default ยังไม่มีแผนเดินทาง ทุกแถวมีป้าย "ยังไม่มีแผนเดินทาง" (E.3)
- Filled แผนเดินทางรออนุมัติ 1 ใบ คันในใบแสดงชื่อแผนเดินทางและวันดำเนินการ (E.13) + toast S1
- Disabled ยานพาหนะครบทุกคัน แผนเดินทาง 2 ใบ ปุ่มสร้างแผนเดินทางกดไม่ได้ (E.15) + toast S1

**หน้าสร้างแผนเดินทาง** (11 จอ)
- ข้อมูลแผนเดินทาง
  - Default ยังไม่กรอกข้อมูล (E.4)
  - Interaction เลือกช่วงวันเดินทาง (E.10)
- ยานพาหนะในแผนเดินทาง
  - Interaction popup เพิ่มยานพาหนะ ยานพาหนะทุกคันของไตรมาส (E.5)
  - Filled เพิ่มยานพาหนะแล้ว สถานที่ตั้งต้นเป็นสำนักงานที่ยานพาหนะอยู่ (E.6)
  - Interaction popup แก้ไขยานพาหนะ ผู้ดูแลยานพาหนะ สถานที่ วันดำเนินการ ค่าเริ่มต้นทั้งช่วงวันเดินทาง (E.7)
  - Interaction เลือกวันดำเนินการ ปฏิทินเลือกได้เฉพาะช่วงวันเดินทาง (E.24)
  - Filled เอายานพาหนะออกจากแผนเดินทาง (E.8) · Interaction เพิ่มยานพาหนะอีกครั้ง คันที่เอาออกกลับมาเลือกได้ (E.9)
  - Interaction ใบถัดไป ยานพาหนะในแผนเดินทางอื่นแสดงแต่เลือกไม่ได้ (E.14)
- ปุ่มยืนยัน
  - Error Validation Field ช่องบังคับว่าง ปุ่มยืนยัน Disabled (E.11)
  - Filled กรอกครบ วันดำเนินการรายคัน หลายคันวันเดียวกันได้ (E.12) ใช้แทน E.25

```
node figma-export/maintainance-feature-plugin/build.js                                          # ประกอบ code.js
FEATURE=trip node figma-export/test-maintainance-feature-plugin.js                              # เทส ต้องได้คำเตือน 0
FEATURE=trip PRE_MODE=build MODE=export-figjam node figma-export/test-maintainance-feature-plugin.js   # เทสส่งไป FigJam
```

แก้รายการ case หรือลำดับหน้าที่ `features/trip.js` (ค่าคงที่ JOURNEYS) ให้ตรงหัวข้อ 2 และ 3 ของไฟล์นี้ ตัวเทสเทียบรหัสจอกับหัวข้อ 3 ให้ · ส่งไปบอร์ด FigJam ตามขั้นตอนไฟล์ 40 หัวข้อ 4.3 ภาพไปที่ `out/figjam/flow-maintainance-feature-trip/` สเปกบอร์ด `board-maintainance-feature-trip-*.json`

**จำนวนเฟรมที่ได้** (เลือกทุก journey อุปกรณ์ทั้งคู่ ตามผลเทส) 192 เฟรม = ต่ออุปกรณ์ 96 เฟรม: Happy flow 31 ขั้น · ทุกเคส 56 จอ · toast 9 เฟรม (toast 8 ชิ้น S1 ขึ้นทั้ง J1 และ J5) · ป้าย Device Type / Header และปุ่มอัปเดตป้ายบนจอที่สร้างแล้ว ตามไฟล์ 40 หัวข้อ 4.3

ขั้นสุดท้ายที่เป็นผลลัพธ์มี toast อยู่ในจอเลย ให้เห็นผลในภาพเดียว · ขั้น "ส่งอนุมัติใหม่สำเร็จ" ของ journey 3 เป็นหน้าไตรมาสแบบจอเดิม E.18 (ชุดทุกเคสไม่สร้างจอนี้ ใช้ toast S2 แทน)

## 5. ยังไม่มีจอ (ส่งให้เจ้าของงานตัดสิน)

1. สร้างแผนเดินทาง: ย้อนกลับจากฟอร์มที่กรอกแล้ว ต้องมีหน้าต่างยืนยันการออกหรือไม่
2. toast สร้างแผนเดินทาง ส่งอนุมัติใหม่ อนุมัติ ส่งกลับ ไม่สำเร็จ (ทั้ง feature ยังไม่มี toast Error)
3. แผนเดินทางรออนุมัติ: ยังไม่มีแผนเดินทางรออนุมัติ และค้นหาแล้วไม่พบ
4. แก้ไขแผนเดินทาง: Error Validation Field ใช้แบบหน้าสร้างแผนเดินทางได้หรือไม่ · ยืนยันการส่งอนุมัติใหม่ต้องมีหน้าต่างยืนยันหรือไม่
5. หน้าไตรมาส: กดแผนเดินทางที่รออนุมัติแล้วไปหน้าไหน (ยังไม่มีหน้ารายละเอียดแผนเดินทางมุมผู้สร้างใน feature นี้)
6. หน้าไตรมาส: popup เพิ่มยานพาหนะเข้าไตรมาสเมื่อไม่มียานพาหนะให้เพิ่ม
7. แผนเดินทางบำรุงรักษา: ยังไม่มีแผนเดินทาง · แผงแจ้งเตือนไม่มีแจ้งเตือน

**เคาะแล้วแต่ชุดจอของเจ้าของงานยังไม่มี** (ห้ามออกแบบเอง รอจอจากเจ้าของงาน)

- การอนุมัติ (S7) และแจ้งเตือน (S8) ของแผนเดินทางจ้างดำเนินการ ตอนนี้ J2 และ J4 มีจอเฉพาะแผนเดินทางดำเนินการเอง
