# Feature ต้นทุนการบำรุงรักษา: journey หน้า และ case สำหรับทีม dev

> ร่าง 17 พ.ย. 2569 ตามรูปแบบของ Feature แผนบำรุงรักษา (ไฟล์ 40)
> ลอกเนื้อหาจากงานเดิม (userflow ไฟล์ 14 scenario 15 ถึง 18 · จอใน `figma-export/maintainance-plugin/screens.js`) มาจัดใหม่ ไฟล์เดิมไม่ได้แก้
> ปลั๊กอิน: `figma-export/maintainance-feature-plugin/features/close.js`
> ปรับ 18 พ.ย. 2569 ตามงานล่าสุดของเจ้าของงาน (origin/main 13 พ.ย. 2569): เจ้าของงานตัด S15 S16 S17 (ส่งประวัติ ตรวจสอบประวัติ ออกรายงานผลและปิดงาน) เมื่อ 10 พ.ย. 2569 (R89) แผนปิดงานเองเมื่อทุกคันเสร็จหรือบำรุงรักษาไม่ได้ และผู้ดูแลยานพาหนะรับทราบครบ · Feature นี้จึงเหลือเรื่องเดียวคือต้นทุนการบำรุงรักษา (S18 · R92) ผู้ใช้เคาะ 18 พ.ย. 2569 เปลี่ยนชื่อ Feature จาก "ประวัติและปิดงาน" เป็น "ต้นทุนการบำรุงรักษา" ชื่อไฟล์เอกสารเปลี่ยนตาม

## 0. กติกาของเอกสารนี้

### 0.1 ชั้นของงาน

- **Feature** ก้อนงานที่ทีม dev รับไปทำ ประกอบด้วยหลายหน้า
- **Journey** งานหนึ่งเรื่องที่ผู้ใช้ตั้งใจทำ ครอบหน้าที่เกี่ยวข้องและทางเปลี่ยนหน้า
- **หน้า** หน้าจอที่ dev ต้องสร้าง
- **case** หน้าตาแบบหนึ่งของหน้านั้น

### 0.2 ไม่สร้างหน้าซ้ำ

1. **Toast สร้างเป็นชิ้นเดียว ไม่สร้างทั้งหน้าซ้ำ** ทุก toast เป็น component Notification ของไลบรารีชิ้นเดียว มีป้ายบอกว่า **แสดงบนหน้าไหน เมื่อไหร่** ตัวอย่าง: toast "ส่งออกไฟล์สำเร็จ" แสดงบนแท็บต้นทุนการบำรุงรักษา เมื่อกดส่งออก Excel สำเร็จ ไม่ต้องสร้างหน้าต้นทุนที่มี toast ขึ้นมาอีกจอ ตำแหน่งบนจอจริงคือมุมขวาบนเสมอ
2. **case ที่หน้าตาเหมือนกันสร้างครั้งเดียว** journey อื่นที่ใช้ case นั้นอ้างรหัสจอเดิม ไม่สร้างใหม่
3. **case ที่หน้าเปลี่ยนจริง ยังสร้างเต็มหน้า** เช่น มียานพาหนะปิดงานแล้ว แท็บต้นทุนเปลี่ยนจากว่างเป็นตัวเลขและตาราง ต้องมีจอของสภาพนั้น แต่ toast ที่ขึ้นพร้อมกันแยกเป็นชิ้น

### 0.3 ชื่อ case มาตรฐาน

| case | ความหมาย |
|---|---|
| Default | เปิดหน้าครั้งแรก ยังไม่มีข้อมูล หรือยังไม่กรอก |
| Filled | มีข้อมูล หรือกรอกครบแล้ว |
| Interaction | ระหว่างใช้งาน เช่น เปิดรายการเลือก แผงตัวกรอง popup เมนู |
| Empty result | ค้นหาหรือกรองแล้วไม่พบ |
| Disabled | ปุ่มกดไม่ได้เพราะเงื่อนไขยังไม่ครบ |
| Error Validation Field | ช่องที่ต้องกรอกยังว่าง แสดง error ตอนออกจากช่อง |
| Confirm | หน้าต่างยืนยันก่อนทำต่อ |
| Role · Status | หน้าตาต่างกันตามบทบาทผู้ใช้ หรือสถานะของแผน |
| Toast | ชิ้นแยก ตามข้อ 0.2 |

## 2. Journey

แต่ละ journey มี 3 ส่วน: ทางเดิน (action แล้วไปหน้าไหน) · case ของแต่ละหน้าตามลำดับที่เดิน · toast ของ journey

### 4.2 การเรียงแบบตัว Z

```
ต้นทุนการบำรุงรักษา                             ← Title หลัก 1 อัน
1 คำนวณต้นทุนการบำรุงรักษา ───────────▶          1 journey = 1 แถวยาว
```

| ชั้น | หน้าตา | ตัวอย่าง |
|---|---|---|
| Title หลัก | component Header แบบ Type=Header (ไม่มี component ใช้กล่องสีเข้มแทน) · หัวส่วน Happy flow และทุกเคสใช้แบบเดียวกัน | ต้นทุนการบำรุงรักษา |

| หน้า | แถบ Subheader สถานะ Sub Flow คร่อมจอของหน้านั้น | 1.1 หน้ารายละเอียดแผน แท็บต้นทุนการบำรุงรักษา |
| case | แถบ Subheader สถานะ Sub Flow 2 เหนือแต่ละจอ · หน้าไฟล์ Excel ใส่ "ไฟล์ Excel · " นำหน้า | 1.1.3 Filled สรุปรายไตรมาส ต้นทุนรายคัน (Q.2) |
| ป้ายข้างแถว | component Device Type (Type = Header / Desktop / Mobile) ตามไฟล์ 40 หัวข้อ 4.2 | Device · Desktop · Mobile |

- สร้างบน Page "ต้นทุนการบำรุงรักษา" (Page เก่าชื่อ "ประวัติและปิดงาน" ปลั๊กอินยังรู้จักไว้ใช้ตอนลบส่วน) กดแต่ละครั้งวางชุดใหม่ต่อใต้ของเดิม ไม่ลบไม่ย้ายของเดิม

### 4.3 ปลั๊กอินที่สร้างตามหัวข้อนี้

ปลั๊กอิน `figma-export/maintainance-feature-plugin/` ใช้ฟังก์ชันวาดจอเดิมของ `maintainance-plugin/screens.js` ทุกจอ ต่างแค่การจัดวาง · ค่าของ Feature นี้อยู่ที่ `features/close.js`

```
node figma-export/maintainance-feature-plugin/build.js                                   # ประกอบ code.js
FEATURE=close node figma-export/test-maintainance-feature-plugin.js                     # เทส ต้องได้คำเตือน 0
FEATURE=close PRE_MODE=build MODE=export-figjam node figma-export/test-maintainance-feature-plugin.js   # เทสส่ง FigJam
```

แก้รายการ case หรือลำดับหน้าที่ `features/close.js` (ค่าคงที่ JOURNEYS) ให้ตรงหัวข้อ 2 และ 3 ของไฟล์นี้ ตัวเทสเทียบรหัสจอกับหัวข้อ 3 ให้ · ส่งไปบอร์ด FigJam ใช้ขั้นตอนเดียวกับไฟล์ 40 หัวข้อ 4.3 (ภาพไปที่ `out/figjam/flow-maintainance-feature-close/` สเปก `out/board-maintainance-feature-close-{happy,1}.json`)

**จำนวนเฟรมที่ได้** (เลือกทุก journey อุปกรณ์ทั้งคู่ ตามผลเทส) 18 เฟรม = ต่ออุปกรณ์ 9 เฟรม: Happy flow 3 ขั้น · ทุกเคส 5 จอ · toast 1 เฟรม · ป้าย Device Type / Header และปุ่มอัปเดตป้ายบนจอที่สร้างแล้ว ตามไฟล์ 40 หัวข้อ 4.3

### 4.4 Happy flow

ทุกครั้งที่ export มีส่วน **Happy flow** ก่อนส่วนทุกเคส: เส้นทางหลักสั้นๆ ของแต่ละ journey แถวเดียว ป้ายเหนือจอ "ขั้น n · คำอธิบาย (รหัสจอ)"

| Journey | ขั้น |
|---|---|
| 1 คำนวณต้นทุนการบำรุงรักษา | รายละเอียดแผน แท็บต้นทุน (Q.1) → สรุปรายไตรมาส ต้นทุนรายคัน (Q.2) → ส่งออก Excel สำเร็จ (Q.3) |

ขั้นสุดท้ายคือจอเดิม Q.3 ที่มี toast อยู่ในจอเลย ให้เห็นผลในภาพเดียว ส่วนชุดทุกเคสใช้ toast Q1 แยกชิ้นตามหัวข้อ 0.2
