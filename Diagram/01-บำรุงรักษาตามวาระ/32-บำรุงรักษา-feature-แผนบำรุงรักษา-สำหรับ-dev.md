# Feature แผนบำรุงรักษา: journey หน้า และ case สำหรับทีม dev

> ร่าง 13 พ.ย. 2569 ตามแบบร่างบนกระดานของผู้ใช้ (Feature มีหลายหน้า · แต่ละหน้ามี case ใต้กล่อง · Journey ครอบหน้าและทางเปลี่ยนหน้าของงานหนึ่งเรื่อง)
> ลอกเนื้อหาจากงานเดิม (userflow ไฟล์ 14 · AC ไฟล์ 25 28 29 30 · จอใน `figma-export/maintainance-plugin/screens.js`) มาจัดใหม่ ไฟล์เดิมไม่ได้แก้
> ไฟล์นี้เป็นแม่แบบของเอกสาร Feature ทั้ง 5 ไฟล์ (32 แผนบำรุงรักษา · 33 แผนเดินทาง · 34 งานรายคัน · 35 ประวัติและปิดงาน · 36 ติดตามและแดชบอร์ด) · หัวข้อ 4 ปรับตามปลั๊กอินพระผู้สร้าง 18 พ.ย. 2569

## 0. กติกาของเอกสารนี้

### 0.1 ชั้นของงาน

- **Feature** ก้อนงานที่ทีม dev รับไปทำ ประกอบด้วยหลายหน้า
- **Journey** งานหนึ่งเรื่องที่ผู้ใช้ตั้งใจทำ ครอบหน้าที่เกี่ยวข้องและทางเปลี่ยนหน้า
- **หน้า** หน้าจอที่ dev ต้องสร้าง
- **case** หน้าตาแบบหนึ่งของหน้านั้น

### 0.2 ไม่สร้างหน้าซ้ำ

1. **Toast สร้างเป็นชิ้นเดียว ไม่สร้างทั้งหน้าซ้ำ** ทุก toast เป็น component Notification ของไลบรารีชิ้นเดียว มีป้ายบอกว่า **แสดงบนหน้าไหน เมื่อไหร่** ตัวอย่าง: toast "ส่งแผนบำรุงรักษาเพื่ออนุมัติสำเร็จ" แสดงบนหน้ารายการแผน เมื่อบันทึกและส่งอนุมัติสำเร็จ ไม่ต้องสร้างหน้ารายการแผนที่มี toast ขึ้นมาอีกจอ ตำแหน่งบนจอจริงคือมุมขวาบนเสมอ
2. **case ที่หน้าตาเหมือนกันสร้างครั้งเดียว** journey อื่นที่ใช้ case นั้นอ้างรหัสจอเดิม ไม่สร้างใหม่
3. **case ที่หน้าเปลี่ยนจริง ยังสร้างเต็มหน้า** เช่น จัดยานพาหนะลงไตรมาสแล้ว ตัวเลขบนแท็บและป้ายในตารางเปลี่ยน ต้องมีจอของสภาพนั้น แต่ toast ที่ขึ้นพร้อมกันแยกเป็นชิ้น

### 0.3 ชื่อ case มาตรฐาน

| case | ความหมาย |
|---|---|
| Default | เปิดหน้าครั้งแรก ยังไม่มีข้อมูล หรือยังไม่กรอก |
| Filled | มีข้อมูล หรือกรอกครบแล้ว |
| Interaction | ระหว่างใช้งาน เช่น เปิดรายการเลือก แผงตัวกรอง popup เมนู |
| Empty result | ค้นหาหรือกรองแล้วไม่พบ |
| Disabled | ปุ่มกดไม่ได้เพราะเงื่อนไขยังไม่ครบ |
| Error Validation Field | ช่องที่ต้องกรอกยังว่าง แสดง error ตอนออกจากช่อง |
| Confirm | หน้าต่างยืนยันก่อนทำต่อ |
| Role · Status | หน้าตาต่างกันตามบทบาทผู้ใช้ หรือสถานะของแผน |
| Toast | ชิ้นแยก ตามข้อ 0.2 |

### 4.3 ปลั๊กอินที่สร้างตามหัวข้อนี้

ปลั๊กอิน `figma-export/maintainance-feature-plugin/` ใช้ฟังก์ชันวาดจอเดิมของ `maintainance-plugin/screens.js` ทุกจอ ต่างแค่การจัดวาง · ช่องกรอก Text input / Text area เปิด Show Placeholder ทุกช่อง (ยังไม่กรอก = placeholder สีจาง · กรอกแล้ว = Filled) และสร้างบน Page "แผนบำรุงรักษา" (ชื่อ Page = ชื่อ Feature · ถ้า Page ชื่อนี้มีของอื่นอยู่ ปลั๊กอินใช้ "<ชื่อ> (พระผู้สร้าง)" แทน ไม่วางปน)

```
node figma-export/maintainance-feature-plugin/build.js        # ประกอบ code.js
node figma-export/test-maintainance-feature-plugin.js         # เทส ต้องได้คำเตือน 0
```

**หลาย Feature (17 พ.ย. 2569):** ปลั๊กอินตัวเดียวมีทุก Feature ของบำรุงรักษา ติ๊กได้หลาย Feature และเลือก journey ราย Feature (ลูกศร ›) · Page ใน Figma แยกต่อ Feature ชื่อ Page = ชื่อ Feature (ผู้ใช้สั่ง 17 พ.ย. 2569 · Page เก่า "Maintainance Feature" / "MF …" ไม่ถูกแตะ ลบเองได้) · Feature ไหนพังกลางทาง ปลั๊กอินไปต่อ Feature ถัดไปแล้วสรุปท้าย log

| Feature | ไฟล์ค่า | เอกสาร |
|---|---|---|
| แผนบำรุงรักษา | `features/plan.js` | ไฟล์นี้ (32) |
| แผนเดินทาง | `features/trip.js` | 33 |
| งานบำรุงรักษารายคัน | `features/job.js` | 34 |
| ประวัติและปิดงาน | `features/close.js` | 35 |
| ติดตามและแดชบอร์ด | `features/track.js` | 36 |

แก้รายการ case หรือลำดับหน้าที่ `features/<id>.js` (journeys · happy · toasts) ให้ตรงหัวข้อ 2 และ 3 ของเอกสาร Feature นั้น ตัวเทสเทียบรหัสจอกับหัวข้อ 3 ให้ · ส่วนจัดวางกลางอยู่ที่ `feature.js`

```
FEATURE=trip node figma-export/test-maintainance-feature-plugin.js    # เทส Feature อื่น (ไม่ใส่ = plan)
```

**ป้าย Device Type และ Header (18 พ.ย. 2569)** ปลั๊กอินรู้จัก Device Type จากไฟล์ (UI) VMS Plus - Release#2 (Backup) ต้องเปิดพระผู้สร้างในไฟล์นั้น 1 ครั้งให้ปลั๊กอินจำ (หรือลาก Device Type จาก Assets มาวางในไฟล์ที่สร้างจอ 1 ชิ้น) · Header ใช้ค่าที่ดึงจาก UI Release#2 ไว้แล้ว · ปุ่ม "อัปเดตป้าย Device Type / Header บนจอที่สร้างแล้ว" ในส่วน "เครื่องมือ" (กดเปิดท้ายแท็บสร้างจอ) แทน Title หัวส่วน แถบรหัส และป้ายข้างแถว บนจอที่สร้างไว้แล้วทุก Feature ในไฟล์ โดยไม่แตะตัวจอ · ตรวจก่อนแทน ถ้าชิ้นใหม่ผิดแบบ ลบทิ้งแล้วเก็บของเดิม · แทนเสร็จสแกนซ้ำ ต้องเหลือของเก่า 0 ชิ้น

**จำนวนเฟรมที่ได้** (เลือกทุก journey อุปกรณ์ทั้งคู่ ตามผลเทส) 208 เฟรม = ต่ออุปกรณ์ 104 เฟรม: Happy flow 24 ขั้น · ทุกเคส 69 จอ · toast 11 เฟรม (toast 9 ชิ้น วางในแถวของหน้าที่แสดง E1 ขึ้น 3 หน้าจึงมี 3 เฟรม)

**ส่งไปบอร์ด FigJam** (ผู้ใช้สั่ง 17 พ.ย. 2569 · ให้ทำใน Figma ให้นิ่งก่อนแล้วค่อยส่ง) ปลั๊กอินตัวเดียวใช้ได้ทั้งไฟล์ Figma และไฟล์ FigJam · ภาพผ่าน `serve.js` ในเครื่อง · **ปุ่ม "ส่งทุก Feature ไป FigJam"** ส่งทุก Feature ที่สร้างจอแล้วในรอบเดียว ฝั่ง FigJam ติ๊กหัวกลุ่ม = ทั้ง Feature แล้วกดวางครั้งเดียว
1. เปิด `node figma-export/serve.js` ค้างไว้
2. ในไฟล์ Figma เปิดพระผู้สร้าง แท็บ "ส่งไป FigJam" → วางลิงก์บอร์ด FigJam กด "เพิ่ม" (ครั้งแรกครั้งเดียว ปลั๊กอินจำไว้ เก็บได้หลายบอร์ด เลือกจากรายการ) → กด "ส่ง Feature ที่เลือก" (ใช้ตัวเลือกอุปกรณ์และ journey ที่ติ๊ก) หรือ "ส่งทุก Feature ไป FigJam" ภาพชุดล่าสุดของ Feature นี้ไปที่ `out/figjam/flow-maintainance-feature/` และสเปก 6 ไฟล์ `out/board-maintainance-feature-{happy,1..5}.json`
3. กด "เปิดบอร์ดปลายทาง" → ในบอร์ดนั้นรันปลั๊กอินตัวเดิม (หน้าต่างเปลี่ยนเป็นโหมด FigJam เอง) → ติ๊กชุดที่จะวาง กด "วางลงบอร์ดนี้"
   - ถ้าบอร์ดที่เปิดไม่ใช่ปลายทาง (เทียบชื่อไฟล์กับชื่อในลิงก์) ปลั๊กอินเตือนก่อน กดอีกครั้งถึงจะวาง · กด "ตั้งบอร์ดนี้เป็นปลายทาง" เพื่อใช้บอร์ดที่เปิดอยู่
   - ปลั๊กอินเขียนลงไฟล์อื่นไม่ได้ (ข้อจำกัดของ Figma) จึงต้องเปิดบอร์ดแล้วกดวางเอง 1 ครั้ง

บอร์ด: 1 journey = 1 section · คอลัมน์ละจอ แถว Desktop / Mobile · ลูกศรต่อตามลำดับ · Happy flow แยกชุด · กดวางซ้ำ section ชื่อเดิมถูกแทน ส่วนอื่นบนบอร์ดไม่ถูกแตะ · ส่วนวางบอร์ดลอกจาก `figjam-plugin/code.js` ตอนประกอบ (ไม่แก้ไฟล์เดิม)

```
PRE_MODE=build MODE=export-figjam node figma-export/test-maintainance-feature-plugin.js   # เทสส่งภาพ + สเปก (เขียนสเปกทดสอบที่ out/test-mf/)
PRE_MODE=build PRE_DEVICES=both PRE_FEATURES=plan,trip,job,close,track MODE=export-figjam-all node figma-export/test-maintainance-feature-plugin.js   # ส่งทุก Feature รอบเดียว
node figma-export/test-maintainance-feature-figjam.js                                    # เทสบอร์ดปลายทาง + โหมด FigJam
SPEC=test-mf/board-maintainance-feature-1.json node figma-export/test-maintainance-feature-figjam.js   # + วางบอร์ดด้วยปลั๊กอินนี้
```

### 4.4 Happy flow (ผู้ใช้สั่ง 17 พ.ย. 2569)

ทุกครั้งที่ export มีส่วน **Happy flow** ก่อนส่วนทุกเคส: เส้นทางหลักสั้นๆ ของแต่ละ journey แถวเดียว ไม่มีซีนย่อย ป้ายเหนือจอ "ขั้น n · คำอธิบาย (รหัสจอ)" · ขั้นในหน้าเดียวกันห่าง 200 เปลี่ยนหน้าห่าง 500 · ปุ่ม "สร้างเฉพาะ Happy flow" สร้างแค่ส่วนนี้

| Journey | ขั้น |
|---|---|
| 1 สร้างแผน | รายการแผนว่าง (A.2) → ฟอร์มสร้างแผน (A.3) → เลือกยานพาหนะของพื้นที่ (A.7) → ติ๊กยานพาหนะ (A.10) → เลือกไตรมาส (A.11) → จัดลงไตรมาสแล้ว (A.12) → หน้าจัดการอะไหล่ (T.2) → เลือกไส้กรองจากคลัง (T.5) → บันทึกอะไหล่แล้ว กลับฟอร์ม (T.10) → ครบ กดบันทึกและส่งอนุมัติ (A.30) → ส่งอนุมัติสำเร็จ |
| 2 ดูแผน | รายการแผน (A.1) → รายละเอียดแผน (A.20) |
| 3 แก้ไขแผน | เมนู … แก้ไข (R.1) → ฟอร์มแก้ไขแผน (R.3) → ยืนยันการแก้ไข (R.6) → แก้ไขสำเร็จ รออนุมัติใหม่ |
| 4 ลบแผน | เมนู … ลบ (S.1) → ยืนยันการลบ (S.2) → ลบสำเร็จ |
| 5 อนุมัติแผน | แผนรออนุมัติ (B.1) → พิจารณาแผน (B.2) → ยืนยันอนุมัติ (B.3) → อนุมัติสำเร็จ (B.4) |

ขั้นสุดท้ายที่เป็นผลลัพธ์ (สร้าง แก้ไข ลบ) คือหน้ารายการแผน 10 แถวที่มี toast อยู่ในจอเลย ให้เห็นผลในภาพเดียว ส่วนชุดทุกเคสยังใช้ toast แยกชิ้นตามหัวข้อ 0.2

## 5. ยังไม่มีจอ (ส่งให้เจ้าของงานตัดสิน)

1. รายการแผน: ค้นหาหรือกรองแล้วไม่พบแผน
2. รายละเอียดแผน: สถานะดำเนินการ และปิดงานแล้ว
3. แก้ไขแผน: Error Validation Field ใช้แบบหน้าสร้างแผนได้หรือไม่
4. จัดการอะไหล่ของยานพาหนะ: Error Validation Field ของช่องน้ำมันและ popup อะไหล่เพิ่มเติม
5. แผนรออนุมัติ: ยังไม่มีแผนรออนุมัติ
6. toast ลบไม่สำเร็จ
7. toast อนุมัติหรือส่งกลับไม่สำเร็จ
