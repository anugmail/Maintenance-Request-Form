## ตอบคำถาม “ประหยัดต่อคันและรวมเท่าไร”

1. **ต่อรายการรถในแผน** = ราคากลาง − ประเมิน Overhaul.
2. **ต่อแผน** = ผลรวมส่วนต่างรายคันที่มีข้อมูลครบของแผนนั้นหลังกรอง.
3. **รวมทั้งหมด** = ผลรวมส่วนต่างรายการที่มีข้อมูลครบตามปี แผน คำค้น ยี่ห้อ รุ่น ประเภท และความคืบหน้าที่เลือก.
4. **ส่วนต่างเฉลี่ย** = ส่วนต่างรวม ÷ จำนวนรายการที่คำนวณได้. ไม่หารด้วยรถที่ไม่มีราคา.
5. **เปอร์เซ็นต์** = ส่วนต่างรวม ÷ ราคากลางรวมของรายการเดียวกัน × 100. ไม่เฉลี่ยเปอร์เซ็นต์รายคัน. ราคากลาง 0 แสดงเปอร์เซ็นต์ —; ยังแสดงผลต่างเป็นบาทได้.
6. **ค่าติดลบ** = ค่า Overhaul สูงกว่าราคากลาง. ไม่ clamp เป็น 0.
7. โหมด **ค่าใช้จ่ายที่อนุมัติแล้ว** ใช้ค่าอะไหล่ตัวรถ + อะไหล่เครื่องมือกล + ค่าแรง + ค่าใช้จ่ายอื่น ของงานที่อนุมัติปิดแล้วครบทุก PO ของรถในแผน. งานรออนุมัติไม่ถูกนับเป็นค่าใช้จ่ายที่อนุมัติแล้ว. ไม่มีค่าใช้จ่ายครบแสดง —. ค่าแรง 0 ที่ระบุจริงนับได้.
8. ราคากลางและค่าใช้จ่ายในแต่ละยอดใช้รายการรถชุดเดียวกันเสมอ พร้อม coverage `คำนวณได้ n/m รายการ` และจำนวนที่ยังไม่รวม.
9. รถซ้ำหลาย PO ในแผนเดียว deduplicate ด้วย (plan ID, vehicle ID). ราคากลาง/ค่าประเมินนับครั้งเดียว; ค่าใช้จ่ายอนุมัติรวมทุก PO. รถคันเดียวอยู่หลายแผนแสดงแยกเป็นงานของแต่ละแผน. นับรถจริงไม่ซ้ำแยกต่างหาก. ผลรวมส่วนต่างของงานหลายแผนจึงไม่ใช่การประเมินราคาซื้อรถไม่ซ้ำทั้งกองรถ.
10. นี่เป็นส่วนต่างเทียบ **ราคากลาง** ไม่ใช่ยอดเบิกจ่ายหรือเงินงบประมาณคงเหลือ และไม่ใช้ราคาทุนเดิมของรถเป็นราคาซื้อใหม่. ไม่ติดตั้งเกณฑ์แจ้งเตือน 10% จาก Q.4 เพราะ PDF ระบุเองว่ายังเป็นตัวอย่างที่ไม่เคาะ. แสดงกรณี Overhaul สูงกว่าราคากลางเป็นป้ายในรายละเอียดเปรียบเทียบแทน.

วิธีลอง: แท็บรถ → เลือกปีงบประมาณ/แผน → กดกราฟเพื่อกรอง → “ดูส่วนต่างรายคัน” → “ระบุราคา”. หรือเข้าแผน → ไอคอนแก้ไขราคาในแถวรถ → กรอกสองราคา → กลับ Dashboard. ปุ่ม “วิธีคำนวณ” อธิบายสูตรและขอบเขตในหน้า.

## ปรับความสมจริงและรายการแผน — 11 พ.ย. 2569 (feedback ล่าสุด)

- รายการแผนเพิ่มคอลัมน์ **ราคาประเมิน Overhaul (บาท)**. รวมรถทั้งหมดในแผนด้วย vehicle ID ไม่ซ้ำ ไม่รวมซ้ำตาม PO; หากไม่มีรถหรือมีราคารถแม้แต่คันเดียวที่ยังไม่ทราบ ให้ยอดรวมเป็น —. ไม่แสดงยอดบางส่วนเหมือนเป็นยอดครบทั้งแผน. ค่า 0 ที่กรอกจริงรวมได้และเป็น 0.00.
- ความคืบหน้ารายการแผนและ PO เป็น **เปอร์เซ็นต์**. ใช้ค่าเฉลี่ยข้อมูลความคืบหน้าที่บันทึกของรถชุดเดียวกับ Dashboard; รถหลาย PO ใช้ความคืบหน้าต่ำสุดของงานครบทุก PO, ถ้าบาง PO ยังไม่มีความคืบหน้าให้รายคันเป็นไม่ทราบ. Hover ที่เปอร์เซ็นต์มีจำนวนรายการที่มีข้อมูลให้ตรวจสอบ. ไม่มีข้อมูลเป็น —; อนุมัติปิดงานแล้วเป็น 100%. ไม่แสดงอัตรา “ปิดแล้ว/จำนวน PO” ในคอลัมน์ความคืบหน้าอีก.
- สถานะ “รอเลข PO” เปลี่ยนเป็น **รอเลข Purchase order** ทั้งตาราง ตัวกรอง และรายละเอียด.
- เอาแถบ Mockup และข้อความการสกัดข้อมูล/ทดสอบออกจากหน้าทำงาน. ที่มาและข้อจำกัดยังบันทึกในเอกสารนี้. ไม่มีการเปลี่ยนให้ต้นแบบยิง API UAT.
- การตอบรับ/ปฏิเสธ/อนุมัติไม่วางเป็นปุ่ม “จำลอง” กลางหน้าแล้ว. เข้าผ่านเมนูผู้ใช้งานมุมขวาบน → บทบาทผู้ใช้งาน → หน่วยงานเจ้าของรถ หรือ ผู้บังคับบัญชา. เมื่อกลับทำงานฝั่ง กบค. ให้เลือกบทบาท กบค. การเปลี่ยนบทบาทและการตอบรับยังเก็บเฉพาะ localStorage ของต้นแบบ.

## แก้เพิ่มรถเข้า Purchase Order ว่างหลายแผน — 11 พ.ย. 2569

ผู้ใช้ยืนยันว่าต้องมีรถมาเลือกได้หลายแผน. สาเหตุที่ทำซ้ำได้: ตัวเลือกเดิมอ่านเฉพาะ `plan.cars` แต่ snapshot มีรถเฉพาะ ORZ6900026. แผนอื่นมีรายการแผนแต่ `cars=[]` จึงเปิดตัวเลือกแล้วว่าง.

รถที่ยังไม่อยู่ในแผนจะเพิ่มเข้าแผนและ Purchase Order พร้อมกัน หลัง validation ครบและกดบันทึกจริง (กรณีแก้ไขต้องยืนยันด้วย). ยกเลิก form/confirmation หรือบันทึกไม่ผ่าน validation ไม่เพิ่มรถลงแผน. คงราคาเดิมของรถที่มีอยู่แล้ว; รถใหม่ที่ไม่มีราคายังเป็น null/—. ไม่ reset localStorage ของผู้ใช้หรือเปลี่ยนรถในแผนอื่น. กรณีเลือกรถครบทุกคันแสดง empty state ที่อธิบายเหตุผล และ “แสดงเฉพาะที่เลือก” เมื่อยังไม่เลือกแสดงข้อความตรงกับสถานะนั้น.

## Chart.js และข้อมูลราคาที่คำนวณได้ — 11 พ.ย. 2569 (คำสั่งล่าสุด)

เปลี่ยนกราฟทั้ง4กล่องเป็น Chart.js4.4.8 (`assets/vendor/chart.umd-4.4.8.js`, MIT license เก็บคู่กัน): horizontal bar เปรียบเทียบราคา, doughnut ความคืบหน้า, polarArea ประเภทรถ, horizontal bar อันดับยี่ห้อ. ยึด layout ภาพผู้ใช้และสี tokens. Destroy instance เมื่อ render/เปลี่ยนหน้า; defer render หลังจบ Chart click เพื่อไม่ทำลาย tooltip ระหว่างประมวลผล event.

เจ้าของงานขอเติมราคาแล้ว จึงแทนคำสั่งเดิมที่ให้เว้นราคาเป็น— เฉพาะข้อมูลตัวอย่างที่กำหนดให้: `PX_PRICE_EXAMPLES` ใน data.js เป็น fixture ระบุชัดว่าไม่ใช่ราคาที่อ่านจากUAT. Migration `priceExamplesVersion=1` เติมเฉพาะช่องว่างของรถ8คันใน ORZ6900026 ครั้งเดียว คงราคาที่ผู้ใช้เคยกรอก. ไม่ใช้ราคาซื้อเดิมเป็นแหล่งราคากลางและไม่แก้ทะเบียน/งบประมาณUAT. งบของแผน UAT นี้เป็นข้อมูลทดสอบ100,000บาท จึงไม่อ้างว่ายอดประเมินอยู่ในวงเงินหรือเป็นเงินงบประมาณคงเหลือ.

ยอดราคากลางตาม fixture =23,160,000.00บาท; ราคาประเมิน =2,483,000.50บาท (ต่อรถในแผน รวมขอบเขตทุกPurchase Order ไม่ซ้ำ). กราฟรวมเฉพาะรายการที่มีราคาครบสองค่า. เพิ่มคอลัมน์ “ราคาจริง (บาท)” ในตารางรถ. ราคาจริง =ค่าแรง +Σ(จำนวนอะไหล่×ราคาต่อหน่วย)+ค่าใช้จ่ายอื่น ที่บันทึกหลังส่งมอบ(stage>=7); ไม่เท่ากับอนุมัติแล้ว. หลายPurchase Order ต้องมีค่าใช้จ่ายครบทุกใบก่อนรวม. `approved` แยกต่างหากเฉพาะstage9 เพื่อไม่เปลี่ยนความหมายรายงานอนุมัติเดิม.

## แก้ความหมาย “ราคาจริง (บาท)” ตามเจ้าของงาน — 11 พ.ย. 2569 (ล่าสุด)
