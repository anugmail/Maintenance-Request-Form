# Spec — ขยาย plan-skeleton ให้ครอบทั้งโฟลว์ (11 หน้าจอ)

วันที่ 9 ส.ค. 2569 · สถานะ: ตกลงกับเจ้าของงานแล้ว รอทำแผน implement

## ปัญหา

`plan-skeleton.html` (โครงแก้ได้) ครอบแค่ **ฝั่งออกเลขงาน 4 หน้าจอ 41 ฟิลด์**
`skeleton.html` (โครงกระดูก) ครอบ 5 เฟส แต่ **อ่านอย่างเดียว** และเป็นเอกสารอธิบาย ไม่ใช่โครง

⇒ เวลาไปนั่งเก็บ requirement เฟส 2–5 กับเจ้าของงาน **ไม่มีที่ให้แก้ฟิลด์สดๆ**

## สิ่งที่จะได้

หน้าเดียว ครอบทั้งโฟลว์ 11 หน้าจอ แก้โครงได้ทุกจอ พร้อมช่องตอบคำถามที่ยังไม่เคาะ และ export เป็น Markdown ไปแปะ `plan.md`

## 1 · ขอบเขต

**ทำ**
- ขยาย `plan-skeleton` จาก 4 เป็น **11 หน้าจอ**
- **ยุบ `skeleton.html` ทิ้ง** — เนื้อที่เก็บไว้คือ *คำถามที่ยังไม่เคาะ* ย้ายเข้าหน้าใหม่ · ส่วนที่เป็นคำอธิบาย (ใครทำ/รับเข้า/ส่งออก/ลำดับขั้น) **ตัดทิ้ง ไม่ย้ายตาม**
- แยกข้อมูลออกเป็น `skeleton-data.js`
- เพิ่มขั้น **"ยืนยันรถเข้าร่วมแผน"** เข้า flow (ต้นเฟส 1) พร้อมอัปเดต `Diagram/`

**ไม่ทำรอบนี้**
- ปุ่ม "ยกโครงจาก skeleton ไปหน้าจริง"
- auto-sync ธง `done` กับหน้าจริง
- **หน้าจริง** ของยืนยันรถ (รอบนี้ได้แค่โครงใน skeleton)
- สายว่าจ้างในเฟส 1

## 2 · หลักการที่ตกลงกัน

**skeleton = โครงเปล่า ไม่ใช่เอกสาร**
หน้าจอมีแค่ *section + ตารางฟิลด์ + พรีวิว* ไม่มีคำอธิบายว่าเฟสนี้คืออะไร ใครทำ ลำดับยังไง
เหตุผล: flow มีเจ้าของอยู่แล้วที่ `Diagram/01-บำรุงรักษาตามวาระ/` ถ้าเขียนซ้ำ 2 ที่จะเพี้ยนกัน

**skeleton = สิ่งที่ตกลงไว้ · หน้าจริง = สิ่งที่ทำแล้ว**
ทุกฟิลด์มีธง `done` ⇒ ป้าย `ยังไม่ทำในหน้าจริง` คือช่องว่างระหว่างสองอัน
ฟิลด์ที่ยังไม่มีแหล่งข้อมูล ⇒ ป้าย `รอข้อมูล` คือ requirement ใหม่ที่ต้องไปขอ API

**แก้ที่นี่ไม่กระทบหน้าจริง** — คนละ localStorage key

## 4 · โครงข้อมูล

```js
{
  version: 2,
  screens: [{
    id:    'ph2',                          // คงที่ ใช้เป็นกุญแจตอน migrate
    group: 'issue' | 'phase' | 'unit',     // ใช้แบ่ง 3 กลุ่มบนแถบนำทาง
    no:    '2',                            // เลขที่โชว์บนแท็บ ('1a' '1b' ได้)
    title: 'ดำเนินการบำรุงรักษา',
    real:  null | 'index.html',            // ลิงก์หน้าจริง — null = ยังเป็นหน้าเปล่า
    sections: [{
      id, title, kind: 'form' | 'table',
      fields: [{ key, label, src, show, note, done }]
    }],
    asks: [{ id: '2.1', q: '…', ans: '', status: 'open' | 'agreed' | 'dropped' }]
  }]
}
```

เทียบของเดิม: เพิ่ม `version` `group` `no` `real` `asks` · ตัด `meta` `does` ที่เคยเสนอไว้ตอนแรกออก (เจ้าของงานสั่งให้หน้าโล่ง)

`real` ทำหน้าที่ 2 อย่างพร้อมกัน — เป็นทั้งธง ✅/⬜ และเป็นปลายทางของไอคอน ↗

## 5 · แถบนำทาง

3 กลุ่ม กลุ่มละแถว หัวแถวเป็นชื่อกลุ่ม

```
── ออกเลขงาน ─────────────────────────────────
  ① ชื่อแผน + เลือกรถ ✅↗   ② รายการอะไหล่ ✅↗   ③ สรุปแผนทั้งปี ✅↗

── 5 เฟสปฏิบัติการ ────────────────────────────
  ①a ยืนยันรถ ⬜   ①b เบิก/จัดหา + แผนเดินทาง ✅↗   ② ดำเนินการ ⬜
  ③ ตรวจรับ ⬜     ④ รายงาน ⬜                   ⑤ ต้นทุน ⬜

── หน้าหน่วยงานอื่น ───────────────────────────
  ฝ่ายพัสดุ ✅↗    ต้นทาง — ยืนยันรถ ⬜
```

- `✅` = `real !== null` · `⬜` = `real === null`
- `↗` = ลิงก์ไปหน้าจริง โผล่เฉพาะอันที่มี `real` · กดแล้วเปิดแท็บใหม่
- ป้ายสถานะฉบับอ้างอิงอยู่ที่ `Diagram/README.md` + `plan.md` — หน้านี้แค่สะท้อนมา

## 12 · ผลกระทบต่อ flow (ทำในคอมมิตเดียวกัน)

ขั้น **ยืนยันรถ** เป็นของใหม่ที่ยังไม่มีในผัง ต้องแก้ `Diagram/` ตาม convention

**ตำแหน่ง** — ต้นเฟส 1 ก่อนทำแผนเดินทาง (ต้องรู้ก่อนว่ารถคันไหนเข้าได้จริง ถึงวางวัน/จุดนัด/คำนวณเบี้ยเลี้ยงได้ถูก)

```
เฟส 1 ├─ เบิก/จัดหาอะไหล่
      ├─ ยืนยันรถเข้าร่วมแผน   ← ถามต้นทาง รอคำตอบ
      └─ ทำแผนเดินทาง          ← ใช้เฉพาะรถที่ยืนยันแล้ว
```

**2 ฝั่ง**

| ใคร | ยืนยันอะไร |
|---|---|
| เจ้าของรถ (หน่วยงานที่ใช้รถ) | รถว่างช่วงนั้นไหม · ติดงานอะไรอยู่ |
| กรย. (ผู้ดูแลรถ) | สภาพรถพร้อมเข้าบำรุงรักษาไหม · จุดนัดรับ |

**คันที่ตอบ "ไม่พร้อม"** — ค้างไว้ให้ กบค. ตัดสินรายคัน (`ตัดออกจากแผน` / `เลื่อนไปรอบหน้า` / `ยืนยันเข้าตามเดิม`) ไม่ตัดอัตโนมัติ · เฟส 1 ไปต่อขั้นแผนเดินทางได้เมื่อทุกคันมีข้อสรุปแล้ว

ของเดิม "ส่ง Noti แจ้งเจ้าของรถ + กรย." ที่เคยอยู่ **ท้าย** เฟส 1 เป็นการแจ้งทางเดียว → ย้ายมาเป็น **ต้น** เฟส 1 และกลายเป็นถาม-ตอบ

## 13 · แนวทางที่พิจารณาแล้วไม่เอา

| | ทำไมไม่เอา |
|---|---|
| ยัดทุกอย่างใน `plan-skeleton.js` ไฟล์เดียว | จะกลายเป็น ~900 บรรทัด ข้อมูลปนกับ logic |
| เก็บโครงเป็น JSON แล้ว `fetch` | `fetch` บน `file://` พัง · โปรเจกต์ static ไม่มี build · ของเดิมเป็น `.js` หมด |
| เก็บ `skeleton.html` ไว้คู่กัน แบ่งหน้าที่กันคนละชั้น | ต้องจำว่าอะไรอยู่หน้าไหน · เจ้าของงานเจอ 2 หน้าชื่อคล้ายกัน |
| ให้หน้าจริง (`plan-new.html`) แก้โครงได้เอง | ใส่ฟิลด์ที่ยังไม่มีข้อมูลไม่ได้ ซึ่งคือของที่มีค่าที่สุดตอนเก็บ requirement |
| คงคำอธิบายเฟส (ใครทำ/ลำดับขั้น) ไว้ในหน้า | เจ้าของงานสั่งให้โล่ง · flow มีเจ้าของที่ `Diagram/` แล้ว เขียนซ้ำจะเพี้ยน |
