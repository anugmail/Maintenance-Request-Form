## 2 · ตรรกะแหล่งของ — เปลี่ยนจาก "แหล่งเดียวต่อรายการ" เป็น "เกินยอด = จัดซื้อส่วนต่าง"

เดิม `partSource(x)` เลือกแหล่งเดียวตามลำดับ `stock > 0` → `stockAlt > 0` → `buy`
ทำให้ของที่มีในคลังไม่พอ ยังถูกนับเป็น "เบิก" ทั้งก้อน

ใหม่:

```
onHand(p)   = p.stock + p.stockAlt      // 2 คลังเบิกได้เหมือนกัน ต่างแค่ที่เก็บ
fromStock(x)= min(x.qty, onHand(p))
toBuy(x)    = max(0, x.qty - onHand(p))
stockCost   = Σ fromStock(x) × price
buyCost     = Σ toBuy(x)     × price
```

**ผลข้างเคียงที่ต้องจัดการ:** `partsRowsHTML(no, list, editable)` เป็นตารางแบบเดิม
ถูกใช้ 2 ที่ — `partsEditorHTML` (editable=true) และ `partsSummaryHTML` (editable=false)
ตัวแรกถูกแทน ตัวหลังยังต้องใช้ → คงตารางไว้เป็นตัวอ่านอย่างเดียว (ตัดพารามิเตอร์ `editable`
และโค้ดฝั่งแก้ไขทิ้ง) พร้อมเปลี่ยนคอลัมน์ "คลัง" ให้ใช้ตรรกะ `fromStock`/`toBuy` ชุดเดียวกัน
ไม่งั้นสรุปหลังยืนยันจะไม่ตรงกับตอนกดยืนยัน

ฟังก์ชันที่เลิกใช้แล้วต้องลบ ไม่ปล่อยค้าง: `invCell()` · แถบ `.srcbar`/`.srcpill` ใน `partsRowsHTML`
· `addListHTML()` · `renderAddList()` · state `E.addOpen`

## 3 · Stepper 6 ขั้น — เฉพาะเส้น "ซ่อมเอง"

เพิ่มชุดขั้นใหม่ ใช้เมื่อ `j.route === 'self'` เท่านั้น เส้นส่งอู่ (`quote`) และซ่อมหน้างาน
(`loc==='onsite'`) ยังใช้ `KSTEPS` 4 ขั้นเดิม

```js
const SELF_STEPS = [
  { k:'parts',   label:'เบิกอะไหล่',          icon:'inventory_2' },
  { k:'appt',    label:'นัดหมายวันซ่อม',      icon:'event' },
  { k:'inspin',  label:'ตรวจสภาพก่อนซ่อม',    icon:'fact_check' },
  { k:'work',    label:'ดำเนินการซ่อม',       icon:'engineering' },
  { k:'inspout', label:'ตรวจสภาพรถหลังซ่อม',  icon:'checklist' },
  { k:'close',   label:'รายงานการปิดงาน',     icon:'task_alt' }
];
```

เหนือ stepper เป็น breadcrumb `รับเรื่องแล้ว › ซ่อมเอง` — สองขั้นที่มาก่อนไม่อยู่ใน stepper แล้ว
เพราะเข้าหน้านี้ได้ต่อเมื่อผ่านมาแล้วทั้งคู่

`renderKbkDetail()` เลือกชุดขั้นจาก `j.route`: ซ่อมเอง → `SELF_STEPS` + `selfStepIndex(j)`
· อื่นๆ → `KSTEPS` + `stepIndex(j)` (เดิม)

## 4 · เรียงลำดับ state ของเส้นซ่อมเองใหม่

ลำดับเดิมในโค้ดคือ `partsOK` → ตรวจสภาพขาเข้า+`KBK_STEPS` (`j.wi` 0–4) → เปิดตารางว่าง →
`phase:'slots'` → `phase:'appt'` → ตรวจสภาพขาออก → `closed` — คือ**นัดหมายอยู่ท้าย** (นัดรับรถคืน)

ดีไซน์ใหม่ให้**นัดหมายวันซ่อมอยู่ขั้น 2 ก่อนเริ่มซ่อม** จึงต้องสลับลำดับ:

| ขั้น | เงื่อนไข (`selfStepIndex`) | แผงที่แสดง |
|---|---|---|
| 1 เบิกอะไหล่ | `!j.partsOK` | หน้าจอใหม่ (ข้อ 1) |
| 2 นัดหมายวันซ่อม | `partsOK && !j.appt` | ตารางว่าง → `kbkSendSlots()` → `phase:'slots'` → ผู้แจ้งเลือก → `phase:'appt'` |
| 3 ตรวจสภาพก่อนซ่อม | `j.appt && !j.inspIn` | `inspFormHTML(no,'in',j)` |
| 4 ดำเนินการซ่อม | `j.inspIn && j.wi < 4` | `KBK_STEPS` tracker + ปุ่ม `kbkAdvance()` |
| 5 ตรวจสภาพรถหลังซ่อม | `j.wi === 4 && !j.inspOut` | `inspFormHTML(no,'out',j)` |
| 6 รายงานการปิดงาน | `j.inspOut \|\| phase==='closed'` | `costFieldsHTML()` + ปิดงาน |

จุดที่ต้องแก้ตาม:

- ป้ายในแผงนัดหมายเปลี่ยนจาก "นัดรับรถ" → "นัดหมายวันซ่อม" (ทั้งฝั่ง กบค. และฝั่งผู้แจ้ง)
- `kbkPartsConfirm()` เดิมตั้ง `partsOK=true` แล้วตกไปแทร็ก `j.wi` — เปลี่ยนเป็นพาไปขั้นนัดหมาย
- ตรวจสภาพขาเข้าเดิมผูกกับ `j.wi === 0` — ย้ายมาผูกกับ `j.appt` แทน
- `TG.inspection` ปิดอยู่ → ข้ามขั้น 3 และ 5 (stepper แสดง 4 ขั้น)
