# AC — Overhaul v2 ฉบับใหม่ · A–P

วันที่ 9 พฤศจิกายน 2569 · Desktop · ร่างเกณฑ์ตรวจรับสำหรับ BA / Design / Dev / QA

ยึดรหัส ชื่อ state และเนื้อหาจากปลั๊กอิน Overhaul v2 ปัจจุบัน พร้อมคำสั่งล่าสุดที่เจ้าของงานยืนยัน. แยกจากเอกสาร AC เก่า; ไม่ใช่การยืนยันผลทดสอบผ่าน และยังไม่ได้เทียบเฟรมที่แก้มือหลังสร้างใน Figma.

ครอบคลุม **16 Flow / 78 เฟรม** ตั้งแต่ A ถึง P เท่านั้น. ไม่รวม Q ทดลอง, R ทางเข้าเดิม, S แบบเก่า, Summary/Notification/Toast ชุด export แยก หรือฟีเจอร์อื่นใน SP09. Toast ที่อยู่ในเฟรม A–P ยังอยู่ใน AC ของเฟรมนั้น.

รหัส `OH2-…-NEW-*` ใช้แยกฉบับใหม่. A.1 ใช้ 16 ข้อเดิมจากไฟล์ AC-A1-new โดยคง ID เดิม. ข้ออื่นระบุแยกตามแต่ละเฟรม ไม่ใช้ AC ของทั้ง Scene แทนทุก state.

## เกณฑ์ร่วม

1. อ้างแผน Purchase Order และรถของรายการที่เลือก ไม่ใช้เลข/ข้อมูลตัวอย่างคงที่เป็นข้อมูลจริง.
2. ใช้ VMS Plus ตามแบบ; ตัวกราฟ A.5 ใช้เลเยอร์แก้ไขได้ตามที่อนุญาต. Desktop กว้าง 1440 และเนื้อหาจอยาวต้องแสดงครบ.
3. Toast บนจอชิดมุมขวาบนระยะ 0; overlay ครอบคลุมขนาดเฟรมจริงหลังจัดเนื้อหา.
4. จำนวนเงินแสดง comma และทศนิยมสองตำแหน่ง. ข้อมูลที่ไม่มีใช้ “—”/“-” ตามช่อง ไม่แสดง NaN และไม่เติม 0 โดยไม่มีข้อมูล.
5. เปอร์เซ็นต์แสดงค่าจริง เช่น 23%; ป้ายไม่ปัดตามช่วง variant ของ Progress bar.
6. ข้อที่ระบุ “กด/บันทึก/กลับ/เปิด” เป็นเกณฑ์ interaction ที่ต้องทดสอบเมื่อเชื่อมการทำงานจริง; การสร้างเฟรมได้อย่างเดียวไม่ถือว่าผ่าน.
7. Validation/error ต้องไม่แสดง success หรือเลื่อนขั้นจากคำสั่งที่ล้มเหลว; ข้อสำเร็จต้องมีข้อมูลบันทึกกลับมาอ่านได้.

## ประเด็นที่ต้องยืนยันก่อนปิดตรวจรับ

- ขอบเขตค่าตรงจุดแบ่งช่วงงบ, วิธีรวม checkbox และจังหวะ apply/search/sort.
- จำนวนรถขั้นต่ำ รถซ้ำข้าม Purchase Order และการเปลี่ยนรถหลังเริ่มงาน; ฟอร์มตัวอย่างบาง state ยังมี selection ไม่ตรง pool ของแผน ต้องปรับก่อน UAT.
- วันสัญญาบังคับหรือไม่ และ validation วันเริ่ม/สิ้นสุด.
- นโยบายลบแผน/PO ที่มีงานดำเนินการแล้ว และผลต่อข้อมูลลูก/เอกสาร; ไม่อนุมาน hard delete/cascade จากข้อความยืนยัน.
- ชนิด/ขนาด/จำนวนไฟล์ต่อส่วน, เอกสาร Safety บังคับก่อนผ่านหรือไม่ และกติกา checklist ที่ตอบไม่มี/ชำรุด/ผิดรุ่น.
- นิยามรายการ progress ล่าสุดเมื่อกรอกย้อนหลัง และความละเอียดทศนิยมที่รับได้; ยืนยันช่วง 0–100 และ gate ล่าสุด 100% แล้ว.
- ค่าเปอร์เซ็นต์ที่ Header งานรายคันยังมีตัวอย่างจากเลขขั้นตอน; ต้องเชื่อมเปอร์เซ็นต์งานจริง ไม่ถือว่าสูตรตัวอย่างผ่าน.
- Text input ของ modal เปอร์เซ็นต์ยังต้องตรวจ suffix % ใน component จริง.
- ตัวอย่างรับประกัน 365 วันไม่ใช่ข้อสรุปแทน JO 180 วัน; ต้องสรุปประเภทและจุดเริ่มนับก่อนตรวจค่าประกัน.
- ชื่อปุ่ม “ปิดงาน” ใน O ต้องสอดคล้องการส่งอนุมัติก่อนปิดจริง; หน้าผู้อนุมัติ/ตีกลับยังไม่ครบจาก P.1/P.2 เพียงสองเฟรม.
- แม่แบบนำเข้าอะไหล่ นิยามราคาต่อหน่วย/ยอดรายการ ภาษี และการปัดเศษยังต้องยืนยัน.
- หน้าราคารถบางจุดยังแปลง string มี comma เป็น Number; ต้องไม่ปล่อยให้แสดง NaN ตามเกณฑ์ร่วม.

ข้อข้างต้นไม่ใช่ AC ใหม่ที่ได้รับการอนุมัติโดยอัตโนมัติ. สถานะเอกสารนี้เป็นเกณฑ์เป้าหมายตามแบบ/คำตอบล่าสุด ไม่ใช่ผลยืนยัน import, layout, persistence หรือระบบอนุมัติจริง.
