# Acceptance Criteria — งาน Overhaul

ฉบับวันที่ 9 พฤศจิกายน 2569 · สำหรับ BA / Design / Dev / QA

ขอบเขต: หน้าจอ Desktop ของปลั๊กอิน Overhaul และข้อปรับล่าสุดที่เจ้าของงานยืนยัน รวมแผน Purchase Order งานรายคัน Dashboard การแจ้งเตือน และ Summary รายคัน. ไม่รวมฟีเจอร์อื่นในปลั๊กอิน SP09.

เอกสารนี้เป็น **ร่างเกณฑ์ตรวจรับ** ไม่ใช่ผลทดสอบผ่านหรือคำยืนยันว่าระบบเชื่อมข้อมูลจริงแล้ว. ข้อมูลตัวอย่าง เช่น เลขแผน ทะเบียน ราคา จำนวนแถว และเปอร์เซ็นต์ ไม่ใช่ค่าคงที่ของระบบ.

## วิธีใช้

- **ยืนยัน:** ข้อกำหนดที่เจ้าของงานยืนยันในการรีวิว.
- **ตามแบบ:** สิ่งที่แสดงในแบบหน้าจอ ใช้ตรวจ UI ได้; พฤติกรรมระบบที่ระบุยังต้องพัฒนาและทดสอบจริง.
- **รอยืนยัน:** กติกาที่ยังไม่ชัด ไม่ถือเป็นเงื่อนไขผ่าน/ไม่ผ่านจนกว่าจะได้ข้อสรุป.
- รหัส `OH-…` เป็นรหัส AC ในเอกสารนี้ ไม่ใช่เลขข้อ JO หรือรหัส user story เดิม.
- รหัสจออิง inventory ล่าสุด: A–S รวม 86 state. งานหลัก A–P มี 78 state; Q ทดลอง 4 state, R ทางเข้าเดิม 3 state, S แบบเก่า 1 state.
- ฉากที่เคยเรียก T.1 ใน feedback ปัจจุบันอยู่ **P.1**; Dashboard คือ **A.5**. Q.1 ปัจจุบันเป็นชุดทดลอง ไม่ใช่แท็บรถ. ต้องใช้รหัสปัจจุบันเมื่ออ้างอิงงาน.
- หน้าแจ้งเตือนและ Summary เป็นชุดแยก: ใช้ namespace `NOTI:` / `SUMMARY:` เพื่อไม่ชนกับรหัสจอชุดหลัก.

| OH-A-06 | ความคืบหน้าแผนคำนวณจากรถทุกคันใน Purchase Order ทุกใบของแผน ให้น้ำหนักต่อคันเท่ากัน; ไม่เฉลี่ยค่าเฉลี่ยของแต่ละ Purchase Order และไม่ใช้จำนวนรถปิดงาน | ยืนยัน |

| OH-A-13 | เปลี่ยนรุ่นรถแล้วจำนวนรถ กราฟราคา กราฟ progress กราฟประเภท และตารางต้องอ้างผลลัพธ์ชุดเดียวกัน; ถ้าไม่พบข้อมูลให้แสดง empty state และไม่เหลือตัวเลขจากผลลัพธ์ครั้งก่อน | ยืนยัน |
