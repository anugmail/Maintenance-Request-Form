## สิ่งที่เห็นจาก UAT

- รายการแผน: ชื่อหน้า จัดการงาน Overhaul, ค้นหา, ตัวกรอง, ปุ่มสร้างแผน, ตารางหมายเลข/ชื่อแผน ประเภทงบ ปีงบ งบประมาณ ความคืบหน้า สถานะ วันที่สร้าง และเมนู …; แสดงเงินสองตำแหน่ง. มี pagination.
- ตัวกรอง: ปีงบ dropdown, งบประมาณ 6 ช่วงแบบ checkbox, สถานะ และปุ่มล้าง/ยกเลิก/ตกลง.
- ฟอร์มสร้าง: ข้อมูลแผน ชื่อ ปีงบ งบประมาณ ประเภทงบ และเอกสาร 3 กลุ่ม. ยังไม่มีเลือกรถเป็นส่วนที่ 2 และไม่มีแท็บรถ/Dashboard ในรายการเดิม.
- รายละเอียดแผนแสดงข้อมูลแผน เอกสาร ตาราง Purchase Order (หมายเลข ชื่อ อู่ จำนวนรถ ความคืบหน้า ระยะสัญญา เมนู) และส่วนอะไหล่. ตัวอย่าง Test PO-001 มี 3 PO; อ่านเทียบโดยไม่แก้รายการ.
- รายละเอียด PO แสดงทะเบียน รุ่น/ประเภท หน่วยงานเจ้าของรถ เลขไมล์ อายุ และสถานะ. หน้างานรายคันมี 7 ขั้น รวมยืนยันการส่งอนุมัติ; นัดหมายเดิมเป็นช่วงวัน ส่วน feedback ล่าสุดกำหนดวันเดียวและมีปุ่มข้ามขั้น.
- UAT เดิมแสดงความคืบหน้าแบบจำนวนรถ เช่น 0/3. Feedback ล่าสุดกำหนดเปอร์เซ็นต์รายคัน จึงใช้ feedback ในปลั๊กอิน.

| ช่วง | การปรับตาม feedback |
|---|---|

## ผลตรวจและข้อจำกัด

ตัวสร้างหน้าจอหลัก 135/135 callbacks ผ่านเมื่อมี component ครบ; Summary/History 4 state และ SP09 80 callbacks ผ่าน. ทดสอบเปอร์เซ็นต์ถ่วงน้ำหนักต่อคัน ฟอร์มติดตาม 4 ช่อง สัญญา PO รถตามแผน ราคา/อายุ/ตัวกรอง Dashboard และเมนู scenario ผ่าน.

ผลนี้เป็นการ execute ตัวสร้างด้วย mock API ไม่ใช่การยืนยันภาพจริง/variant/import ใน Figma. I.1–I.5 และหน้าดูย้อนหลัง S.5 ต้องมี ReceiptChecklist/HandoverSignature จริง; เมื่อไม่มี component ต้องบล็อกพร้อมเหตุผล. P.1–P.2 ต้องมีการ์ดยานพาหนะต้นฉบับ 2623:88498 ในไฟล์ Maintain-D; ไม่ใช้การ์ดจำลองแทน. Full library harness ยังขาด Table definition. ยังไม่ได้เปลี่ยนเว็บ UAT หรืออัปเดตเฟรมเดิมใน Figma.
