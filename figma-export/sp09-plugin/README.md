# Maintain-D — SP09 งานเพิ่มเติม

ขอบเขตตามคำตอบเจ้าของงาน 9 พ.ย. 2569: งานอื่นนอก Overhaul ในกรอบ SP09 และการ์ด Overhaul สีเทาที่ยังไม่ได้ทำ. ภาพ PDF ที่มองเห็นระบุสีเทา UC-24-03/04; ไม่สร้าง 24/24-01/24-02 สีเหลืองซ้ำ.

## ชุดที่สร้างได้ในสคริปต์ปัจจุบัน

| **รวม** | **Desktop 1440** | **80** |

นี่คือจำนวน callback ที่เตรียมไว้ ไม่ใช่จำนวนเฟรมที่ตรวจผ่านใน Figma แล้ว. ทุก state เป็นข้อมูลตัวอย่าง; ปุ่มยังไม่มี prototype interaction/API. เบิก–คืนส่งคำขอไปคลังและแสดง “รอคลังดำเนินการ” ตามที่เจ้าของงานยืนยัน ไม่เปลี่ยนยอดสต็อก/ยอดคืนจริงจากการส่งคำขอ. คะแนนอู่คำนวณจาก fixture การประเมิน ไม่สร้างคะแนนเมื่อไม่มีประวัติ. Dashboard แยกค่าใช้จ่ายจริงจากราคาประเมินชัดเจน.

คำตอบเจ้าของงาน 9 พ.ย. 2569: ยืนยัน Overhaul เฉพาะ UC-24-03/04; ระบบแนะนำอู่เฉพาะประเภทรถก่อน ไม่ใช้ระยะทาง ยี่ห้อ คะแนน หรือ AI จัดอันดับ; หน้า Login เป็นทางเข้าไป Keycloak ไม่รับรหัสผ่านเอง; รายงานถึงเลือก/กรอง/รายการไฟล์; Flow ตอบรับครอบคลุมนัดเข้าอู่/รับรถ/แผนบำรุงรักษา; ใช้ตารางและพักปฏิทินไว้; เบิก–คืนส่งคำขอไปคลังก่อน.

## เส้นทางตรวจจอ

- H ทางเข้าระบบ → หน้า Keycloak ภายนอก (ไม่ได้ออกแบบหน้ากรอกรหัสผ่านใหม่).
- I ใบแจ้งซ่อม → ผลวิเคราะห์ → เลือกซ่อมเอง/ส่งอู่ → อู่ที่รองรับประเภทรถ → บันทึก/นัดซ่อม/ขอเบิกอะไหล่. ฟอร์มและคำขออะไหล่งานซ่อมอ้าง REQ-690001; งาน Overhaul ใน E อ้าง PO-700201 ไม่ปะปนกัน.
- J รายการรอตอบรับ → รายละเอียดตามประเภท → ยืนยันตอบรับ หรือปฏิเสธพร้อมเหตุผล → ผลตอบรับ/ส่งไม่สำเร็จ. state ผลตอบกลับไม่แสดงปุ่มส่งซ้ำ.
- E ฟอร์มเบิก/คืน → validation → ยืนยันส่งคำขอ → รายละเอียดรอคลัง; ยอดเบิก–คืนที่คลังทำแล้วแสดงแยกจากจำนวนที่ขอ.
- F/G กรองรายงาน → เลือกรายงาน → รายการไฟล์/ไม่มีไฟล์/โหลดไม่สำเร็จ. รายการไฟล์ดาวน์โหลดได้ในแบบจอโดยไม่เปิดลบ; ยังไม่แสดงเนื้อหา PDF สมมติ.

## เปิดใช้

Figma → Plugins → Development → Import plugin from manifest → เลือก `manifest.json` ในโฟลเดอร์นี้. เปิดปลั๊กอิน “Maintain-D — SP09 งานเพิ่มเติม (VMS Plus)”. ตรวจ component ก่อน แล้วเลือกบล็อกที่จะสร้าง. สร้างในหน้า `sp09-desktop-N` ใหม่; ถ้าข้อจำกัดแผน Figma สร้างหน้าไม่ได้ จะใช้ fallback ของ helper เดิมวางต่อท้ายและแจ้ง log. ไม่แทนที่/ลบจอเดิม.

ผลสร้างต้องอ่าน `สร้าง/คาดหวัง`, รายการล้มเหลว และรายการคำเตือนจาก UI; ไม่ถือว่ารันสำเร็จทั้งหมดหากยังมีรายการใดล้มเหลว. มีปุ่มคัดลอก log และอ่านโครงจอที่เลือก.

## Source และการ build

- แก้ `screens.js` สำหรับชุด SP09.
- ใช้ helper/keys/variant ที่แก้บั๊กแล้วจาก `../overhaul2-plugin/code.js`; ไม่คัดลอกไปดูแลเองอีกชุด.
- `code.js` เป็น bundle ที่ generate แล้วพร้อม import; ไม่แก้ไฟล์ generated โดยตรง.

```sh
node figma-export/build-sp09-plugin.js
node --check figma-export/sp09-plugin/code.js
node figma-export/test-sp09-plugin.js
```

## ขอบเขตที่พักไว้ / ไม่รวมในชุดนี้

1. ปฏิทินเดือน/สัปดาห์: เจ้าของงานให้พักและใช้ตารางก่อน.
2. อู่ใกล้เคียงและระบบแนะนำขั้นสูง: ระยะแรกใช้เฉพาะประเภทรถตามที่ยืนยัน.
3. หน้าปฏิบัติงานคลังและ integration Smart Inventory: ชุดนี้จบที่คำขอรอคลัง ไม่ทำผลตัด/คืนสต็อกทันที.
4. เนื้อหา PDF/แบบฟอร์ม กฟภ.: พักรอแบบจริงตามที่ยืนยัน; ทำรายการไฟล์และตัวกรองแล้ว.

## ผลตรวจและข้อจำกัด

เทสต์ execute callback จริงของ SP09 ทั้ง 80 state พร้อมตรวจ dependency ที่ประกาศ, ห้ามเพิ่มลูกใน instance, การคำนวณต้นทุน/คะแนน, การจับคู่ประเภทรถที่ไม่กรองยี่ห้อหรือระยะทาง, validation เบิกคืน/เหตุผลปฏิเสธ, ส่งคำขอไม่เปลี่ยนสต็อก และ dispatch ที่แยกจากปลั๊กอิน Overhaul. ตรวจว่าหน้า Login ไม่มีช่องรหัสผ่านหรือ navigation ของผู้เข้าสู่ระบบแล้ว.

เทสต์ไม่ได้ตรวจ import/variant/auto-layout/font ใน Figma จริง. ข้อจำกัดเดิมคือ MCP ปฏิเสธสิทธิ์และ dump ไม่มี component set Table สำหรับ full harness. ต้องตรวจผลบนไฟล์ Figma ที่รันจริงก่อนถือว่าจอพร้อมส่งมอบ.
