# มุม Dev — Component รายเฟรม

อ่านคู่กับ AC ฉบับอ่านง่าย รายการต่อไปนี้อ้าง component และ state ที่บรรยายใน AC รายเฟรมต้นฉบับ เป็นแนวทางพัฒนา/ข้อเสนอ ไม่เพิ่ม component ที่ยังไม่มีจอเป็นข้อกำหนด และไม่ยืนยันเรื่องที่ยังต้องตกลงแทนทีม

หลักฐาน behavior ที่อ่านจากโปรเจกต์ (ใช้เป็นหลักฐาน prototype แยกจาก AC/Sheet):
- FilterPanel + PlanFilter: `overhaul-next/src/components/ui/FilterPanel.tsx`, `overhaul-next/src/components/plans/PlanFilter.tsx` — Side panel/Background overlay ของ Component + Filter Side panel ของ UI Release#2 หน้า 5.1
- Modal/ConfirmDialog/useOverlay: `overhaul-next/src/components/ui/Modal.tsx` — Modal และ Bottom sheet ของ Component + การใช้ใน PlanForm, PoForm, StepProgress และ JobView
- SearchInput/Combobox/RowMenu/DualList/FileUpload/Button: `overhaul-next/src/components/ui/` — มีชื่อ component และหน้า UI Release#2 อ้างไว้ในหัวไฟล์
- ต้นทาง/ปลายทาง: `overhaul-next/src/app/plans/edit/page.tsx`, `overhaul-next/src/components/plans/PlanForm.tsx`, `overhaul-next/src/components/po/PoForm.tsx`, `overhaul-next/src/components/job/JobView.tsx`
- เทียบของเก่า: `app/src/components/FilterDrawer.tsx` + `app/src/app/overhaul/page.tsx` — ปุ่มล้างเคย apply ทันที ซึ่งต่างจาก PlanFilter/AC ฉบับอ่านง่าย

พบ component-overhaul snapshot แต่ไม่มี snapshot ชุด component/ui-release2 ที่เครื่องมือ figma-screens คาดไว้ จึงยืนยันพฤติกรรมจากโค้ดที่อ่านได้ ไม่อ้างว่าอ่าน interaction สดจาก Figma แล้ว จุดที่ต่าง AC หรือยังไม่มี component ถูกระบุไว้ในเฟรมที่เกี่ยวข้อง

## A.1

- ช่องค้นหา (SearchInput): คลิกในช่อง → เข้า focus แสดง cursor และพิมพ์ แก้ไข หรือลบคำค้นได้
- ช่องค้นหา (SearchInput): คลิกออกจากช่อง → blur แต่ข้อความในช่องยังอยู่ ไม่ล้างออกเอง
- ช่องค้นหา (SearchInput): ระหว่าง loading ให้แสดงคำค้นที่พิมพ์ไว้; หากเปลี่ยนคำค้น ให้ใช้ผลของคำล่าสุด ไม่แสดงผลจากคำค้นก่อนหน้าทับ
- ช่องค้นหา (SearchInput): หากเกิด error ให้เก็บคำค้นไว้และลองใหม่ได้; วิธีเริ่มค้นหาและ AutoComplete ยังต้องตกลง
- ปุ่ม “ตัวกรอง”: เปิดแผงตัวกรอง A.2; แต่ละคลิกเปิดครั้งเดียว ไม่เปิดแผงซ้อนจากการกดซ้ำ
- ปุ่ม “+ สร้างแผน Overhaul”: เปิด form สร้างแผน B.1; แสดงเฉพาะผู้มีสิทธิ์ และไม่เปิดหน้าใหม่ซ้อนจากการกดซ้ำ
- ตารางรายการแผน (DataTable): หัวคอลัมน์ที่เรียงได้ต้องเปลี่ยนทิศ sort และข้อมูลพร้อมกัน; ชื่อยาวตัดด้วย …; ป้ายสถานะ/ความคืบหน้าอ่านค่าจากรายการเดียวกัน
- ปุ่มเปลี่ยนหน้าใต้ตาราง (Pagination) และช่องเลือกจำนวนต่อหน้า: เปลี่ยนแล้วโหลดหน้าที่ถูกต้องโดยคงคำค้น/ตัวกรอง; ไม่คำนวณจำนวนทั้งหมดจากเพียงแถวในหน้าปัจจุบัน
- เมนู “…” ท้ายแถวรายการ (RowMenu): คลิกนอกเมนูปิดโดยไม่ทำ action; Esc ปิดและคืน focus ให้ปุ่มเมนูเดิม ลูกศรขึ้น/ลงเลื่อนรายการ และเมื่อเลือกรายการจะปิดเมนูก่อนนำทาง/เปิดกล่อง

## A.2

- แผง “ตัวกรอง” ด้านขวา (FilterPanel): เปิดแล้วแสดงค่าที่ใช้อยู่; ค่าใน แผงตัวกรอง เป็นฉบับร่าง ไม่เปลี่ยนตารางด้านหลังทันที
- ช่องเลือกปีงบ: เปิดแผงแล้วแสดงปีงบที่ใช้กรองรายการปัจจุบัน; เปลี่ยนปีงบได้โดยไม่เปลี่ยนช่วงงบหรือสถานะที่เลือกไว้
- checkbox ช่วงงบและสถานะ: เลือกได้หลายข้อในกลุ่มเดียว; คลิกซ้ำที่ข้อเดิมเพื่อยกเลิกข้อนั้น
- label ของ checkbox: คลิกข้อความข้าง checkbox เพื่อเลือกหรือยกเลิก checkbox ข้อนั้น เช่น คลิก “รอเลข PO” เพื่อเลือกหรือยกเลิกสถานะ “รอเลข PO”
- ปุ่ม “ตกลง”: ใช้ตัวกรองที่เลือกในแผงเพื่ออัปเดตรายการ แล้วปิดแผงกลับ A.1
- ปุ่ม “ยกเลิก”: ปิดแผงกลับ A.1 โดยรายการยังใช้ตัวกรองเดิม
- ปุ่ม ×: ปิดแผงกลับ A.1 โดยรายการยังใช้ตัวกรองเดิม
- ปุ่ม “ล้างตัวกรอง”: ล้างตัวเลือกในแผง โดยยังไม่เปลี่ยนรายการจนกด “ตกลง”
- แผง “ตัวกรอง” ด้านขวาของหน้ารายการแผน (FilterPanel / PlanFilter): คลิกพื้นหลังทึบ ปุ่ม × กด Esc หรือกด “ยกเลิก” → ปิด แผงตัวกรอง และกลับไปดูรายการ A.1 ที่อยู่ด้านหลัง ไม่เปลี่ยนหน้า ไม่ apply ค่าที่เพิ่งแก้; เปิดอีกครั้งเริ่มจากตัวกรองที่ใช้อยู่จริง
- คลิกภายในแผง/ช่องกรอง → แผงตัวกรอง ค้างอยู่ ไม่ปิดตาม event ของพื้นหลัง; ขณะเปิดหน้าเบื้องหลังเลื่อนไม่ได้ตาม ตัวควบคุมพื้นหลังทึบ (useOverlay)
- กด “ล้างตัวกรอง” เพื่อล้างตัวเลือกในแผง แล้วกด “ตกลง” เพื่ออัปเดตรายการ หากปิดแผงก่อนกด “ตกลง” รายการจะยังใช้ตัวกรองเดิม และเมื่อเปิดแผงอีกครั้ง ตัวเลือกจะกลับมาเป็นค่าเดิม
- จุดต่างในโค้ด: แผงตัวกรองในต้นแบบเก่า (FilterDrawer) ร่วมกับหน้ารายการแผนของต้นแบบเก่าล้างแล้ว apply ทันที แต่ ตัวกรองของหน้ารายการแผน (PlanFilter) ของ overhaul-next ล้างเฉพาะ draft ซึ่งตรงฉบับอ่านง่าย จึงใช้อย่างหลังเป็นฐาน behavior ไม่ผสมสองแบบ

## A.3

- ส่วนแสดงเมื่อไม่มีข้อมูล “ไม่พบแผน Overhaul”: ใช้เมื่อค้นสำเร็จแต่ไม่มีผล ไม่ใช้แทน loading หรือ error
- ช่องค้นหา (SearchInput): คลิกในช่อง → เข้า focus แสดงขอบสีม่วงและ cursor สามารถพิมพ์ แก้ไข หรือลบคำค้นได้
- ช่องค้นหา (SearchInput): คลิกออกจากช่อง → blur ขอบสีม่วงหาย แต่คำค้นยังอยู่
- ช่องค้นหา (SearchInput): ค้นหาแล้วไม่พบรายการ → แสดง Empty State “ไม่พบแผน Overhaul” โดยเก็บคำค้นและค่าตัวกรองเดิมไว้ เพื่อให้แก้ไขแล้วค้นหาใหม่ได้
- ปุ่ม “ตัวกรอง”: ยังแสดงเมื่อค้นหาไม่พบรายการ กดแล้วเปิดแผงตัวกรอง A.2
- ปุ่ม “+ สร้างแผน Overhaul”: ยังแสดงเฉพาะผู้มีสิทธิ์เมื่อค้นหาไม่พบรายการ กดแล้วเปิด form สร้างแผน B.1
- Pagination: ไม่แสดงปุ่มเปลี่ยนหน้าและตัวเลือกจำนวนรายการต่อหน้า เมื่อไม่มีผลค้นหา
- ปุ่ม “ล้างคำค้นและตัวกรอง”: ล้างทั้งคู่แล้วโหลดรายการใหม่; ไม่คงหน้าที่ไม่มีรายการหลังล้าง
- จากหน้ารายการ plans: ปุ่มล้างคำค้น/ตัวกรองทำงานในหน้าเดิม A.1 ไม่เปิด แผงตัวกรอง และไม่ไปหน้าสร้างแผน; คง focus ที่ช่องค้นหาเพื่อพิมพ์ใหม่

## A.4

- ส่วนแสดงเมื่อไม่มีข้อมูล “ยังไม่มีแผน Overhaul”: ใช้เมื่อยังไม่มีข้อมูล ไม่ปะปนกับค้นไม่พบของ A.3
- ปุ่ม “+ สร้างแผน Overhaul” กลางจอ: พาไป B.1 และตรวจสิทธิ์; ไม่สร้างช่องค้นหา/ตัวกรองหรือ pagination เพิ่มใน state นี้
- ปุ่มสร้างแผนเป็นลิงก์ไป form สร้าง B.1; ถ้าผู้ใช้กลับจาก form โดยยังไม่สร้างสำเร็จ ให้เห็น state ว่าง A.4 เดิม ไม่สร้างแผนจากการเปิด form

## B.1

- ช่องกรอกชื่อแผนและวงเงิน: เริ่มต้นว่าง; คลิกในช่อง → เข้า focus แสดง cursor และพิมพ์หรือแก้ไขค่าได้; คลิกออกจากช่อง → blur โดยเก็บค่าที่กรอกไว้ หากช่องบังคับยังว่าง ให้แสดง validation ตาม B.2
- ช่องเลือกจากรายการ ปีงบประมาณ: เริ่มยังไม่เลือก ไม่กำหนดปีเองแทนผู้ใช้
- ช่องแนบไฟล์ “หนังสืออนุมัติหลักการ”: รับ PDF, PNG และ JPG สูงสุด 10 ไฟล์ในช่องนี้; ขนาดไฟล์สูงสุดและการบังคับแนบยังต้องตกลง
- ช่องแนบไฟล์ “เอกสารอนุมัติงบ”: รับ PDF, PNG และ JPG สูงสุด 10 ไฟล์ในช่องนี้; ขนาดไฟล์สูงสุดและการบังคับแนบยังต้องตกลง
- ช่องแนบไฟล์ “เอกสารอื่น ๆ”: ไม่บังคับแนบ รับ PDF, PNG และ JPG สูงสุด 10 ไฟล์ในช่องนี้; ขนาดไฟล์สูงสุดยังต้องตกลง
- ปุ่ม “บันทึก”: เริ่ม disable และคำนวณสถานะจากฟิลด์ที่ยืนยันแล้วว่าบังคับ
- จาก หน้า form สร้าง/แก้ไขแผน (PlanForm): ปุ่มย้อนกลับไปหน้ารายการ ถ้ายังไม่แก้ค่าให้ออกได้ทันที; ถ้ามี draft เปิด “ยืนยันการออก” B.4 ก่อน ส่วน เส้นทางนำทางด้านบน เป็นลิงก์ตรงและยังไม่ผ่าน guard จึงต้องปรับ/เคาะให้ครอบคลุมก่อนอ้างว่ากันข้อมูลหายทุกทาง; หน้าใหม่ไม่มีปุ่ม “ยกเลิก” ท้าย form จึงใช้ปุ่มย้อนกลับเพื่อออกจากหน้านี้

## B.2

- ช่องกรอก ชื่อแผน/วงเงิน และ รายการตัวเลือก ปีงบ: blur แล้วแสดง error ใต้ช่องที่ผิด พร้อมขอบแดง; แก้ช่องใดถูกให้ล้างเฉพาะ error ช่องนั้น ข้อความผิดพลาดต้องระบุช่อง ไม่ใช้ toast แทน validation รายช่อง
- ช่องกรอก วงเงิน: ค่า 0 ไม่ผ่าน; ทศนิยม/การใส่ comma ยังต้องตกลง
- ปุ่ม “บันทึก”: คง disable เมื่อข้อมูลบังคับไม่ครบ; ไม่เพิ่ม error เอกสารเองเพราะเฟรมยังไม่มีข้อความนี้

## B.3

- ช่องกรอก ชื่อแผน/วงเงิน/เลขอ้างอิง และ รายการตัวเลือก ปีงบ: คงค่าที่กรอกครบ ไม่ reset เมื่อมีไฟล์เพิ่ม
- รายการไฟล์แนบ: แสดงชื่อ ขนาด progress และปุ่มลบแยกต่อไฟล์; ลบรายการที่เลือกเท่านั้น
- ปุ่ม “บันทึก”: enable เมื่อข้อมูลครบ และกันกดซ้ำระหว่างรอผลโดยยังคงค่า form

## B.4

- กล่องโต้ตอบกลางจอ (Modal) “ยืนยันการออก”: เปิดจากการออกจาก form ที่แก้แล้ว; คง form ไว้ด้านหลัง
- ปุ่ม “ปิด”: ปิดกล่องแล้วกลับ form สร้างแผน B.1/B.3 โดยไม่ล้างค่า
- ปุ่ม “ยืนยัน”: ทิ้งข้อมูลที่ยังไม่บันทึกแล้วกลับรายการแผน A.1 หรือหน้าว่าง A.4 ตามข้อมูลที่มี
- Breadcrumb/ทางออกจากหน้า: ต้องตกลง trigger ที่แท้จริง เพราะจอสร้างแผนไม่มีปุ่มย้อนกลับ/ยกเลิก
- จาก หน้า form สร้าง/แก้ไขแผน (PlanForm) + กล่อง “ยืนยันการออก” (ConfirmDialog): ปุ่ม “ปิด”, ×, Esc หรือคลิกพื้นหลัง → ปิดเฉพาะ กล่องโต้ตอบกลางจอ (Modal) แล้วกลับ B.1/B.3 พร้อมชื่อแผน ปีงบ วงเงิน และไฟล์ draft เดิม ไม่ออกจาก form
- กด “ยืนยัน” → ทิ้ง draft และไปหน้ารายการแผน A ผ่าน หน้าต้นทางที่กำหนดไว้; เส้นทางนำทางด้านบน ของ prototype ยังเป็นลิงก์ตรง ไม่ผ่านกล่องนี้ จึงต้องเพิ่ม guard ให้ตรง AC ก่อน

## B.5

- ข้อความแจ้งผลมุมขวาบน error: แสดงเมื่อบันทึกไม่สำเร็จ; ใช้ข้อความ error ตามที่ตกลง ไม่แจ้งสำเร็จซ้ำ
- ช่องกรอก, รายการตัวเลือก และไฟล์แนบ: เก็บค่าทั้งหมดไว้ให้แก้หรือส่งใหม่
- ปุ่ม “บันทึก”: ออกจากสถานะกำลังส่งหลังล้มเหลว และกด retry ได้โดยไม่สร้างแผนซ้ำ

## B.6

- ข้อความแจ้งผลมุมขวาบน สร้างแผนสำเร็จ: แสดงหลังบันทึกสำเร็จจริงและกลับหน้ารายการ
- ตารางรายการแผน (DataTable)และ ป้ายรายการที่เลือก: โหลดรายการใหม่ให้มีแผนที่สร้างพร้อมสถานะ “รอเลข PO”; ตำแหน่งแถวขึ้นกับ default sort ที่ตกลง
- ความคืบหน้าในแถวใหม่: แผนยังไม่มี PO แสดง “-” ไม่ใช้ยอดเก่าค้าง

## B.7

- ส่วนข้อมูลแผนและเอกสาร: แสดงข้อมูลของแผนที่เปิดจริง; ดาวน์โหลดไฟล์ตามรายการ ไม่ใช้ข้อมูลจากแถวก่อนหน้า
- ส่วน Purchase Order: แยกตารางกับ empty state ตามจำนวน PO จริง
- ปุ่ม “แก้ไขแผน”: เปิด form แก้ไขแผน C.2 เฉพาะผู้มีสิทธิ์
- ปุ่ม “ลบแผน”: เปิดกล่องยืนยันลบแผน D.2.2 เฉพาะผู้มีสิทธิ์
- ปุ่มสร้าง Purchase Order: เปิด form สร้าง PO E.2 เฉพาะผู้มีสิทธิ์; ความต่างระหว่าง B.7/E.1 ต้องตกลงก่อนใช้ component ชุดเดียวกัน

## C.1

- เมนู “…” ท้ายแถว: เปิดให้ตรงแผนที่กด ไม่สลับไปใช้ ID แถวอื่นหลัง sort/แบ่งหน้า
- รายการเมนู “แก้ไข”: พาไป C.2 พร้อมเลขแผนของแถวนั้น; ซ่อน action ที่ role ไม่มีสิทธิ์
- การปิดเมนู: ตาม เมนู “…” ท้ายแถวรายการ (RowMenu) คลิกนอกปิดเมนู และ Esc ปิดพร้อมคืน focus ให้ปุ่มเมนูเดิม ไม่ออกจากหน้ารายการ
- เมนู “…” ท้ายแถวรายการ (RowMenu): คลิกนอกเมนู/Esc → ปิดเมนูแล้วค้างหน้ารายการแผน ไม่เข้าสู่ form; กดแก้ไข → ปิดเมนูแล้วเปิด C.2 ของแถวนั้น

## C.2

- ช่องกรอก/รายการตัวเลือก ใน form แก้ไข: เติมค่าของแผนล่าสุด; แยกค่าที่โหลดมากับค่าที่ผู้ใช้เปลี่ยน
- รายการเอกสารเดิมและ upload: แยกไฟล์ที่เก็บแล้วออกจากไฟล์ใหม่ ไม่อัปโหลดไฟล์เดิมซ้ำ
- ปุ่ม “ยกเลิก”: เปิดกล่องยืนยันการออก C.3 เมื่อมีการแก้ไข; ถ้ายังไม่แก้ กลับหน้าต้นทาง
- ปุ่ม “บันทึก”: เปิดกล่องยืนยันการแก้ไขแผน C.4 เมื่อข้อมูลผ่านเงื่อนไข
- จาก หน้า form สร้าง/แก้ไขแผน (PlanForm) และหน้า plans/edit: “ยกเลิก” ถ้าไม่แก้ข้อมูล → กลับหน้าที่เข้ามา (จากรายการกลับรายการ; เข้าจากหน้ารายละเอียด กลับรายละเอียด B.7); ถ้าแก้แล้ว → เปิด C.3 ก่อน ไม่ทิ้ง draft ทันที
- กด “บันทึก” → validate; ถ้ามีการแก้ที่ผ่านเงื่อนไขเปิด C.4 และยังไม่บันทึกจริงจนกดยืนยัน

## C.3

- กล่องโต้ตอบกลางจอ (Modal) ยืนยันการออก: แสดงบน form แก้ไขโดยยังเก็บ draft
- ปุ่ม “ปิด”: ปิดกล่องแล้วกลับ form แก้ไข C.2 พร้อมค่าที่แก้ทั้งหมด
- ปุ่ม “ยืนยัน”: ทิ้งการแก้ไข แล้วกลับรายการแผน A.1 หรือรายละเอียดแผน B.7 ตามจุดที่เข้ามา
- จาก หน้า form สร้าง/แก้ไขแผน (PlanForm)/กล่อง “ยืนยันการออก” (ConfirmDialog): “ปิด”, ×, Esc, คลิกพื้นหลัง → ปิดเฉพาะกล่องและกลับ C.2 พร้อม draft; “ยืนยัน” → ทิ้ง draft แล้วกลับรายการหรือรายละเอียดแผนตามจุดที่เข้ามา

## C.4

- กล่องโต้ตอบกลางจอ (Modal) “ยืนยันการแก้ไข”: แสดงข้อความเตือนก่อนส่งบันทึกจริง
- ปุ่ม “ยกเลิก”: ปิดกล่องแล้วกลับ form แก้ไขแผน C.2 พร้อมข้อมูลเดิม
- ปุ่ม “ยืนยัน”: ส่งการแก้ไขเพียงครั้งเดียว แสดง pending ระหว่างรอ; สำเร็จแสดงผล C.5
- เมื่อยืนยันไม่สำเร็จ: อย่าล้าง ช่องกรอก/ไฟล์หรือเปลี่ยนข้อมูลบนจอเป็นสำเร็จ
- จาก กล่อง “ยืนยันการแก้ไขแผน” (ConfirmDialog) ของ หน้า form สร้าง/แก้ไขแผน (PlanForm): “ยกเลิก”, ×, Esc หรือคลิกพื้นหลัง → ปิดกล่องยืนยันและกลับ C.2 พร้อมค่าที่แก้ ไม่บันทึกและไม่กลับรายการ
- “ยืนยัน” → เริ่มบันทึก แล้วไปหน้าต้นทางเมื่อสำเร็จ; ปุ่มบนจอ (Button) ที่ loading ปิดการกดซ้ำ แต่ กล่องโต้ตอบกลางจอ (Modal) ปัจจุบันยังปิดด้วยพื้นหลัง/Esc ได้ระหว่างรอ จึงต้องตกลงว่าจะล็อกการปิดระหว่าง pending หรือไม่

## C.5

- ข้อความแจ้งผลมุมขวาบน บันทึกการแก้ไขสำเร็จ: แสดงจากผลบันทึก ไม่ใช่เพียงเพราะปิด กล่องโต้ตอบกลางจอ (Modal)
- ส่วนรายละเอียดแผน: โหลดค่าที่แก้ใหม่ รวมเอกสารและข้อมูลชื่อแผน; ไม่แสดง cache ก่อนแก้

## D.1.1

- เมนู “…” ในตารางแผน: จับแถว/ID ที่กำลังลบไว้ให้แน่นอน
- รายการ “ลบ”: เปิด D.2.1 โดยยังไม่ลบข้อมูลเมื่อเลือกเมนู; ตรวจสิทธิ์ของ action
- เมนู “…” ท้ายแถวรายการ (RowMenu): คลิกพื้นหลังนอกเมนู/Esc ก่อนเลือกลบ → แค่ปิดเมนู อยู่ A.1 และไม่ลบ; เลือกลบ → ปิดเมนูแล้วเปิด D.2.1

## D.1.2

- ปุ่ม “ลบแผน” หน้ารายละเอียด: อ้างแผนที่เปิดอยู่และเปิด D.2.2
- ข้อมูลรายละเอียดด้านหลัง: คงเดิมจนกดยืนยันใน กล่องโต้ตอบกลางจอ (Modal) ไม่ลบเมื่อเพียงเปิดกล่อง

## D.2.1

- กล่องโต้ตอบกลางจอ (Modal) “ยืนยันการลบแผน”: เปิดต่อจากเมนูแถวรายการ และคงแผนเป้าหมายแม้ตารางโหลดใหม่
- ปุ่ม “ยกเลิก”: ปิดกล่องแล้วกลับรายการแผน A.1 โดยไม่ลบ
- ปุ่ม “ยืนยัน” สีแดง: ลบแบบ Soft Delete ตาม Sheet และกันกดซ้ำ; สำเร็จกลับรายการแผนพร้อมผลลบ D.3
- จาก กล่อง “ยืนยันการลบแผน” (ConfirmDialog) ในหน้ารายการ plans: “ยกเลิก”, ×, Esc หรือคลิกพื้นหลัง → ปิด กล่องโต้ตอบกลางจอ (Modal) กลับ A.1 คงแถวแผนเดิม; คลิกในกล่องไม่ปิด และไม่ลบจนกด “ยืนยัน”

## D.2.2

- กล่องโต้ตอบกลางจอ (Modal) “ยืนยันการลบแผน”: เปิดต่อจากปุ่มในหน้ารายละเอียด โดยอ้างเลขแผนของหน้านั้น
- ปุ่ม “ยกเลิก”: ปิดกล่องแล้วกลับรายละเอียดแผน B.7 เดิม
- ปุ่ม “ยืนยัน” สีแดง: ลบแผนและกันกดซ้ำ; สำเร็จกลับรายการแผนพร้อมผลลบ D.3
- จาก กล่อง “ยืนยันการลบแผน” (ConfirmDialog) ใน หน้ารายละเอียดแผน (PlanDetail): “ยกเลิก”, ×, Esc หรือคลิกพื้นหลัง → ปิด กล่องโต้ตอบกลางจอ (Modal) กลับรายละเอียดแผนเดิม B.7 ไม่กลับรายการ; กดยืนยันลบสำเร็จจึงไป A

## D.3

- ข้อความแจ้งผลมุมขวาบน ลบแผนสำเร็จ: แสดงหลังผลยืนยันจาก server
- ตารางแผน/จำนวนรายการ: เอาแผนที่ลบออกแล้วโหลดจำนวนใหม่; ถ้าไม่เหลือข้อมูลให้แสดง empty state ที่ถูกต้อง
- ปุ่มเปลี่ยนหน้าใต้ตาราง (Pagination): ต้องตกลงหน้าที่แสดงต่อหากแถวที่ลบเป็นแถวสุดท้ายของหน้านั้น

## E.1

- ส่วนแสดงเมื่อไม่มีข้อมูล Purchase Order (0): แสดงเมื่อแผนนี้ยังไม่มี PO
- ปุ่ม “+ PO”: เปิด form สร้าง PO E.2
- ปุ่ม “+ เบิก”: ทำรายการในส่วนอะไหล่ ไม่เปิด form PO; ปลายทางของการเบิกยังต้องตกลง
- รายการเอกสารสองคอลัมน์: ดาวน์โหลดไฟล์ของประเภทที่กดและของแผนปัจจุบัน

## E.2

- ช่องกรอก ชื่อ PO: เริ่มว่าง; ช่องเลือกอู่และรถต้องเลือกจากรายการจริง ไม่ถือข้อความที่พิมพ์ว่าเลือกแล้ว
- ช่องแนบไฟล์ ใบสั่งจ้าง/เอกสารอื่น: แยกแต่ละประเภทและแสดงตัวนับ 0/10; รับ PDF และ JPG สูงสุด 10 ไฟล์ต่อช่อง โดยใบสั่งจ้างบังคับแนบ ส่วนเอกสารอื่นไม่บังคับแนบ
- ปุ่ม “บันทึก”: ใช้รูปแบบ validation ของ PO ตาม E.3 ไม่ยก disable ของหน้าสร้างแผนมาใช้เอง
- จาก หน้า form สร้าง/แก้ไข PO (PoForm): ปุ่มย้อนกลับใช้ หน้าต้นทางที่กำหนดไว้ กลับรายละเอียดแผน E.1; มี draft เปิด “ยืนยันการออก” ก่อน ปิดกล่องแล้วกลับ form เดิม ยืนยันแล้วทิ้ง draft ไปต้นทาง ส่วน เส้นทางนำทางด้านบน ยังเป็นลิงก์ตรงไม่ผ่าน guard ต้องแก้/เคาะให้ครอบคลุม; ไม่เพิ่มปุ่มยกเลิกท้ายหน้าสร้าง PO ที่ AC ไม่มี

## E.3

- ช่องกรอก ชื่อ Purchase Order: กดบันทึกแล้วว่างให้แสดง error ใต้ช่องนี้
- ช่องเลือกอู่และ upload ใบสั่งจ้าง: แสดง error แยกแต่ละส่วน และล้างเฉพาะ error ของส่วนที่แก้ถูก
- ปุ่ม “บันทึก”: ไม่ส่งข้อมูลเมื่อ validation ไม่ผ่าน; เงื่อนไขต้องเลือกรถอย่างน้อยหนึ่งคันยังต้องตกลง

## E.4

- ช่องพิมพ์ค้นหา อู่: พิมพ์แล้วค้นจาก vendor list; แยกข้อความค้นจากอู่ที่เลือกแล้ว
- ช่องเลือกจากรายการ ผลค้น: แต่ละแถวแสดงชื่ออู่และข้อมูลรองเบอร์/พื้นที่; เลือกได้อู่เดียว คลิกแล้วปิดรายการและแสดงชื่อที่เลือก ช่องพิมพ์ค้นและเลือกจากรายการ (Combobox) ในโปรเจกต์รองรับลูกศร/Enter เพื่อเลือกและ Esc เพื่อปิดแล้ว
- เมื่อเลือกอู่: เก็บ vendor_id พร้อมชื่อ/เบอร์/ที่อยู่ตาม Dev mapping; เปลี่ยนข้อความค้นแล้วต้องไม่คง ID ของอู่เดิมผิดรายการ
- Loading/ไม่พบอู่/error ของผลค้น: ต้องตกลงข้อความและจำนวนตัวอักษรเริ่มค้น ไม่เพิ่มค่า 3 ตัวอักษรเอง
- จาก ช่องพิมพ์ค้นและเลือกจากรายการ (Combobox): focus เปิดรายการ; blur/คลิกนอกช่องปิดรายการและคืนชื่อรายการที่เลือกไว้ ถ้าพิมพ์แต่ไม่เลือกจะไม่ถือว่ามีอู่ใหม่; ลบข้อความจนว่างล้างค่าที่เลือก
- ↑/↓ เลื่อนตัวเลือก, Enter เลือกและปิด, Esc ปิดรายการโดยไม่เปลี่ยนอู่; ปุ่มเลือกในรายการตัวเลือก ป้องกัน blur ก่อนเลือก เพื่อไม่ให้คลิกแล้วค่าหาย

## E.5

- ช่องพิมพ์ค้นหา รถ: แยกคำค้นจากรายการรถที่เลือกไว้ และไม่ให้ผลคำเก่ามาทับคำใหม่
- ช่องเลือกจากรายการ รถ: แสดงเครื่องหมายเลือกของคันที่อยู่ในรายการแล้ว; เลือกหลายคันได้โดยไม่เพิ่มคันเดิมซ้ำ
- ป้ายสถานะ/รายการที่เลือก ทะเบียนและปุ่ม ×: ลบเฉพาะคันนั้น และเอาเครื่องหมายเลือกในรายการตัวเลือก ออกพร้อมกัน
- รูปแบบเลือกแบบ ป้ายรายการที่เลือก กับรายการสองฝั่งใน Sheet/F.2 ยังขัดกัน จึงไม่สร้างตัวกรองที่ยังไม่มีใน mock เป็นข้อยืนยัน
- มุม Dev สำหรับ ป้ายรายการที่เลือก ยังยึด AC E.5: กด × เอารถออกแต่ form PO ยังค้าง ไม่ใช่ปิดทั้งหน้า; component รายการเลือกรถสองฝั่ง “รายการรถทั้งหมด”/“เลือกแล้ว” (DualList) ที่มีในโปรเจกต์เป็นสองฝั่ง จึงใช้แทน ป้ายรายการที่เลือก โดยไม่เคาะรูปแบบไม่ได้

## E.6

- ช่องกรอก ชื่อ PO/อู่ และ ป้ายรายการที่เลือก รถ: แสดงค่าที่เลือกครบให้สอดคล้องกับข้อมูลที่จะส่ง
- ช่องแนบไฟล์ ใบสั่งจ้าง: แสดงชื่อ ขนาด และตัวนับ 1/10 ตามจำนวนไฟล์จริง
- ปุ่ม “บันทึก”: ส่งชุดข้อมูลปัจจุบันครั้งเดียว และกันกดซ้ำระหว่างรอผล
- จาก ปุ่มบนจอ (Button): เมื่อส่งให้ใช้ loading เพื่อปิดการกดซ้ำทั้งเมาส์/คีย์บอร์ด; ไม่ใช้เพียงเปลี่ยนสี เพราะตัวปุ่มจะ disable จริงเมื่อ loading; หากออกจาก form ขณะมี draft ต้องผ่าน leave guard ของ หน้า form สร้าง/แก้ไข PO (PoForm)

## E.7

- ข้อความแจ้งผลมุมขวาบน “General Error”: อยู่บน form เดิมเมื่อส่งไม่สำเร็จ
- ช่องกรอก ชื่อ PO, อู่, ป้ายรายการที่เลือก รถ และไฟล์แนบ: คงค่าทั้งหมด ไม่ reset จากการ refetch ที่ล้มเหลว
- ปุ่ม “บันทึก”: กลับมากด retry ได้หลังพ้น pending
- ข้อความแจ้งผลมุมขวาบน error ไม่ใช่ กล่องโต้ตอบกลางจอ (Modal) จึงไม่สร้างพื้นหลังทึบหรือบังคับให้ปิดก่อนกรอกต่อ; กด × บน toast ปิดเฉพาะข้อความ form PO กับไฟล์เดิมยังอยู่

## E.8

- ข้อความแจ้งผลมุมขวาบน “ไม่พบแผน”: ผูกกับแผนที่ form อ้างอิงและไม่เปิดให้บันทึกลงแผนที่ลบแล้ว
- form PO ด้านหลัง: ต้องตกลงว่าจะค้างพร้อมปิดปุ่ม หรือพากลับรายการ ไม่ตัดสินใจนำทางเองจาก toast

## E.9

- ข้อความแจ้งผลมุมขวาบน สร้าง PO สำเร็จ: แสดงที่รายละเอียดแผนหลังบันทึก
- ตาราง PO และหัวส่วน Purchase Order: โหลดแถวใหม่พร้อมจำนวนรถ/ความคืบหน้า/ระยะสัญญาตามข้อมูลจริง
- ป้ายสถานะ/รายการที่เลือก สถานะแผนและจำนวนรถ: อัปเดตตามผลสร้าง PO ไม่คง 0 คันจากหน้าก่อน; ที่มาระยะสัญญายังต้องตกลง

## E.10

- ตารางรถ: แต่ละแถวแสดง ป้ายรายการที่เลือก และข้อมูลรองตามสถานะของรถคันนั้น; ไม่ใช้ข้อความสถานะร่วมกันทั้งตาราง
- ปุ่ม ›/หน้างาน: เปิดรถที่กดพร้อมแผนและ PO ถูกชุด
- ปุ่ม “แก้ไข”: เปิด form แก้ไข PO F.2 โดยตรวจสิทธิ์ก่อน
- ปุ่ม “ลบ PO”: เปิดกล่องยืนยันลบ PO G.1 โดยตรวจสิทธิ์ก่อน
- รายการเอกสาร: ตรวจสิทธิ์เข้าถึงไฟล์ ไม่อาศัยเพียงซ่อนปุ่มบนหน้า
- จาก หน้ารายละเอียด PO (PoDetail): กด “ลบ PO” เปิด G.1 บนหน้าเดิม; ยกเลิกกล่อง → กลับรายละเอียด PO นี้; กด “แก้ไข” → เปิด F.2 โดยจำว่ามาจากรายละเอียด PO เพื่อให้ยกเลิกกลับถูกหน้า

## F.1

- เมนู “…” ในตาราง PO: จับ PO ของแถวที่กด
- รายการ “แก้ไข”: เปิด F.2 พร้อมข้อมูล PO เป้าหมาย; role ที่ดูอย่างเดียวไม่มี action แก้ไข/ลบ
- เมนู “…” ท้ายแถวรายการ (RowMenu): คลิกนอก/Esc ปิดเมนูแล้วอยู่หน้ารายละเอียดแผน (PlanDetail); กดแก้ไข → เปิด F.2 โดยเก็บต้นทางเป็นหน้ารายละเอียดแผน (PlanDetail)

## F.2

- ช่องค้นหาเหนือรายการ (SearchInput)รถ: เปลี่ยนผลรายการฝั่งซ้าย โดยไม่ล้างรถฝั่ง “เลือกแล้ว”
- ช่องติ๊กเลือก รายแถว/เลือกทั้งหมด: เก็บสถานะติ๊กแยกสองฝั่ง; ต้องตกลงเลือกทั้งหมดเฉพาะผลค้นหรือทุกรายการ
- ปุ่ม “เพิ่ม”/“นำออก”: enable เมื่อฝั่งนั้นมีรายการติ๊ก ย้ายตาม ID และอัปเดตจำนวนทั้งสองฝั่ง ไม่ให้รถซ้ำ
- ช่องกรอก ชื่อ PO/อู่และ upload: เติมค่าที่บันทึกเดิม; “ยกเลิก”/“บันทึก” จัดการ draft และเปิดยืนยันตาม flow
- จาก หน้า form สร้าง/แก้ไข PO (PoForm): “ยกเลิก” ถ้าไม่มีการเปลี่ยนค่า → กลับต้นทาง (มาจากตาราง PO กลับรายละเอียดแผน; มาจากรายละเอียด PO กลับ PO เดิม); ถ้ามี draft → เปิดยืนยันการออก ไม่ทิ้งค่าทันที
- กล่องยืนยันการออก: “ปิด”/×/Esc/พื้นหลัง → กลับ F.2 พร้อม draft; “ยืนยัน” → ทิ้ง draft แล้วไปต้นทางที่จำไว้
- จาก รายการเลือกรถสองฝั่ง “รายการรถทั้งหมด”/“เลือกแล้ว” (DualList): ช่องติ๊กเลือก เลือกทั้งหมดเลือกเฉพาะรายการในกล่อง/ผลค้นที่แสดง; กดเพิ่ม/นำออกแล้วล้างการติ๊กของฝั่งที่ย้าย แต่คงรถที่เลือกและคำค้นของอีกฝั่ง

## F.3

- กล่องโต้ตอบกลางจอ (Modal) “ยืนยันการแก้ไข”: แสดงก่อนส่งการแก้ PO
- ปุ่ม “ยกเลิก”: ปิดกล่องแล้วกลับ form แก้ไข PO F.2 พร้อมค่าที่แก้
- ปุ่ม “ยืนยัน”: ส่งการแก้ไขเพียงครั้งเดียว; สำเร็จไปหน้ารายละเอียด PO F.4 และคงข้อมูลที่แก้หากผิดพลาด
- จาก กล่อง “ยืนยันการแก้ไข” (ConfirmDialog) ของ หน้า form สร้าง/แก้ไข PO (PoForm): “ยกเลิก”, ×, Esc หรือคลิกพื้นหลัง → ปิดเฉพาะกล่องแล้วกลับ F.2 พร้อมชื่อ PO อู่ รถ และไฟล์ที่แก้; “ยืนยัน” จึงส่งบันทึก
- ปลายทางหลังบันทึกใน prototype กลับตามต้นทาง แต่ AC ล่าสุดระบุไปหน้ารายละเอียด PO (PoDetail) F.4 จึงต้องยึด AC/เคาะจุดต่างก่อน ไม่สรุปว่าตาม component แล้วเส้นทางถูกเสมอ

## F.4

- ตารางรถในรายละเอียด PO: โหลดค่าหลังแก้และจำนวนในหัวรายการให้ตรงกัน
- ป้ายสถานะ/รายการที่เลือก สถานะรายคัน: รถใหม่เริ่มรอนัดหมายเข้าอู่ ส่วนรถเดิมคงสถานะเดิม ไม่ reset ทั้งตาราง
- ข้อความแจ้งผลมุมขวาบน สำเร็จ: ใช้ข้อความที่ Sheet ยืนยัน ไม่ยิงซ้ำจากการโหลดรายละเอียดใหม่

## G.1

- กล่องโต้ตอบกลางจอ (Modal) “ยืนยันการลบ”: จับ PO เป้าหมายจาก action ที่เปิดกล่องไว้
- ปุ่ม “ยกเลิก”: ปิดโดยไม่เปลี่ยนตาราง; “ยืนยัน” สีแดง: กันกดซ้ำและทำ Soft Delete
- ข้อความ กล่องโต้ตอบกลางจอ (Modal) ยังไม่มีเลข PO/จำนวนรถ การเพิ่มข้อความเหล่านี้ต้องตกลงก่อน ไม่เติมเป็นคำยืนยันจากจอ
- จาก กล่อง “ยืนยันการลบ” (ConfirmDialog) ใน หน้ารายละเอียดแผน (PlanDetail)/หน้ารายละเอียด PO (PoDetail): “ยกเลิก”, ×, Esc หรือคลิกพื้นหลัง → ปิด กล่องโต้ตอบกลางจอ (Modal) และกลับหน้าที่เปิดกล่อง (รายละเอียดแผนหรือรายละเอียด PO) โดย PO/รถยังอยู่; กดในเนื้อกล่องไม่ปิด
- กด “ยืนยัน” ลบสำเร็จ → ไปหน้ารายละเอียดแผน (PlanDetail) G.2; ไม่ใช้การปิดกล่องเป็นหลักฐานว่าลบสำเร็จ

## G.2

- ตาราง PO/หัวส่วนจำนวน: เอา PO ที่ลบออกและโหลดจำนวนใหม่
- ป้ายสถานะ/รายการที่เลือก สถานะแผน/จำนวนรถ: คำนวณใหม่หลังลบ โดยกรณีเหลือ PO ศูนย์แผนกลับรอเลข PO ตาม Sheet
- ข้อความแจ้งผลมุมขวาบน ลบ PO สำเร็จ: แสดงครั้งเดียวบนหน้ารายละเอียดแผน (PlanDetail)

## H.1

- ช่องเลือกช่วงวันที่ (DateRangeInput) ช่วงวันนำรถเข้า: เริ่มว่าง ไม่ใส่วันนัดเอง
- ช่องเลือกผู้ประสานงาน: เริ่มยังไม่เลือก; ข้อมูลอู่/เบอร์/ที่อยู่เป็นค่าดูอย่างเดียว
- ปุ่ม “ส่งนัดหมาย”: เริ่ม disable จนข้อมูลครบ; ส่งสำเร็จแสดงสถานะรอหน่วยงานตอบรับ H.4.2
- ปุ่ม “ย้อนกลับ”: กลับรายละเอียด PO E.10 โดยไม่ส่งนัด; ถ้ามีข้อมูลที่ยังไม่บันทึกต้องยืนยันการออกก่อน
- จาก หน้าหน้างานรถรายคัน (JobView): “ย้อนกลับ” → รายละเอียด PO E.10; ถ้ามี draft ที่หน้าแจ้ง dirty เปิด “ยืนยันการออก” ก่อน ปิดกล่องแล้วอยู่ขั้นนัดเดิม ยืนยันแล้วจึงกลับ PO

## H.2

- ช่องเลือกช่วงวันที่ (DateRangeInput) และช่องเลือกผู้ประสานงาน: เปิดแล้วปิดโดยยังไม่เลือกให้ขึ้นขอบแดงและ error ของช่องนั้น
- ปุ่ม “Clear” ในปฏิทิน: ล้างช่วงวันแล้วคำนวณ validation/ปุ่มส่งใหม่ ไม่คงวันเดิมในข้อมูลที่จะส่ง
- จาก ช่องเลือกช่วงวันที่ (DateRangeInput): คลิกนอกช่องหรือกด Esc → ปิดเฉพาะแผงปฏิทิน ไม่ออกจากหน้างาน; การแสดง validation ตอน blur ยังเป็นหน้าที่ของ form ไม่ใช่แผงปฏิทินทำให้เอง

## H.3

- ช่องเลือกช่วงวันที่ (DateRangeInput) สองเดือน: เก็บช่วงวันที่กำลังเลือกแยกจากค่าที่ Apply; Cancel ไม่เปลี่ยนค่าที่แสดงใน form
- ช่องพิมพ์ค้นและรายการตัวเลือก ผู้ประสานงาน: เลือกชื่อจริงจากรายการสองบรรทัดแล้วเติมเบอร์ของคนนั้น; แก้คำค้นต้องไม่คงผู้ประสานงานผิดคน
- ปุ่ม “ส่งนัดหมาย”: enable เมื่อเลือกข้อมูลครบ; รูปแบบปฏิทินไทย/พ.ศ. ต้องตรงค่าที่แสดงและข้อสรุปทีม
- จาก ช่องเลือกช่วงวันที่ (DateRangeInput) ปัจจุบัน: คลิกนอก/Esc ปิดแผง และการเลือกวันแก้ค่า form ทันที ไม่มีปุ่ม Apply/Cancel; ต่างจาก AC ที่มี draft และ Apply/Cancel จึงต้องเคาะ/ปรับ component ไม่อ้างว่ารองรับแล้ว
- จาก ช่องพิมพ์ค้นและเลือกจากรายการ (Combobox) ผู้ประสานงาน: blur ปิดรายการคืนชื่อที่เลือกไว้, Esc ปิดไม่เลือกใหม่, Enter เลือกแถวที่ไฮไลต์; ไม่ออกจากหน้า form เพียงเพราะปิด รายการตัวเลือก

## H.4.1

- ข้อความแจ้งผลมุมขวาบน นัดหมายไม่สำเร็จ: คงสถานะก่อนส่ง ไม่เลื่อน stepper
- ช่องเลือกช่วงวันที่ (DateRangeInput)/ผู้ประสานงาน: คงค่าที่เลือกไว้ให้ส่งใหม่
- ปุ่ม “ส่งนัดหมาย”: พ้น pending แล้ว retry ได้ ไม่สร้างนัดซ้ำจากการกดค้าง

## H.4.2

- ป้ายสถานะ/รายการที่เลือก สถานะและข้อความ “รอตอบกลับจากหน่วยงาน”: แสดงผลนัดที่ส่งสำเร็จ ไม่เปลี่ยนเป็นตอบรับเอง
- ปุ่ม “แก้ไขนัดหมาย”: เปิด H.4.3 พร้อมนัดปัจจุบัน และตรวจว่ายังแก้ได้เมื่อกด
- ข้อความแจ้งผลมุมขวาบน สำเร็จ: แสดงหลังส่งสำเร็จครั้งเดียว; วิธีแสดงผลเมื่อหน่วยงานตอบภายหลังยังต้องตกลง

## H.4.3

- ช่องเลือกช่วงวันที่ (DateRangeInput)/ช่องผู้ประสานงาน: เติมข้อมูลนัดเดิมและเปิดแก้เป็น draft
- ปุ่มส่งนัดใหม่: ตรวจสิทธิ์และสถานะตอบรับล่าสุดก่อนส่ง พร้อมกันกดซ้ำ
- ป้ายสถานะ/รายการที่เลือก สถานะ: ใช้ผลนัดล่าสุดหลังส่งใหม่ ไม่คงป้ายปฏิเสธหรือค่าจาก draft
- ออกจากการแก้นัดด้วยปุ่มย้อนกลับ → ขอไปรายละเอียด PO ผ่าน leave guard ของ หน้าหน้างานรถรายคัน (JobView); ถ้ามี draft ปิดกล่องยืนยันการออกจะกลับนัดที่กำลังแก้ ไม่ใช่ส่งนัดใหม่
- ปิดเฉพาะ รายการตัวเลือก ผู้ประสานงาน/ปฏิทินด้วยคลิกนอก ไม่ถือเป็นการยกเลิกนัดที่เคยส่ง

## H.4.4

- กล่องเหตุผลการปฏิเสธ: แสดงหมายเหตุของนัดที่ถูกปฏิเสธแบบอ่านอย่างเดียว
- ช่องเลือกช่วงวันที่ (DateRangeInput)/ผู้ประสานงาน: เติมค่าครั้งก่อนให้แก้ใหม่โดยไม่ทำเหตุผลปฏิเสธเดิมหายระหว่างกรอก
- ปุ่มส่งนัดใหม่: ส่งค่าที่แก้ และอัปเดตกล่องสถานะตามผล server
- กด “ย้อนกลับ” ออกจาก form ที่แก้นัดหลังถูกปฏิเสธ ใช้ leave guard แล้วกลับรายละเอียด PO; การปิดกล่องยืนยันการออกคงเหตุผลปฏิเสธและ draft ไว้ ไม่ลบประวัตินัด

## H.5

- ข้อมูลนัดที่ผ่านขั้นแล้ว: แสดงวัน/ผู้ประสานงานเป็นอ่านอย่างเดียว ไม่เปิด picker หรือ รายการตัวเลือก ให้แก้
- ปุ่มส่ง/แก้ไขนัด: ไม่แสดงใน state นี้; stepper และ ป้ายรายการที่เลือก ต้องตรงนัดที่ตอบรับแล้ว
- จาก หน้าหน้างานรถรายคัน (JobView): “ย้อนกลับ” ของหน้างานหมายถึงไปรายละเอียด PO ไม่ใช่ถอยสถานะจากขั้นตรวจรับกลับเป็นรอนัดเข้าอู่; การคลิกดูขั้นก่อนหน้าไม่แก้สถานะที่บันทึกแล้ว

## I.1

- ตารางรายการตรวจสอบ 13 ข้อ: radio มี/ไม่มีเลือกได้หนึ่งค่า ส่วน ช่องติ๊กเลือก ชำรุด/ผิดรุ่นเก็บแยก; note เป็น ช่องกรอก ของแต่ละแถว

- ตัวเลือกที่เลือกได้หนึ่งค่า/ช่องติ๊กเลือก และ ช่องกรอก หมายเหตุใน checklist: รักษาค่าต่อแถว ไม่ reset เมื่อลงชื่อ
- ช่องเลือกจากรายการ ผู้ส่งมอบ/ผู้รับมอบ: เลือกแล้วแสดงชื่อ แต่ยังไม่ถือว่าเซ็นแล้ว
- ปุ่ม “เซ็นลงนาม” สองฝ่าย: เปิด กล่องโต้ตอบกลางจอ (Modal) ของฝ่ายที่กด; “ยืนยันรับรถ” ยัง disable เพราะยังไม่มีลายเซ็น

## I.3

- กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) “เซ็นลงนาม”: แสดงชื่อและบทบาทของฝ่ายที่กด ไม่หยิบชื่ออีกฝ่าย
- พื้นที่วาดลายเซ็น: เริ่มว่าง รองรับการลากวาดด้วยเมาส์/สัมผัสตามอุปกรณ์ที่ใช้; วาดอยู่ต้องไม่ลากทั้ง กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) หรือเลื่อนหน้าพื้นหลังไปพร้อมกัน
- ปุ่ม “บันทึก”: disable เมื่อพื้นที่ว่าง; “ปิด”/× ปิดโดยไม่บันทึกลายเซ็น draft
- ข้อเสนออ้าง กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้): “ปิด”/×/คลิกพื้นหลัง/Esc ปิดเฉพาะกล่องลายเซ็นแล้วกลับ I.2 ฝ่ายเดิม โดยไม่บันทึกภาพ draft; คลิก/วาดในกล่องต้องไม่ปิดตามพื้นหลัง
- ข้อจำกัดที่พบ: หน้าตรวจรับรถ (StepReceive) ใน prototype ลงชื่อจากรายชื่อ ยังไม่มี กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) วาดลายเซ็นตาม I.3 จึงเป็นพฤติกรรมที่จะนำจาก กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) มาใช้ ไม่ใช่ยืนยันว่า signature component ทำไว้ครบแล้ว

## I.4

- พื้นที่วาดลายเซ็น: เมื่อมีเส้นวาดให้เปิดปุ่มบันทึก ไม่ถือการแตะพื้นที่ว่างว่าได้เซ็นแล้ว
- ปุ่ม “บันทึก”: เก็บภาพ ผู้เซ็น เวลา และฝ่ายที่ถูกต้อง แล้วปิด กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้)
- ปุ่ม “ปิด”: ทิ้งภาพที่ยังไม่ได้บันทึก ไม่เปลี่ยนสถานะฝ่ายนั้นเป็นเซ็นแล้ว
- ข้อเสนอใช้ กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) สำหรับลายเซ็น: “ปิด”/×/พื้นหลัง/Esc ทิ้งเฉพาะภาพที่ยังไม่บันทึกและกลับ checklist I.2/I.5; “บันทึก” สำเร็จแล้วจึงเปลี่ยนสถานะฝ่ายนั้น; signature canvas ยังไม่พบใน prototype

## I.5

- ข้อความ “เซ็นลงนามแล้ว” และปุ่ม “แก้ไขลงนาม”: แสดงแยกสองฝ่าย เปิด กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) ฝ่ายที่เลือก
- ปุ่ม “ยืนยันรับรถ”: enable เมื่อครบเงื่อนไขที่ตกลงแล้ว; pending กันกดซ้ำ
- แถบขั้นตอน 6 ขั้น (Stepper)/ป้ายรายการที่เลือก: ไปกำลังซ่อมหลังยืนยันสำเร็จจริง; การเปลี่ยนชื่อแล้วล้างลายเซ็นต้องตกลงก่อน
- ปุ่ม “แก้ไขลงนาม” เปิดกล่องของฝ่ายนั้น; ปิดกล่องโดยไม่บันทึกให้กลับ I.5 และเก็บลายเซ็นที่เคยบันทึกไว้ ไม่ใช้ภาพ draft แทนหลักฐานเดิม (แนวทางจาก กล่อง “เซ็นลงนาม” (Modal — แนวทางนำไปใช้) ต้องนำไปทำใน signature component)

## J.1

- ส่วนแสดงเมื่อไม่มีข้อมูล ความคืบหน้า: แสดงเมื่อยังไม่มีรายการ ไม่แสดงตารางเก่าค้าง
- ปุ่ม “+ ความคืบหน้า”: เปิดกล่องเพิ่มความคืบหน้า J.2
- ปุ่ม “ซ่อมสำเร็จ”: disable ขณะยังไม่มีรายการ จึงยังไม่เปลี่ยนหน้าหรือขั้นตอน

## J.2

- ช่องกรอกข้อความหลายบรรทัด (TextArea) รายละเอียดการติดตาม: กรอกข้อความหลายบรรทัดและตรวจค่าว่างตามข้อความ error ที่ตกลง
- ช่องกรอก หมายเหตุ: เป็น optional ไม่ใช้เป็นเงื่อนไขบังคับบันทึก
- ปุ่มบันทึก/ปิด กล่องกรอกข้อมูลกลางจอ: กันกดซ้ำตอนส่ง และเก็บค่าที่กรอกเมื่อส่งไม่สำเร็จ; ไม่เพิ่ม date/time ช่องกรอก ที่จอไม่มี
- จาก กล่อง “เพิ่มความคืบหน้า” (Modal) + หน้าติดตามความคืบหน้า (StepProgress): “ยกเลิก”, ×, คลิกพื้นหลังหรือ Esc → ปิด กล่องกรอกข้อมูลกลางจอ แล้วกลับ J.1/J.3 ที่อยู่ด้านหลัง โดยไม่บันทึก textarea; คลิกภายใน กล่องกรอกข้อมูลกลางจอ ไม่ปิด; บันทึกสำเร็จจึงปิดและโหลดแถวใหม่
- ข้อแตกต่างของ prototype: หน้าติดตามความคืบหน้า (StepProgress) ยังมีวันที่/เวลา แต่ AC ปัจจุบันไม่มี จึงไม่นำช่องนี้มาเพิ่มใน AC; ถ้าต้องการถามก่อนทิ้งข้อความที่แก้ใน กล่องกรอกข้อมูลกลางจอ ต้องเพิ่ม guard เพราะ กล่อง “เพิ่มความคืบหน้า” (Modal) ปัจจุบันปิดทันที

## J.3

- ตารางความคืบหน้า: เพิ่มแถวที่ server บันทึกแล้ว พร้อมวันที่ รายละเอียด หมายเหตุ
- ไอคอนแก้ไข/ลบในแถว: จับรายการของแถวนั้นให้ถูกต้อง
- ปุ่ม “ซ่อมสำเร็จ”: เปิดตามจำนวนรายการที่ใช้ได้จริง ไม่ใช้แค่แถว draft ใน กล่องกรอกข้อมูลกลางจอ

## K.1

- ไอคอนดินสอในตารางความคืบหน้า: เปิด กล่องกรอกข้อมูลกลางจอ ของรายการที่กด พร้อมค่าปัจจุบัน
- รายการแถวอื่น: ไม่ถูกแก้หรือเปิด กล่องกรอกข้อมูลกลางจอ ซ้ำเมื่อโหลดตารางใหม่
- จาก ไอคอนดินสอท้ายแถวความคืบหน้า: เปิดแก้ไขต้องจำ ID รายการ; กดนอกเมนู/Esc ก่อนเลือกแก้ไข → แค่ปิดเมนู ไม่เปลี่ยนข้อมูลหรือเปิด กล่องกรอกข้อมูลกลางจอ

## K.2

- ช่องกรอกข้อความหลายบรรทัด (TextArea) รายละเอียดและ ช่องกรอก หมายเหตุใน กล่องกรอกข้อมูลกลางจอ แก้ไข: เติมค่าเดิม แล้วเก็บ draft แยกจากแถวที่บันทึกแล้ว
- ปุ่มบันทึก: ส่ง ID รายการเดิม ไม่เพิ่มเป็นแถวใหม่; ปิดโดยไม่บันทึกต้องไม่เปลี่ยนตาราง
- จาก กล่อง “แก้ไขความคืบหน้า” (Modal) + หน้าติดตามความคืบหน้า (StepProgress): “ยกเลิก”, ×, พื้นหลังทึบ/Esc → ปิด กล่องกรอกข้อมูลกลางจอ แล้วกลับตารางความคืบหน้า K.1 โดยแถวเดิมยังเป็นค่าก่อนแก้; “บันทึก” สำเร็จจึงปรับแถวเดิม ไม่สร้างแถวใหม่

## K.3

- ตารางความคืบหน้า: เปลี่ยนเฉพาะรายการที่บันทึกแก้ ไม่เพิ่มแถวซ้ำ
- ข้อความแจ้งผลมุมขวาบน แก้ไขสำเร็จ: แสดงหลัง server สำเร็จ; ต้องตกลงวันที่ในแถวว่าจะคงเวลาสร้างหรือเปลี่ยนเป็นเวลาแก้ไข

## L.1

- icon ถังขยะในตาราง: ผูก ID ของรายการที่จะลบก่อนเปิด L.2
- เงื่อนไขลบ: ตรวจจำนวนรายการตามกติกาที่ห้ามลบจนเหลือศูนย์ ไม่เปิด action ให้ทำเกินเงื่อนไข

## L.2

- กล่องโต้ตอบกลางจอ (Modal) ยืนยันลบความคืบหน้า: คงรายการเป้าหมายไว้แม้ตารางเปลี่ยนระหว่างเปิด
- ปุ่มยกเลิก: ปิดโดยไม่ลบ; ยืนยัน: กันส่งซ้ำและตรวจจำนวนรายการล่าสุดอีกครั้ง
- จาก กล่องยืนยันลบความคืบหน้า (ConfirmDialog) + หน้าติดตามความคืบหน้า (StepProgress): “ยกเลิก”, ×, คลิกพื้นหลัง/Esc → ปิดกล่องแล้วกลับตาราง L.1 พร้อมรายการครบเดิม; กด “ยืนยัน” จึงลบรายการเป้าหมาย; คลิกในกล่องไม่ปิด

## L.3

- ตารางความคืบหน้า: เอาเฉพาะแถวที่ลบออกหลังสำเร็จ และคงรายการที่เหลือ
- ข้อความแจ้งผลมุมขวาบน ลบสำเร็จ/ปุ่มซ่อมสำเร็จ: อิงผลลบจริงกับจำนวนรายการล่าสุด ไม่แสดงความสำเร็จก่อนผลบันทึก

## M.1

- ช่องแนบไฟล์ “เอกสาร Safety Inspection”: รับ PDF, PNG, JPG สูงสุด 10 ไฟล์; แยกเลือกไฟล์กับอัปโหลดสำเร็จ ไม่รับไฟล์ผิดชนิดหรือเกินจำนวน หากไฟล์ใดอัปโหลดไม่สำเร็จให้แสดงสถานะของไฟล์นั้นโดยไม่ลบไฟล์อื่น ขนาดสูงสุดและข้อความ error ยังต้องตกลง
- ปุ่ม “ยืนยันการตรวจสภาพ”: เริ่ม disable เพราะยังไม่มีไฟล์ที่ใช้ได้
- แถบขั้นตอน 6 ขั้น (Stepper) ขั้น 04: ไม่เลื่อนไปขั้นนัดรับรถเพียงเพราะเลือกไฟล์
- ปุ่ม “ย้อนกลับ”: กลับหน้ารายละเอียด PO (E.10); หากเลือกไฟล์ไว้แต่ยังไม่บันทึก ต้องแสดงกล่องยืนยันการออกก่อน โดยให้หน้าตรวจ Safety เป็นผู้ตรวจว่ามีข้อมูลที่ยังไม่บันทึกและเปิดกล่องยืนยัน ส่วน FileUpload ทำหน้าที่เลือกและแสดงไฟล์เท่านั้น
- จาก ช่องแนบไฟล์และรายการไฟล์ (FileUpload): เลือกไฟล์แล้วกด Cancel ในหน้าต่างเลือกไฟล์ของเครื่อง → รายการเดิมไม่เปลี่ยน; ตอนนี้โค้ดตรวจ PDF/JPG และไม่อัปโหลดจริง จึงต้องเพิ่มการรับ PNG และสถานะอัปโหลดจริงให้ครบก่อนใช้จริง

## M.2

- รายการไฟล์แนบ: แสดงชื่อ ขนาด progress และปุ่มลบรายไฟล์; ลบแล้วคำนวณจำนวนไฟล์ที่พร้อมใหม่
- ปุ่ม “ยืนยันการตรวจสภาพ”: enable จากไฟล์ที่อัปโหลดสำเร็จ และกันกดซ้ำระหว่างยืนยัน
- แถบขั้นตอน 6 ขั้น (Stepper)/ป้ายรายการที่เลือก: ไปขั้นนัดรับรถหลังยืนยันสำเร็จเท่านั้น; error ต้องคงไฟล์ไว้
- จาก ช่องแนบไฟล์และรายการไฟล์ (FileUpload): กดไอคอนลบลบเฉพาะไฟล์นั้น หน้าตรวจ Safety ยังอยู่; กดชื่อไฟล์/ดาวน์โหลดใน prototype เป็นข้อความจำลอง ไม่ได้มี viewer จริงที่ยืนยันการปิด/ย้อนกลับได้
- กด “ย้อนกลับ” ไป PO ผ่าน guard หากมีการเปลี่ยนไฟล์; กด × ปิด toast สำเร็จ/ผิดพลาดไม่เปลี่ยนรายการไฟล์และไม่เปลี่ยนขั้นเอง

## N.1

- ช่องเลือกช่วงวันที่ (DateRangeInput) นัดรับรถและช่องเลือกผู้ประสานงาน: เริ่มว่าง; ข้อมูลอู่เป็นอ่านอย่างเดียว

- จาก หน้าหน้างานรถรายคัน (JobView): “ย้อนกลับ” → รายละเอียด PO เดิม; หากมี draft นัดรับรถให้เปิดยืนยันการออกก่อน ไม่ถอยสถานะไปเป็นนัดเข้าอู่

## N.2

- ช่องเลือกช่วงวันที่ (DateRangeInput)/ช่องผู้ประสานงาน: blur โดยไม่เลือกแสดง error ของช่องนั้น; แก้ถูกแล้วหายเฉพาะช่อง
- Label/error ช่วงวัน: ต้นฉบับยังใช้คำขาเข้า ต้องตกลงคำ “ช่วงวันนัดรับรถ” ก่อนใช้จริง
- จาก ช่องเลือกช่วงวันที่ (DateRangeInput): คลิกนอกปฏิทิน/Esc ปิดเฉพาะแผง ยังอยู่หน้าขั้นนัดรับรถ; label/error ต้องใช้ของขากลับตามข้อสรุป ไม่ยกข้อความขาเข้ามาเพราะ reuse component

## N.3

- ช่องเลือกจากรายการ ผู้ประสานงาน: เลือกชื่อจริงแล้วเติมเบอร์ให้ตรงคน
- ปุ่ม “ส่งนัดหมาย”: enable จากข้อมูลที่เลือกครบ ไม่ใช้เพียงข้อความที่พิมพ์ในช่องชื่อ
- ช่องเลือกช่วงวันที่ (DateRangeInput) ในโค้ดยังไม่มี Apply/Cancel และแก้ค่าทันทีเมื่อเลือก ต่างจาก AC นัดรับรถ จึงต้องเพิ่ม draft หากจะใช้รูปแบบ Apply/Cancel; คลิกนอก/Esc ปิดแผงไม่ใช่ออกจากหน้างาน

## N.4.1

- ข้อความแจ้งผลมุมขวาบน นัดรับรถไม่สำเร็จ: แสดงบน form เดิมและไม่เลื่อน stepper
- ช่องเลือกช่วงวันที่ (DateRangeInput)/ผู้ประสานงาน: คงค่าที่เลือก; ปุ่มส่งพ้น pending แล้วให้ลองใหม่ได้

## N.4.2

- ป้ายสถานะ/รายการที่เลือก และข้อความรอตอบกลับ: แสดง “รอหน่วยงานตอบรับนัดหมายรับรถ” หลังส่งสำเร็จ
- ปุ่ม “แก้ไขนัดหมาย”: เปิดค่าปัจจุบันที่ N.4.3; ต้องตรวจว่ายังไม่มีคำตอบใหม่ก่อนให้แก้
- ข้อความแจ้งผลมุมขวาบน สำเร็จ: ส่งเพียงครั้งเดียวจาก action ไม่ยิงซ้ำเมื่อ refresh หน้า

## N.4.3

- ช่องเลือกช่วงวันที่ (DateRangeInput)/ผู้ประสานงาน: เติมนัดรับรถครั้งก่อนให้แก้ได้ โดยแยก draft
- ปุ่มส่งนัดใหม่: ตรวจสถานะล่าสุดก่อนส่ง กันซ้ำ และแสดงสถานะรอตอบรับจากผลใหม่
- ป้ายสถานะ/รายการที่เลือก ปฏิเสธใน mock: เป็นจุดขัดกันที่ต้องตกลง ไม่ hardcode ตามภาพจนสถานะผิด
- “ย้อนกลับ” ขณะแก้นัดรับรถ → ขอไป PO ผ่าน leave guard; ปิดกล่องยืนยัน → กลับ draft ใน N.4.3, ยืนยัน → ทิ้ง draft ไป PO โดยไม่ยกเลิกนัดที่บันทึกไว้

## N.4.4

- กล่อง “เหตุผลการปฏิเสธ”: แสดงหมายเหตุของนัดรับรถครั้งที่ถูกปฏิเสธ
- ช่องเลือกช่วงวันที่ (DateRangeInput)/ผู้ประสานงานและปุ่มส่งใหม่: คงค่าเดิมให้ปรับแล้วส่ง โดยไม่เปลี่ยนไปใช้ข้อมูลนัดเข้าอู่
- ปิด รายการตัวเลือก/ปฏิทินไม่ล้างเหตุผลปฏิเสธ; กดย้อนกลับใช้ guard แล้วไป PO ไม่ใช่ลบนัดรับรถที่ถูกปฏิเสธ

## N.5

- ข้อมูลนัดรับรถที่ตอบรับแล้ว: แสดงเป็นอ่านอย่างเดียว ไม่มีการเปิด picker/รายการตัวเลือก เพื่อแก้
- แถบขั้นตอน 6 ขั้น (Stepper)/ป้ายรายการที่เลือก และปุ่ม: ขั้น 05 ผ่านแล้ว สถานะรอปิดงาน ไม่แสดงปุ่มส่ง/แก้ไขนัด
- จาก หน้าหน้างานรถรายคัน (JobView): ปุ่มย้อนกลับเปิดรายละเอียด PO; การกลับไปดูขั้นก่อนหน้าเป็นการเปลี่ยนมุมมองเท่านั้น ไม่ถอยขั้นตอน/ยกเลิกการตอบรับนัดที่บันทึกแล้ว

## O.1

- ช่องกรอก ชื่ออะไหล่/จำนวน และ รายการตัวเลือก หน่วย: แยกค่าต่อแถว ชื่อว่างและจำนวนไม่ถูกต้องต้องไม่กลายเป็นรายการพร้อมปิดงาน; หน่วยต้องอ้างค่าที่เลือก ไม่ตีความหน่วยเป็นจำนวน ส่วนทศนิยมและข้อความ error ยังต้องตกลง
- ปุ่ม “นำเข้าไฟล์”: เปิดเลือกไฟล์ แต่ชนิด/template/การต่อท้ายหรือแทนที่ยังต้องตกลง
- ส่วนแสดงเมื่อไม่มีข้อมูล และปุ่ม “ปิดงาน”: ต้องมีอย่างน้อยหนึ่งรายการตามกติกา; วิธีเพิ่มแถว/Enter ยังไม่มีข้อสรุป
- ปุ่ม “นำเข้าไฟล์” เปิด file picker; ถ้ากด Cancel ที่หน้าต่างของเครื่องให้กลับ O.1 พร้อมรายการอะไหล่เดิม ไม่เปิดกล่องยืนยันออกจากหน้าแทน
- “ย้อนกลับ” → PO ผ่าน leave guard เมื่อมีรายการที่ยังไม่บันทึก; เส้นทางนี้เป็นของ หน้าหน้างานรถรายคัน (JobView) ส่วน file import ของอะไหล่ยังไม่มี component ที่ยืนยัน behavior template/rollback ได้

## O.2

- ตารางอะไหล่และไอคอนลบ: ลบเฉพาะรายการนั้น แล้วปรับจำนวนรายการที่ใช้ปิดงาน
- แถว ช่องกรอก ชื่อ/จำนวน/รายการตัวเลือก หน่วย: คงไว้สำหรับกรอกเพิ่ม แต่ไม่สมมติว่ารายการซ้ำต้องรวมเอง
- ปุ่ม “ปิดงาน”: enable เมื่อมีรายการถูกต้อง กันส่งซ้ำ และตรวจรายการล่าสุดก่อนบันทึก
- กดไอคอนลบแถวเป็นการแก้ draft ในหน้าปิดงาน ไม่ใช่นำทางออก; ปุ่มย้อนกลับไป PO ต้องพิจารณา dirty guard เพื่อไม่ทิ้งรายการที่เพิ่มโดยไม่ตั้งใจ; การคง draft หลังออกยังต้องตกลง

## O.3

- ตารางอะไหล่: แสดงรายการที่บันทึกจริงเป็นอ่านอย่างเดียว ไม่มีแถว ช่องกรอก หรือไอคอนลบ
- ปุ่มนำเข้า/ปิดงาน: ไม่แสดงในสถานะปิดแล้ว แม้กลับมาเปิดจาก URL เดิม
- ป้ายสถานะ/รายการที่เลือก/stepper: แสดงปิดงานแล้วและครบทั้ง 6 ขั้น; toast สำเร็จไม่ยิงซ้ำเพียงเพราะกลับมาอ่านหน้า
- ปุ่มย้อนกลับ/ไปดู PO เป็นการออกจากมุมมองอ่านอย่างเดียว ไม่เปิดยืนยันการออกเพราะไม่มี draft และไม่เปลี่ยนสถานะปิดงานแล้ว

## O.2.1

- สวิตช์รับประกัน/ช่องวันเริ่ม/รายการเลือกระยะ: ใช้ข้อมูลรับประกันชุดเดียวกับ O.2; เปิดตัวเลือกไม่เปลี่ยนรายการอะไหล่หรือสถานะรถ
- วันหมดอายุ: คำนวณด้วยวันปฏิทินจากวันเริ่ม + 90/180/360/720 วัน แสดงปี พ.ศ. และไม่บันทึกเพียงข้อความวันที่บนหน้าจอ
- ข้อเสนอเพิ่มเติม: ตรวจวันเริ่มและระยะก่อนปิดงานเมื่อเปิดรับประกัน; การคำนวณไม่ได้แปลว่าบันทึกหรือส่งแจ้งเตือนแล้ว

## O.2.2

- สวิตช์รับประกัน: ปิดแล้วแสดงไม่มีการรับประกันและไม่บังคับกรอกช่องวันที่/ระยะ โดยยังตรวจรายการอะไหล่
- ข้อมูลปิดงาน: บันทึกสถานะไม่มีการรับประกันให้ชัด ไม่ใช้วันที่ที่ซ่อนอยู่สร้างแจ้งเตือน
- การคืนค่าหลังเปิดสวิตช์อีกครั้งและข้อความสรุปหลังปิดงานยังต้องตกลง ไม่กำหนดเองจากค่าที่ซ่อนไว้
