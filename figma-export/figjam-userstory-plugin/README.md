# Maintain-D — AC Bridge (Figma + FigJam)

## ใช้ plugin เดียวส่งข้อมูลจาก Figma ไป FigJam

นำเข้า `figma-export/figjam-userstory-plugin/manifest.json` ใน Figma ผ่าน Plugins → Development → Import plugin from manifest ใช้ **Maintain-D — AC Bridge (Figma + FigJam)** ตัวเดียวกันทั้งสองไฟล์ ไม่ต้องเปิด AC annotator ตัวเก่าแยก

1. ใน Figma Design เลือก frame หนึ่งหรือหลาย frame แล้วกด **บันทึกข้อมูลสำหรับ AC** รอข้อความบันทึกสำเร็จ
2. เปิดไฟล์ FigJam และเปิด plugin ตัวเดียวกัน กด **โหลดข้อมูลจาก Figma**
3. เลือก frame ที่บันทึกไว้จากรายการ ตรวจชื่อไฟล์ หน้า และเวลาบันทึก
4. เลือกภาพหรือ frame ปลายทางใน FigJam 1 ชิ้น หรือไม่เลือกเพื่อวางบนพื้นที่ว่าง แล้วกด **แปะ / อัปเดต AC จากข้อมูลที่เลือก**
5. เมื่อแก้ design ให้กลับไปบันทึก frame เดิมจาก Figma แล้วโหลดใหม่ใน FigJam และกดอัปเดต ตัวอ่านสดไม่บันทึกข้ามไฟล์ให้เองจนกดบันทึก

การอัปเดตจับคู่ด้วยไฟล์ต้นทาง + node ID ของ frame + ปลายทาง FigJam ไม่ใช้เพียงชื่อ frame จึงเปลี่ยนชื่อแล้วอัปเดตข้อมูลเดิมได้ เก็บตำแหน่งป้ายเดิมและแทนที่เฉพาะป้ายที่ bridge สร้างให้ข้อมูล/ปลายทางคู่นั้น เลือกป้าย AC เดิมหรือลูกของป้ายเพื่ออัปเดตได้ด้วย เมื่อสร้างฉบับใหม่ไม่สำเร็จจะเก็บป้ายเก่าไว้ ป้ายที่เขียนเองและป้ายรุ่นเก่าที่ยังไม่ได้ผูกกับ bridge ไม่ถูกลบ

รหัสปลายทางที่ระบุชัดว่าเป็นคนละ AC จะถูกปฏิเสธเพื่อกันแปะผิด frame หากไม่มี AC ที่เขียนไว้สำหรับรหัสใหม่ เช่น S19 จะแปะรายการ UI ที่อ่านได้และบอกว่ายังไม่มีข้อกำหนด behavior โดยไม่เดา behavior เพิ่ม

ข้อมูลเก็บใน `clientStorage` ของ plugin บนเครื่อง/แอปที่ใช้งาน ไม่ sync ข้ามคน เครื่อง หรือ desktop/browser ต้องใช้ plugin identity เดียวกันใน Figma และ FigJam การส่งไป FigJam ไม่ต้องใช้ server ส่วนการบันทึกไฟล์ลง workspace ต้องเปิด `node figma-export/serve.js` หากไม่มี file key จะบันทึก source identity ใน plugin data ของเอกสาร Figma เพื่อไม่ให้ข้อมูลคนละไฟล์ชนกัน ลบรายการที่บันทึกได้จาก plugin โดยไม่ลบ design หรือป้ายบน canvas

รายการ UI ที่บันทึกถูกแนบใต้ **UI ล่าสุดจาก Figma** พร้อม metadata แหล่งที่มาและเวลาบันทึก ส่วน AC behavior ที่เขียนไว้ยังคงเป็นข้อกำหนดแยกจาก observation ของ design การบันทึก component ใหม่ไม่ได้ยืนยันสิทธิ์ validation หรือ API โดยอัตโนมัติ หากข้อมูลถูกตัดเพราะเกิน 10,000 layers จะไม่บันทึกทับ snapshot เดิม

ไฟล์หลัก: `plugin-lib/frame-inspector.js` อ่าน component, `plugin-lib/frame-bridge.js` เก็บข้อมูลข้ามโหมด และ code/UI ในโฟลเดอร์นี้ หลังแก้ helper ให้รัน `node figma-export/build-frame-inspector.js` ส่วน build-content.js ยังสร้างชุด AC ตามเดิมโดยรักษาส่วน bridge ไว้

ตรวจด้วย:

```sh
node figma-export/test-frame-inspector.js
node figma-export/test-frame-bridge.js
node figma-export/test-ac-bridge-ui.js
node figma-export/test-figjam-userstory-plugin.js
node figma-export/test-ac-annotator-plugin.js
```

ทดสอบด้วย mock Plugin API ทั้งการบันทึก/โหลดข้ามโหมด การแก้ property การอัปเดตป้ายเดิม การเก็บตำแหน่ง การป้องกันแปะผิดรหัส และการเก็บป้ายเดิมเมื่อ render ไม่สำเร็จ ยังต้องทดลองการเก็บข้อมูลข้ามไฟล์และการจัดวางจริงใน Figma Desktop

## รายละเอียดชุด AC เดิม

แต่ละเฟรมมีเนื้อหาเรียงดังนี้:

1. **Behavior**: ต่อจากชื่อ AC ทันที ย้ายข้อความจาก “พฤติกรรมที่ควรทำ” มาทั้งหมด โดยยังเป็นแนวทางเสนอพัฒนาตามต้นฉบับ
2. **As-is — Sprint 06**: baseline `Refinement 15/10/69 - Final Userflow Overhaul #14/10/2026` พร้อมจอที่ใช้เทียบและขอบเขตข้อมูลที่พบ
3. **To-be — สิ่งที่เปลี่ยนหรือเพิ่มใหม่**: NEW/CHANGE เฉพาะเฟรม แยกจากรายการสิ่งที่เห็นบนหน้าจอ
4. **สิทธิ์การใช้งาน (Permission)**: ข้อมูลสิทธิ์จาก Sheet ที่ระบุสำหรับเฟรม แยกจากสถานะ/notification และเก็บป้าย Sheet พี่นุทุกข้อ แสดงก่อนรายละเอียดหน้าจอเฉพาะเฟรมที่มีข้อมูล
5. **รายละเอียดหน้าจอ**: หัวข้อหลักต่อจาก To-be เก็บข้อมูลที่มีผลต่อการใช้งานจาก “จากจอเดิม” และรายละเอียดที่ฉบับเต็มระบุแต่ฉบับอ่านง่ายย่อออก โดยตัดคำบรรยายหน้าตาที่เห็นใน design อยู่แล้ว เช่น ช่อง ค่าเริ่มต้น ปุ่ม และข้อความ ข้อมูล Sheet ที่เกี่ยวข้องอยู่ในส่วนนี้พร้อมป้ายรายข้อ
6. **มุม Dev — Component ในเฟรมนี้ (แนวทางพัฒนา)**: ชื่อบนจอและชื่อโค้ดในวงเล็บ เช่น เมนู “…” ท้ายแถวรายการ (RowMenu) พร้อม event → ผลลัพธ์ → ปลายทาง → การคง/ทิ้ง draft
7. **Error Handling / Edge Cases**: กรณีผิดพลาดและข้อยกเว้นที่เกี่ยวกับ action/state ของเฟรม อยู่ต่อจากมุม Dev ไม่ใช้ checklist กลางซ้ำทุกจอ
8. **ประเด็นที่ต้องเคาะ**: รวมคำถามจากหัวข้อเดิม “ต้องตกลงก่อนทำ” กับประเด็นของ AC ฉบับเต็ม ตัดข้อซ้ำโดยเก็บข้อความที่ครบกว่า ไม่มีหัวข้อ “ต้องตกลงก่อนทำ” แยกอีก

ทุกส่วนยังอยู่ใน native text ของ shape เดียว การเปลี่ยนลำดับไม่ตัดเนื้อหาหรือป้าย Sheet และไม่มีหัวข้อ “จากจอเดิม” หรือ “พฤติกรรมที่ควรทำ” แยกค้างอยู่

## เอกสารต้นทาง

- `Overhaul-AC-ฉบับอ่านง่าย-ทุกเฟรม.md`: เนื้อหาอ่านง่ายและพฤติกรรม มี 70 รหัส
- `Overhaul-AC-รายเฟรม.md`: รายละเอียดบนจอ ข้อมูล Sheet คำถามเพิ่มเติม และเฟรม D.2.1/D.2.2 ที่ฉบับอ่านง่ายไม่ได้แยกไว้
- `Overhaul-Dev-แนวทางประกอบ.md`: Dev notes ที่เขียนแยกครบ 72 รหัส พร้อมหลักฐานจาก component/หน้าที่ใช้งานจริงในโปรเจกต์
- `Overhaul-Error-Handling-Edge-Cases-รายเฟรม.md`: กรณีผิดพลาด/ข้อยกเว้นเฉพาะแต่ละเฟรม 2–3 ข้อ เป็นแนวทางเสนอพัฒนา ไม่ถือว่า Sheet ยืนยันหรือ prototype ทำแล้ว
- `Overhaul-Sprint06-Delta-รายเฟรม.md`: As-is และ NEW/CHANGE เฉพาะแต่ละเฟรม อย่างน้อยสองข้อ ไม่ใช้ข้อความกลางแทนเฟรมที่ขาด

ข้อมูล Sheet รวมกับเนื้อหารายละเอียดหน้าจอ และมีป้าย `[Sheet พี่นุ — …]` ต่อข้อ ไม่ทำหัวข้อ Sheet แยกท้ายจอ และไม่ถือว่าทุกข้อความจาก Sheet เป็นฟีเจอร์ใหม่ ข้อเสนอและเรื่องรอยืนยันยังคงสถานะตามเอกสาร

NEW หมายถึงเพิ่ม state หรือเพิ่มรายละเอียด behavior จาก baseline ไม่จำเป็นต้องพัฒนา feature ใหม่ทั้งหมด ส่วนที่มีโค้ดรองรับหรือ prototype ต่างจาก AC ระบุในมุม Dev การจับคู่ baseline ใช้ชื่อ/state ร่วมกับรหัส เพราะ H/N/I เปลี่ยนรหัส และ E/L มีรหัสซ้ำ

## การแสดงผลและการใช้งาน

หนึ่งเฟรมใช้ shape ชนิด SQUARE โดยใส่เรื่องราวลง `shape.text.characters` โดยตรง หัวข้อหลักและหัวข้อย่อยเป็นตัวหนาใน shape เดียว ไม่มี TEXT แยกวางทับ ใช้ TextNode ชั่วคราววัดความสูงแล้วลบทิ้ง ตารางที่มีในเอกสารยังแยกเป็น TABLE และมีเลขอ้างอิงในข้อความ ปุ่มล้างลบ shape และตารางของปลั๊กอินร่วมกัน

หลังแก้เอกสาร รันจาก root:

```sh
node figma-export/figjam-userstory-plugin/build-content.js
node figma-export/test-figjam-userstory-plugin.js
```

build อัปเดต code.js และ `Overhaul-Sprint06-As-is-To-be.md` สำหรับอ่านทบทวน โดยไฟล์ทบทวนใช้ลำดับหัวข้อเดียวกับปลั๊กอิน ชุดทดสอบตรวจข้อมูล AC ฉบับอ่านง่ายทุกข้อ ลำดับ Behavior → As-is → To-be → รายละเอียดหน้าจอ ครบ 72 เฟรม รายละเอียด A.2 ที่เคยตกหล่น ชื่อ component/behavior และ native shape text

ใน FigJam เปิด development plugin จาก manifest.json ปิดและเปิดปลั๊กอินใหม่หลังอัปเดต ล้างป้ายเก่าก่อนแปะใหม่

อ้างอิง API: [ShapeWithTextNode](https://developers.figma.com/docs/plugins/api/ShapeWithTextNode/) และ [TextSublayer](https://developers.figma.com/docs/plugins/api/TextSublayer/) — text sublayer ไม่รองรับการ resize/position หรือแก้ textAutoResize โดยตรง

USER_STORIES และตัวช่วยรุ่นเก่ายังคงไว้สำหรับ compatibility tests การแปะจริงใช้ FRAME_STORIES เท่านั้น

## รายการและการตัดข้อความซ้ำ

ข้อความใน shape ใช้ bullet แทนเลขลำดับเพื่อไม่สื่อว่าต้องทำตามขั้น/เริ่มนับ 1 ซ้ำในกลุ่มต่อเนื่อง รวมรายการหน้าจอที่อยู่ติดกัน และเก็บรายการซ้ำเพียงครั้งเดียวพร้อมป้าย Sheet ถ้าข้อความมีเพียงการยืนยัน CF ของฟิลด์ที่อธิบายแล้ว จะย้ายป้าย Sheet ไปท้ายรายละเอียดฟิลด์แทน หัวข้อคำถามที่มีแต่ข้อความแจ้งว่าเอกสารยังไม่ได้ระบุจะไม่แสดง แต่คำถามจริงและเนื้อหา AC ยังคงอยู่

## ข้อความเปลี่ยนแปลงที่อ่านง่าย

`format-content.js` แสดงการแก้ชื่อเป็นชื่อเดิม -> ชื่อใหม่คนละบรรทัด พร้อมป้าย Sheet ต่อข้อ เช่น ยังไม่มี PO -> รอเลข PO และดำเนินการ -> รอดำเนินการ ส่วนชื่อที่ไม่เปลี่ยนระบุว่าใช้ชื่อเดิม ไม่เขียนรายการใหม่หลายค่าปนกับวงเล็บรายการเดิมที่จับคู่ไม่ได้ กรณีข้อความค้นหา ตัวกรองรถ และ toast ที่มีคู่เดิม/ใหม่ชัดเจนใช้รูปแบบเดียวกัน Pagination ที่มีตัวเลือกตัวเลขจะแสดงเป็น “จำนวนรายการต่อหน้า: … รายการ” โดยไม่เพิ่มตัวเลือกที่ต้นทางไม่ได้ระบุ

## การแยกสิทธิ์และรวมคำถาม

กรณีข้อความ Sheet เดียวมี `Status … · Permission … · ไม่มี notification` จะแยกเฉพาะ Permission ไปอยู่หัวข้อสิทธิ์ ไม่ย้ายสถานะหรือ notification ไปปะปน การแยกเก็บป้าย Sheet ในทุกข้อความที่ได้ ไม่มีการเดาสิทธิ์เพิ่มสำหรับเฟรมที่เอกสารไม่ได้ระบุ

หัวข้อคำถามใช้ “ประเด็นที่ต้องเคาะ” เพียงหัวข้อเดียว คำถามสรุปที่เป็นส่วนหนึ่งของข้อความฉบับเต็มจะเหลือฉบับที่ครบกว่า ส่วนคำถามคนละเรื่องยังอยู่ครบ

## รายละเอียดหน้าจอเน้น action และกติกา

`simplify-screen.js` ทำให้รายละเอียดไม่แข่งกับ design: A.1 ใช้ชุดคอลัมน์ที่ยืนยันจาก Sheet ชุดเดียว เขียนชื่อคอลัมน์เป็น bullet และคงคำอธิบายเฉพาะกติกานับรถ/ความคืบหน้า ไม่แสดงทั้ง “ตารางมี 8 คอลัมน์” กับ “คอลัมน์ CF” ซ้ำกัน

ตัดคำบรรยายประเภทงบสองบรรทัด สี/ตัวอย่างค่าที่ไม่เพิ่ม behavior และรายการ “ตัดออก” ที่ทำใน design แล้ว รวมเรื่องชื่อสถานะให้มีจุดเดียว โดยคง behavior เลือกหลายสถานะไว้ใน A.2 กติกาการเรียง การคำนวณ การเลือก การยืนยัน และสิทธิ์ยังอยู่พร้อมป้าย Sheet เดิม เอกสารต้นฉบับไม่ถูกแก้หรือลบเพื่อให้ตรวจอ้างอิงย้อนหลังได้

## Error Handling / Edge Cases

มีหัวข้อชื่อนี้ตรงกันครบ 72 รหัส อยู่หลัง Dev และก่อนประเด็นที่ต้องเคาะ ภายใน native text ของ shape เดิม แต่ละเฟรมเลือกกรณีจริงของ action เช่น คำค้นเก่าทับคำใหม่ ขาดการเชื่อมต่อหลังบันทึกจนไม่รู้ผล คนอื่นตอบรับนัดระหว่างแก้ ภาพลายเซ็นยังว่าง หรือกลับมาเปิดงานที่ปิดแล้ว ไม่เพิ่ม API route/ชนิด error หรือข้อความ toast ที่ไม่มีข้อสรุปเอง

กรณีเชื่อมต่อ server เป็นข้อเสนอสำหรับระบบจริง หาก prototype ใช้ข้อมูลจำลองไม่ได้แปลว่าทำกรณีเหล่านี้แล้ว รายการที่อ้าง Sheet โดยตรงคงป้าย Sheet พี่นุ ส่วนวิธีที่ยังต้องตกลงให้พิจารณาคู่ประเด็นที่ต้องเคาะ ข้อผิดพลาดเดี่ยวที่อยู่ใน Dev ถูกย้ายมารวมในหัวข้อนี้แทนการแปะซ้ำ

build จะหยุดเมื่อขาดรหัสซ้ำ/ข้อมูลไม่ครบ ชุดทดสอบตรวจครบทุกเฟรม ตำแหน่งหัวข้อ case เฉพาะ state และการแสดงหัวข้อเป็นตัวหนาภายใน shape

การตัดชื่อแผนยาวเกินคอลัมน์ด้วย “…” เป็น overflow behavior ที่ต้องเก็บในรายละเอียดหน้าจอ ไม่ใช่คำบรรยายรูปแบบที่ตัดออกได้ และมี regression test ตรวจว่าข้อนี้ยังถูกแปะใน native shape text

## เกณฑ์การเก็บ Behavior สำหรับ QA

เก็บข้อกำหนดที่ QA สังเกตผลและตัดสินผ่าน/ไม่ผ่านได้ตามเนื้อหาของแต่ละเฟรม รวมถึงการตัดชื่อยาวเป็น “…”, validation, เงื่อนไขเปิด/ปิดหรือซ่อนปุ่ม, สิทธิ์, การคำนวณและค่าเมื่อไม่มีข้อมูล, ผลของการยกเลิก/ปิดกล่อง, การคงหรือล้างข้อมูล และ error/loading ที่เกี่ยวข้อง ไม่จำกัดเฉพาะการคลิก ไม่เพิ่ม tooltip หรือพฤติกรรมใหม่โดยไม่มีแหล่งข้อมูล และยังแยกข้อเสนอ/ประเด็นที่ต้องเคาะออกจากข้อสรุป เก็บป้าย Sheet พี่นุไว้กับข้อมูลที่มาจาก Sheet ตัดได้เฉพาะคำบรรยายภาพที่ไม่เพิ่มกติกาการใช้งานหรือข้อความที่ซ้ำโดยกติกายังอยู่ครบ

## UI Components & Behavior

รวมรายละเอียดหน้าจอและมุม Dev เป็นหัวข้อเดียวครบ 72 เฟรม จัด bullet ตาม component และแทรก `Dev Note (แนวทางพัฒนา)` ภายในกลุ่มเดียวกัน ตารางแยก `Columns`, `Row Actions`, `Sorting`, `Pagination`; A.2 รวม `Fields`, `Actions`, `Behavior` ใต้ Side panel ไม่เพิ่มกลุ่มว่าง และข้อความที่ระบุว่าไม่มี component ใช้ `Visibility` เพื่อไม่ทำให้เข้าใจว่ามี component นั้นบนจอ

ชื่อ `Table (DataTable)`, `Side panel (FilterPanel)`, `Modal` อ้างอิงชื่อ Figma ที่บันทึกในหัวไฟล์ `overhaul-next/src/components/ui/{DataTable,FilterPanel,Modal}.tsx` ส่วนชื่ออื่นใช้ชื่อโค้ดที่มีจริงหรือคำทั่วไป ไม่อ้างว่าทุกชื่อเป็นชื่อ Design System ที่ยืนยันจาก Figma สด ข้อความต้นทาง ป้าย Sheet และสถานะข้อเสนอคงเดิม ตารางประกอบยังแยกได้ การจัดกลุ่มทำใน `group-components.js` หลังรวมและลดข้อความซ้ำแล้ว

## รูปแบบล่าสุด: Behavior ชุดเดียว

รวม Behavior เดิม รายละเอียดหน้าจอ Action และมุม Dev เป็น `Behavior` ชุดเดียวหลังชื่อ AC ทุกเฟรม แยกย่อยตาม component; ไม่มีหัวข้อ `Dev Note` หรือ `Actions` แยกซ้ำ ส่วน `Row Actions` ยังคงใช้เป็นชื่อส่วนเมนูท้ายแถวตามปกติ เนื้อหาทาง Dev อยู่ในพฤติกรรมที่เกี่ยวข้อง รวมข้อความซ้ำ/ข้อความที่อยู่ครบในข้อที่ละเอียดกว่าโดยรักษาแหล่ง Sheet และข้อสงวนที่ต่างกันไว้ ไม่รวมข้อความที่แค่คล้ายกันจนทำเงื่อนไขหาย A.2 เรียบเรียงการเปิด/ตกลง/ยกเลิก/ล้าง/ปิดพื้นหลังใหม่เป็นกติกาครบวงจร ส่วน As-is / To-be ยังคงแยกสำหรับเทียบ baseline

ใช้ “ค่าที่เลือกไว้” แทน “ค่าร่าง” และ “ข้อมูลที่ยังไม่บันทึก” แทน draft ในข้อความที่แสดง เอกสารต้นทางไม่ได้ถูกแก้ตามการจัดคำนี้

## รูปแบบหัวข้อปัจจุบัน

ใช้ `UI Component & Behavior` เป็นหัวข้อรวมรายละเอียด component และพฤติกรรมทุกเฟรม ส่วน `As-is — Sprint 06` เหลือเฉพาะข้อความสรุปสภาพเดิมรายเฟรม ใช้คำว่า `จากเดิม` แทน `baseline` โดยไม่แสดงชื่อบอร์ดหรือรายชื่อจอที่ใช้เทียบ

## ลำดับเนื้อหาล่าสุด

ภาพรวมหน้านี้ (What / Who / Do) → As-is — Sprint 06 → To-be → UI Component & Behavior → สิทธิ์การใช้งาน → Error Handling / Edge Cases → ประเด็นที่ต้องเคาะ โดยไม่มีหัวข้อ Page Behavior ซ้ำ

## แนวทางภาษา

ข้อความทุกเฟรมใช้คำศัพท์ UI ให้สม่ำเสมอ: focus, blur, cursor, checkbox, icon, Pagination และ AutoComplete โดย `plainLanguage()` ปรับคำในผลลัพธ์ก่อนสร้างปลั๊กอินและเอกสารทบทวน เขียน behavior ให้บอกว่าผู้ใช้กดหรือเปลี่ยนอะไร ระบบแสดงอะไร และเมื่อยกเลิกจะกลับหน้าไหน/เก็บข้อมูลใด แยกแต่ละปุ่มพร้อมระบุปลายทาง ไม่ใช้ “ตามลำดับ” เพื่อจับคู่ปุ่มกับหน้า และไม่เพิ่ม behavior ที่ยังไม่มีข้อสรุป

ใช้ `form` แทน “ฟอร์ม” ทุกเฟรม และระบุชนิด/จำนวนไฟล์ในช่องนั้นโดยตรง ไม่เขียนเพียง “ตาม AC” หากขนาดไฟล์หรือการบังคับแนบยังไม่ตกลง ให้บอกว่ารอข้อสรุปโดยไม่เดาเพิ่ม

## อ่าน component จาก selection

เพิ่มแผงอ่าน Component ล่าสุดจาก frame ที่เลือก พร้อมคัดลอกข้อมูลและแนบรายการ UI สดกับ AC ดูวิธีใช้และข้อจำกัดที่ `../ac-annotator-plugin/README.md` หากเลือกภาพใน FigJam จะอ่าน component ที่อยู่ในภาพไม่ได้ ต้องเปิด AC annotator ในไฟล์ Figma Design แล้วเลือก frame ต้นฉบับ ส่วนนี้เป็น observation ของ design ไม่ใช่การยืนยัน behavior ใหม่

## ไฟล์ข้อมูลล่าสุดสำหรับแปลง AC

เปิด `node figma-export/serve.js` ก่อนกด **บันทึกข้อมูลสำหรับ AC** ปลั๊กอินจะส่งรายการ frame ที่เก็บไว้ทั้งหมดไปเขียนทับ `figma-export/out/ac-bridge/latest.json` ทุกครั้ง ไม่สร้างไฟล์แยกตามเวลา หรือชื่อ frame; frame เดิมอัปเดตตาม source + node ID ส่วน frame อื่นที่เก็บไว้ยังอยู่ ใช้ไฟล์นี้เป็นต้นทางแปลง AC และแก้เอกสาร AC ฉบับอ่านง่ายไฟล์เดิม ไม่สร้างฉบับใหม่ หาก server ไม่ทำงานจะแจ้งว่าบันทึกลง workspace ไม่สำเร็จ โดยข้อมูลใน plugin ยังอยู่

## Sprint 09 — เลือกเฟรมแล้ว map AC

ใช้ manifest เดิมของ **Maintain-D — AC Bridge (Figma + FigJam)** และปิด/เปิด plugin ใหม่หลังอัปเดตไฟล์

1. เปิด plugin ใน FigJam แล้วเลือกภาพหรือ frame ปลายทาง **1 ชิ้น**
2. ในหัวข้อ **Sprint 09 — map AC กับเฟรมที่เลือก** เลือก Story แล้วติ๊กเฉพาะ AC ที่สัมพันธ์กับจอนี้
3. กด **แปะ / อัปเดต AC Sprint 09 ให้เฟรมที่เลือก** ป้ายวางข้างปลายทางและบันทึก mapping กับ node ID โดยไม่ต้องเปลี่ยนชื่อเฟรม
4. กดซ้ำกับปลายทางเดิมเพื่อแทนที่ป้าย Sprint 09 เดิมหลังสร้างป้ายใหม่สำเร็จ ป้าย AC รุ่นเดิมและ design ไม่ถูกลบ

มี 9 Story / 62 AC จาก `../../docs/sprint09-acceptance-criteria.md` คงสถานะ R (ข้อสรุป), D (รอยืนยัน Sprint scope), P (ข้อเสนอรอรับรอง) และบริบท/คำถามของ Story ไม่จับคู่ A.1 อัตโนมัติเพราะรหัสซ้ำข้ามชุดจอ ไม่ติ๊ก AC ให้ล่วงหน้า หากอยู่ Figma Design ให้บันทึกข้อมูล/นำภาพไป FigJam แล้วเลือกปลายทางใน FigJam เพื่อ map ชุดนี้

เมื่อแก้ต้นทาง ให้รัน `node figma-export/figjam-userstory-plugin/build-sprint09.js` เพื่อฝังข้อมูลใหม่ใน `code.js` (ไม่แก้ generated block ด้วยมือ) การ map ชุดนี้เลือกโดยผู้ใช้และไม่ได้เปลี่ยน AC ของทุกเฟรมบน canvas อัตโนมัติ


### AC ตามเฟรมที่เลือกอัตโนมัติ

เลือก frame/ภาพ 1 ชิ้นใน FigJam แล้วกด **แปะ AC ตามเฟรมที่เลือก** ได้เลย ไม่ต้องเลือก Story หรือติ๊ก AC รายข้อ แผงแสดง ID ที่จับคู่ก่อนกด ใช้ชื่อและสถานะเฉพาะจอจาก `sprint09-frame-map.json` (เช่น รถที่ Overhaul — ไม่พบข้อมูล, SSO กรอกรหัสผิด, P.2 ปิดงานแล้ว) รหัสที่ซ้ำอย่าง A.1 เพียงอย่างเดียวไม่ถูกจับคู่ หากไม่พบชื่อที่รองรับจะแจ้งว่าไม่มี mapping โดยไม่แปะ AC ผิดชุด ตัวเลือก manual อยู่ในหัวข้อพับไว้ให้แก้ได้ กดซ้ำอัปเดตป้ายของปลายทางเดิม

หลังแก้ mapping รัน `node figma-export/figjam-userstory-plugin/build-sprint09.js` แล้วปิด/เปิด plugin ใหม่


### เลือกหลายเฟรมพร้อมกัน

ปุ่ม **แปะ AC ตามเฟรมที่เลือก** รองรับเลือกหลาย frame/ภาพใน FigJam ระบบจับคู่และแปะ AC แยกรายเฟรม ไม่ใช้ AC ชุดเดียวกันกับทุกจอ พรีวิวแสดงผลจับคู่ทุกชิ้น เฟรมที่ไม่มี mapping ถูกข้ามโดยไม่หยุดเฟรมอื่น หากเฟรมใดแปะไม่สำเร็จจะรายงานชื่อและสาเหตุ พร้อมยอดสำเร็จ/ทั้งหมด กดซ้ำอัปเดตป้ายแต่ละปลายทาง ไม่เพิ่มป้ายซ้ำ ปุ่มเลือก Story/AC เองยังใช้ครั้งละ 1 ชิ้นเพื่อไม่ส่ง AC ชุดเดียวกันไปหลายจอโดยไม่ตั้งใจ


### เฟรม OH2 ที่มี AC เดิม

ปุ่มแปะตามเฟรมใช้ AC Sprint 09 เมื่อมี mapping ใหม่ หากไม่มีแต่ชื่อขึ้นต้น `OH2 /` และมีรหัสในชุด AC เดิม จะใช้ AC ที่ทบทวนแล้วของเฟรมนั้น เช่น `OH2 / A.1 · หน้ารายการแผน — ค้นหา — รายการแผน` ใช้ AC A.1 เดิม พรีวิวและผลสรุประบุว่าเป็น AC เดิม ไม่ถือว่าเนื้อหาเดิมทั้งหมดได้รับการยืนยันใหม่ใน Sprint 09 ชื่อ A.1 ที่ไม่มี namespace ยังไม่ถูกเดาข้ามชุดจอ


### ปุ่มหลัก: AC ตามเฟรมที่มี

ส่วน **AC ตามเฟรมที่เลือก** รองรับชุด AC Overhaul ที่มีอยู่ครบ 74 รหัส โดยชื่อเฟรมไม่จำเป็นต้องขึ้นต้น OH2 เช่น `A.1`, `B.1`, `O.2.1` ก็ใช้ได้ เลือกหลายเฟรมแล้วกดปุ่มเดียว ระบบใช้ AC รายเฟรมที่เขียนไว้จริง และเลือกข้อสรุป Sprint 09 สำหรับชื่อ/สถานะที่ map เพิ่มไว้ ไม่สร้างข้อกำหนดใหม่จากสิ่งที่เห็นในภาพ ชื่อขึ้นต้น SP09 ไม่ถูกนำรหัสซ้ำไปจับกับ Overhaul อัตโนมัติ หากไม่มี AC จะรายงานให้ทราบ


การเลือกหลายชิ้นข้ามป้าย `SHAPE_WITH_TEXT`, ข้อความ และป้ายที่ plugin สร้างไว้ ไม่นำมานับเป็นเฟรมไม่มี mapping การอัปเดตค้นหาป้ายเดิมด้วยการเดิน children และตรวจ `typeof getPluginData` ก่อนเรียก ไม่ใช้ callback `findAll` ที่ล้มเมื่อเจอ node ไม่รองรับ plugin data ตัวเลข AC เดิมนับเฉพาะที่แปะสำเร็จแล้ว


รุ่น `frame-batch v3` แสดงสถานะไว้ด้านบนแผง พร้อมความคืบหน้าแต่ละเฟรม หลังสร้างเสร็จเลื่อน viewport ไปป้ายแรกให้อ่านได้ ไม่ zoom รวมทุกเฟรมจนตัวหนังสือเล็ก แจ้งจำนวนที่สำเร็จผ่าน Figma notification ด้วย หากหัวปลั๊กอินไม่แสดงรุ่นนี้ แสดงว่ายังไม่ได้โหลดไฟล์ล่าสุด
