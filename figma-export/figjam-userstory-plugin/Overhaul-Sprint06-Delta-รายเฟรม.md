# Overhaul — รายละเอียด As-is / NEW / CHANGE ทุกเฟรม

ข้อกำหนดเปรียบเทียบรายเฟรม: NEW หมายถึงเพิ่ม state หรือเพิ่มรายละเอียด behavior จาก baseline ไม่ใช่อ้างว่าระบบเดิมไม่มี feature ทั้งชุด รายละเอียดที่ยังไม่ตกลงยังคงเป็นข้อเสนอ การรองรับจริงของ prototype อ่านคู่กับมุม Dev

## A.1

**As-is**

- baseline มีหน้ารายการ ค้นหา ตัวกรอง ตารางและเมนูท้ายแถว แต่ไม่ได้แยกผลของคำค้นที่ส่งซ้อน/การโหลดผิดพลาดเป็นข้อกำหนดราย state

**To-be**

- NEW — เพิ่มข้อกำหนดช่องค้นหา (SearchInput): คงคำค้นเมื่อ blur/โหลดผิดพลาด และไม่ให้ผลคำค้นก่อนหน้าทับคำล่าสุด; จังหวะเริ่มค้นยังต้องตกลง
- NEW — เพิ่มข้อกำหนดเมนู “…” ท้ายแถว (RowMenu): คลิกนอกปิดโดยไม่ทำ action; Esc ปิดคืน focus; เลือกแก้ไข/ลบต้องอ้าง ID ของแถวที่กด ไม่ใช่ตำแหน่งแถวหลังเรียงใหม่

## A.2

**As-is**

- baseline มีปีงบ งบประมาณ สถานะ และล้าง/ยกเลิก/ตกลง แต่ยังไม่ระบุ contract การปิดพื้นหลัง/Esc และค่าร่างครบทุกทาง

**To-be**

- CHANGE — ชื่อสถานะ “ยังไม่มี PO” → “รอเลข PO” และ “ดำเนินการ” → “รอดำเนินการ”; “เสร็จสิ้น” คงเดิม [Sheet พี่นุ — 1 รายการแผน]
- NEW — เพิ่มข้อกำหนดการปิดแผง: พื้นหลังทึบ/×/Esc/ยกเลิกปิดแผง ไม่ใช้ค่าร่าง และกลับ A.1 ไม่ใช่สร้างตัวกรองใหม่ทั้งชุด; แผงตัวกรอง (FilterPanel/PlanFilter) ในโค้ดรองรับอยู่แล้ว
- NEW — เพิ่มข้อกำหนดค่าร่าง: ล้างเฉพาะในแผงและยังไม่กรองจนกดตกลง; ปิดโดยไม่ตกลงทิ้งค่าร่าง เปิดใหม่ใช้ค่าที่กรองอยู่จริง

## A.3

**As-is**

- baseline มีจอค้นไม่พบและการล้างคำค้น แต่ไม่ได้แยก no-result จากการโหลด/error และผลต่อ focus เป็น contract ชัดเจน

**To-be**

- NEW — เพิ่มข้อกำหนด state ค้นไม่พบ: ไม่แสดงตารางเก่าหรือ pagination ค้าง แต่ยังคงคำค้น/ตัวกรองไว้ให้แก้; error ต้องไม่ใช้ภาพค้นไม่พบแทน
- NEW — เพิ่มผลปุ่มล้าง: ล้างคำค้นและตัวกรองพร้อมกันแล้วกลับรายการ A.1 ในหน้าเดิมและคืน focus ที่ช่องค้นหา

## A.4

**As-is**

- baseline มีจอยังไม่มีแผนและปุ่มสร้าง ไม่ได้แยกข้อกำหนดการเข้าถึงปุ่มกับการกลับจากฟอร์มเป็นราย state

**To-be**

- NEW — เพิ่มข้อกำหนดปุ่มสร้างกลางจอ: ผู้มีสิทธิ์กดแล้วไป B.1; กลับโดยยังไม่สร้างต้องยังเห็น A.4 ไม่สร้างแผนจากการเปิดฟอร์ม
- NEW — เพิ่มขอบเขต empty state: ไม่แสดงแถบค้นหา/ตัวกรอง/แบ่งหน้าในจอว่าง และไม่ใช้ state นี้แทน A.3 ที่ค้นไม่พบ

## B.1

**As-is**

- baseline มีฟอร์มสร้างว่างและช่องบังคับ แต่ยังไม่แยก contract ออกจากฟอร์มทุกทางกับค่าที่ไม่เคยแก้

**To-be**

- NEW — เพิ่มข้อกำหนดทางออก: ไม่เคยแก้ค่าให้กลับรายการ A ได้ทันที; มี draft เปิด B.4 ก่อนออก โดยต้องครอบคลุม breadcrumb ที่โค้ดปัจจุบันยังเป็นลิงก์ตรง
- NEW — เพิ่มเงื่อนไขเริ่มต้น: ปีงบยังไม่เลือกและปุ่มบันทึกยังไม่พร้อม ห้ามตั้งปี/สร้างแผนแทนผู้ใช้

## B.2

**As-is**

- baseline ตั้งชื่อ state กดบันทึกโดยยังไม่ครบ ส่วน AC ล่าสุดอธิบายการออกจากช่องโดยไม่กรอก

**To-be**

- CHANGE — เปลี่ยนจังหวะ validation จาก state กดบันทึกใน baseline เป็น blur/out of focus ตาม AC ล่าสุด พร้อมปุ่มบันทึก disable; ต้องยืนยัน pattern ก่อนพัฒนา
- NEW — เพิ่มการแก้ error รายช่อง: กรอกถูกให้ล้างเฉพาะ error ช่องนั้น คงค่าช่องอื่น; วงเงิน 0 ยังไม่ผ่าน และไม่สร้าง error เอกสารเองขณะที่ยังไม่ตกลง required

## B.3

**As-is**

- baseline มีฟอร์มกรอกครบ/ไฟล์แนบ แต่ยังไม่แยกข้อกำหนดหลายไฟล์และการส่งซ้ำเป็น contract ราย action

**To-be**

- NEW — เพิ่มข้อกำหนดรายการไฟล์: ลบเฉพาะไฟล์ที่กด ปรับจำนวน/progress ตามจริง และไม่ reset ช่องกรอกที่ครบแล้ว
- NEW — เพิ่ม state บันทึกกำลังส่ง: ปิดการกดซ้ำจากเมาส์/คีย์บอร์ดโดยคงข้อมูลชุดที่กำลังส่งไว้

## B.4

**As-is**

- baseline มีการยืนยันออกจากฟอร์ม แต่รายละเอียดการปิดพื้นหลัง/Esc และการคง draft ยังไม่แยกครบทุกทาง

**To-be**

- NEW — เพิ่มข้อกำหนดปิดกล่อง (ConfirmDialog): ปิด/×/Esc/พื้นหลังกลับ B.1/B.3 พร้อม draft ไม่ใช่ออกจากฟอร์ม
- NEW — เพิ่มผลยืนยันออก: ทิ้งเฉพาะค่าที่ยังไม่บันทึกแล้วไปหน้ารายการ A; ปิดกล่องธรรมดาต้องไม่ทำผลเดียวกับยืนยัน

## B.5

**As-is**

- baseline มีผลบันทึกแผนไม่สำเร็จ แต่ไม่ได้แยก retry กับการคงข้อมูล/ไฟล์เป็น contract รายส่วน

**To-be**

- NEW — เพิ่มข้อกำหนด error: toast ปิดได้โดยฟอร์มยังอยู่และคงค่า/ไฟล์ทุกช่อง ไม่ทำแผนใหม่จากการ retry อัตโนมัติ
- NEW — เพิ่มผลปุ่ม retry: เมื่อพ้น pending กดบันทึกใหม่ได้ และผลล้มเหลวเดิมต้องไม่แสดง success ทับ

## B.6

**As-is**

- baseline มีบันทึกแผนสำเร็จและกลับรายการ แต่ยังไม่ได้ระบุการป้องกันผลสำเร็จซ้ำจากการกลับมาอ่านหน้า

**To-be**

- NEW — เพิ่มข้อกำหนดหลังสำเร็จ: โหลดรายการแผนจากผลที่บันทึกจริงพร้อมสถานะรอเลข PO และความคืบหน้า “-” ไม่คงข้อมูลก่อนสร้าง
- NEW — เพิ่ม contract toast: แสดงครั้งเดียวจากการสร้างสำเร็จ ไม่ยิงอีกเพียงเพราะ refresh/กลับมาที่รายการ

## B.7

**As-is**

- baseline มีรายละเอียดแผนและส่วน PO/เอกสาร แต่ไม่ได้แยกผลของปุ่มและการเปิดข้อมูลข้ามแผนเป็น contract ครบถ้วน

**To-be**

- NEW — เพิ่มข้อกำหนดข้อมูลรายละเอียด: เปลี่ยนแผนแล้วเอกสาร/จำนวน PO/สถานะต้องเป็นของแผนนั้น ไม่คงข้อมูลแผนก่อนหน้า
- NEW — เพิ่มปลายทาง action: แก้ไขไป C.2 พร้อมต้นทางรายละเอียด; ลบเปิด D.2.2 บนหน้าเดิม; สร้าง PO ไป E.2 โดยตรวจสิทธิ์แต่ละปุ่ม

## C.1

**As-is**

- baseline มีเมนูแก้ไขแผนในแถว แต่ไม่ได้แยกการปิดเมนูกับการเลือก action ทุกทาง

**To-be**

- NEW — เพิ่มข้อกำหนดเมนู “…” (RowMenu): คลิกนอก/Esc ปิดแล้วค้าง A.1 และคืน focus; เลือกแก้ไขจึงไป C.2 ของแถวที่กด
- NEW — เพิ่มการรักษาเป้าหมาย: หลัง sort/เปลี่ยนหน้า ห้ามนำ action ไปใช้กับแถวใหม่ที่ตำแหน่งเดิม

## C.2

**As-is**

- baseline ระบุแก้ไขเข้าจากรายการหรือรายละเอียดและยกเลิกกลับทางเดิม แต่ยังไม่แยก callback/ค่าร่าง/ไฟล์ทุกกรณี

**To-be**

- NEW — เพิ่ม contract ยกเลิก: ไม่แก้ให้กลับต้นทางทันที; มี draft เปิด C.3 ก่อน และจำต้นทางเป็นรายการ A.1 หรือรายละเอียด B.7 ให้ชัด
- NEW — เพิ่ม contract prefill: แยกค่าเดิม/ค่าที่แก้/ไฟล์ใหม่ ไม่อัปโหลดไฟล์เดิมซ้ำและไม่ reset draft เมื่อเปิดกล่องยืนยัน

## C.3

**As-is**

- baseline มีกล่องยืนยันออกเมื่อยกเลิกการแก้ไข แต่ไม่ได้ระบุผลพื้นหลัง/Esc อย่างละเอียด

**To-be**

- NEW — เพิ่มข้อกำหนดปิดกล่อง: ปิด/×/Esc/พื้นหลังกลับ C.2 พร้อม draft; ยืนยันจึงทิ้ง draft แล้วกลับรายการหรือรายละเอียดตามทางเข้า
- NEW — เพิ่มขอบเขตการทิ้งข้อมูล: การปิดกล่องไม่ลบไฟล์เดิมหรือแผนที่บันทึกแล้ว

## C.4

**As-is**

- baseline มียืนยันแก้ไข แต่ไม่ได้แยกการยกเลิกยืนยันกับการออกจากฟอร์ม และการปิดระหว่าง pending

**To-be**

- NEW — เพิ่มผลยกเลิกยืนยัน: ยกเลิก/×/Esc/พื้นหลังกลับ C.2 พร้อมค่าที่แก้ ไม่บันทึกและไม่กลับรายการ
- NEW — เพิ่มข้อกำหนดกำลังบันทึก: ยืนยันได้ครั้งเดียว; ต้องตกลงว่าจะค้างกล่องหรือยอมปิดระหว่าง pending เพราะกล่องเดิมยังปิดด้วยพื้นหลัง/Esc ได้

## C.5

**As-is**

- baseline มีผลแก้แผนสำเร็จ แต่ไม่ได้แยกการโหลดค่าหลังแก้และ toast จากการนำทางซ้ำ

**To-be**

- NEW — เพิ่มข้อกำหนดแสดงผล: ชื่อแผน/ปีงบ/วงเงิน/ไฟล์ต้องเป็นค่าที่บันทึกใหม่ ไม่แสดง cache ก่อนแก้
- NEW — เพิ่ม contract กลับต้นทาง: ใช้ปลายทางตามทางเข้าและยืนยันกับ AC ล่าสุด; toast เกิดจากการแก้สำเร็จ ไม่เกิดซ้ำเมื่อเปิดหน้าอ่าน

## D.1.1

**As-is**

- baseline มีทางเข้าลบจากเมนูแถวรายการ แต่ยังไม่ได้แยกการเปิดเมนูออกจากการยืนยันลบเป็น contract ละเอียด

**To-be**

- NEW — เพิ่มข้อกำหนดเมนูลบ: คลิกนอก/Esc ก่อนเลือกลบเพียงปิดเมนูอยู่ A.1 ไม่เปลี่ยนข้อมูล; เลือกลบจึงเปิด D.2.1
- NEW — เพิ่มการจำแผนเป้าหมายด้วย ID ไม่ใช้ index ของตารางที่อาจเปลี่ยนจาก sort

## D.1.2

**As-is**

- baseline snapshot ยังไม่พบเฟรมทางเข้าปุ่มลบในรายละเอียดที่แยกตรงรหัสนี้

**To-be**

- NEW — เพิ่มการอ้างอิงทางเข้าลบจากปุ่มใน B.7 แยกจากเมนูรายการ; กดแล้วเปิด D.2.2 บนรายละเอียดเดิม ยังไม่ลบ
- NEW — เพิ่มผลเมื่อยกเลิกกล่องจากทางเข้านี้: กลับรายละเอียด B.7 ไม่กลับรายการ A.1 โดยไม่สรุปว่าระบบเดิมไม่มีสิทธิ์ลบจากรายละเอียด

## D.2.1

**As-is**

- baseline มีกล่องยืนยันลบแผน แต่ไม่แยกปลายทางปิดกล่องตามทางเข้ารายการอย่างละเอียด

**To-be**

- NEW — เพิ่ม contract ยกเลิก/×/Esc/พื้นหลัง: ปิดกล่องกลับ A.1 คงแถวแผนเดิม; คลิกในกล่องไม่ปิด
- NEW — เพิ่ม contract ยืนยัน: ส่งลบครั้งเดียวตาม Soft Delete และไม่แสดงสำเร็จก่อนผลจริง; เงื่อนไขปิดระหว่างกำลังลบต้องตกลง

## D.2.2

**As-is**

- baseline มีกล่องยืนยันลบรวม แต่ไม่แยก state เปิดจากรายละเอียดเป็นรหัสเฉพาะ

**To-be**

- NEW — แยก contract ของกล่องลบจากรายละเอียด: ยกเลิก/×/Esc/พื้นหลังกลับ B.7 ไม่กลับ A.1
- NEW — ยืนยันลบสำเร็จจึงไปหน้ารายการ A; การแค่ปิดกล่องต้องไม่ทำให้รายละเอียดถูกนำออกหรือลบข้อมูล

## D.3

**As-is**

- baseline มีผลลบแผนสำเร็จ แต่ไม่ได้แยกกรณีลบแถวสุดท้ายของหน้ากับรายการทั้งหมดว่าง

**To-be**

- NEW — เพิ่มข้อกำหนดตารางหลังลบ: โหลดจำนวนใหม่และไม่คงแถวแผนที่ลบ; หากไม่เหลือแผนให้แสดง A.4
- NEW — เพิ่มกรณี pagination หลุดหน้า: หากหน้าปัจจุบันว่างแต่ยังมีข้อมูลหน้าอื่น ต้องตกลงหน้าที่จะกลับและไม่แสดงว่ายังไม่มีแผนทั้งระบบ

## E.1

**As-is**

- baseline มีแผนยังไม่มี PO เอกสาร และทางเข้าสร้าง PO แต่ไม่ได้แยก behavior แต่ละส่วนเมื่อเป็นข้อมูลว่าง

**To-be**

- NEW — เพิ่มข้อกำหนดปุ่ม “+ PO”: เปิด E.2 ของแผนปัจจุบัน ไม่สร้าง PO จากการเปิดฟอร์มและไม่ทำงานร่วมกับปุ่มเบิกอะไหล่
- NEW — เพิ่มข้อกำหนดเอกสารสองคอลัมน์: ดาวน์โหลดไฟล์ตามประเภท/แผนที่กด ไม่ใช้ไฟล์จากแผนก่อนหน้า

## E.2

**As-is**

- baseline มีฟอร์มเพิ่ม PO พร้อมอู่ รถและเอกสาร แต่ไม่ได้แยก contract การออกทุกทาง/การเลือกเป็น ID ครบถ้วน

**To-be**

- NEW — เพิ่มข้อกำหนดเลือกอู่/รถ: พิมพ์ชื่ออย่างเดียวไม่ถือว่าเลือก ต้องมีรายการจริงและค่าที่ส่งตรงกับสิ่งที่แสดง
- NEW — เพิ่มการออกจากฟอร์ม: ปุ่มย้อนกลับใช้ leave guard กลับ E.1 ส่วน breadcrumb ปัจจุบันยังข้าม guard ต้องแก้ให้ตรงข้อกำหนดก่อนอ้างว่าป้องกันข้อมูลหายครบ
